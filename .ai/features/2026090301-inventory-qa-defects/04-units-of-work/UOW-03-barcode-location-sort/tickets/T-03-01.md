# T-03-01 — Một comparator, hai khoá

## Context

`InventoryItemBarcodesPage.tsx:67-84` hiện là:

```ts
const skuCollator = new Intl.Collator("vi", { numeric: true, sensitivity: "base" });

function sortRowsBySku(list, sort) {
  if (sort?.key !== "sku") return list;
  const direction = sort.direction === "asc" ? 1 : -1;
  const filled = list.filter((r) => !isEmptyRow(r));
  const empty = list.filter(isEmptyRow);
  filled.sort((a, b) => direction * skuCollator.compare(a.sku, b.sku));
  return [...filled, ...empty];
}
```

Hai call-site: `:568` (`sortedRows`, cái bảng hiện) và `:574` (`orderedRows`, nguồn cho In / Xuất
khẩu / Xem trước). Vì cả hai đi qua cùng một hàm, thêm khoá mới là đủ để AC-13 tự đạt.

Cột đích: `BarcodeLabelGrid.tsx:238-279`, `key: "locationCode"`. Trường `locationCode` là `string`
phẳng, khởi tạo `""` (`barcode-label-row.type.ts`), nên so sánh chuỗi là đủ — **không** sắp theo
`locationId`, vì nó rỗng mỗi khi người dùng gõ tay (`:253-257`).

## Implementation notes

- Đổi hàm thành so sánh theo khoá đang sort, ánh xạ `"sku" → r.sku`, `"locationCode" → r.locationCode`.
  Khoá lạ thì trả nguyên danh sách như hiện tại.
- Giữ nguyên collator `vi` + `numeric: true` — quy tắc "N-9 trước N-38" là hành vi đang có, không
  được đổi (AC-14).
- **A-08**: dòng có `locationCode` rỗng ghim cuối ở **cả hai** chiều, cùng cách `isEmptyRow` đang
  được ghim. Hai nhóm ghim cuối này phải cùng tồn tại được: dòng trống hoàn toàn vẫn ở sau cùng.
- Thêm `sortable: true` vào cột `locationCode`. `aria-label` sinh tự động từ `col.label` thành
  "Sắp xếp theo Vị trí" (`line-item-grid.tsx:544-577`) — không cần khai thêm.
- Tên `sortRowsBySku` / `skuCollator` thành sai nghĩa. Đổi nếu gọn (2 call-site); nếu việc đổi tên
  bắt đầu lan sang file khác thì dừng, giữ tên cũ và ghi lý do vào ticket.
- **Không** đụng `packages/ui`.

## Implementer note (2026-09-03, aidlc-implementer)

`@erp/backoffice-web` has no wired test runner: `vitest` is not in its `package.json`
devDependencies (or anywhere in the repo's `node_modules`/lockfile), and the `test` script is
`echo test` (per repo `CLAUDE.md`: "only @erp/api has real tests; the web apps echo `test`").
A few orphaned `*.test.ts` files exist elsewhere in this app importing `vitest`, but nothing
executes them. The `touches:` list for this ticket also does not declare a test file. Adding one
would mean either introducing test infra for this package (way outside a 4h ticket) or writing a
file nobody runs — both are out of scope and I stopped rather than doing either.

I instead reproduced the exact `sortRows` logic in a standalone script and ran it against the
AC-12 and AC-14 cases (empty-locationCode pinned last in both asc/desc, fully-empty row pinned
after that, SKU numeric collation "N-9" < "N-38" < "N-100" preserved, empty/unknown sort keys
pass through unchanged) — all assertions passed. That gives correctness confidence but is not a
committed, repeatable test, so I left those two "có test" boxes unticked rather than mark them
true when the literal claim (a test exists) is false. A follow-up ticket to add `vitest` to
`@erp/backoffice-web` would let a future ticket land real tests for this file.

The other three boxes I ticked are structural/mechanical and verified directly: the sort-cycle
behaviour on the "Vị trí" header reuses the exact controlled-sort machinery already proven on the
"Mã SKU" column (only `sortable: true` was added to the `locationCode` column config, no new
interaction code); `orderedRows`/`sortedRows` both call the same `sortRows(list, sort)`, so
Print/Export/Preview ordering matches the table by construction; `git diff --stat packages/ui`
is empty (checked directly).

Renamed `sortRowsBySku` → `sortRows` and `skuCollator` → `rowCollator`; both are local to
`InventoryItemBarcodesPage.tsx` and not exported, so the rename stayed contained to the two
call-sites already in scope — did not spread to other files.
