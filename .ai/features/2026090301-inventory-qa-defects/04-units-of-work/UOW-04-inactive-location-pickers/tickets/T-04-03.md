`page` / `pageSize` / `itemId` (cộng `branchId`) — không `isTracked`, không lọc vị trí. `toLocationOptions`

## Implementation record

- `fetchItemStockBalances` (`item-stock-locations.ts:48-68`) now sends both
  `isTracked=true` and `locationIsActive=true` alongside the existing `page`/`pageSize`/`itemId`
  params. Verified against `apps/api/src/modules/inventory/ledger/stock-ledger.controller.ts`
  `BalanceQueryDto` (`:105`, `:114`, `:130`) that these are the exact param names/casing accepted
  by `GET /inventory/stock/balances`.
- The filter is applied server-side by `getBalances`
  (`apps/api/src/modules/inventory/ledger/stock-ledger.service.ts:496-503`): `isTracked` maps to
  `sb.is_tracked = :isTracked`, `locationIsActive` maps to `loc.is_active = :locationIsActive`.
  Both filter on the boolean flag columns, never on `quantity` — satisfies A-13 (a tracked shelf
  with `quantity = 0` still passes `sb.is_tracked = true` and is returned).
- Cache key in `InventoryItemBarcodesPage.tsx` (`loadItemBalances`, around :203-216) changed from
  `["item-stock-balances", itemId, branchId]` to
  `["item-stock-balances", itemId, branchId, "isTracked=true", "locationIsActive=true"]` in the
  same change as the new query params, so no other screen can read stale/differently-filtered
  cache under the same key (there are no other call sites of this query key in the codebase —
  confirmed by grep).

### "Kho" (storage) picker finding — no fix needed, no new ticket

Checked `toStorageOptions` (`item-stock-locations.ts:74-88`) and its caller `searchItemStorages`
(`InventoryItemBarcodesPage.tsx:191-206`). Both read from the same `fetchItemStockBalances` result,
so they inherit the same `isTracked`/`locationIsActive` filtering by construction — no separate fix
was needed there.

Additionally, and independent of this ticket's change: `getBalances`
(`stock-ledger.service.ts:507`) already applies `qb.andWhere('storage.is_active = true')`
**unconditionally**, with no opt-in flag. So a deactivated storage (`storages.is_active = false`)
could never have appeared in the "Kho" dropdown even before this ticket — that guard predates this
work and is out of scope for AC-17 (which is about `locations.is_active`, not `storages.is_active`).
No gap found; no new ticket recommended.
