# T-01-01 — Helper đọc kết quả `… RETURNING`

## Context

TypeORM 0.3.28 (`driver/postgres/PostgresQueryRunner.js:198-203`) trả về hai hình dạng
khác nhau từ cùng một `manager.query()`:

```
SELECT …                        → [{…}, {…}]        (mảng dòng)
INSERT … RETURNING              → [{…}]             (mảng dòng)
UPDATE … RETURNING, khớp 0 dòng → [[], 0]           (mảng 2 phần tử!)
UPDATE … RETURNING, khớp 1 dòng → [[{id}], 1]       (mảng 2 phần tử!)
```

Đây là nguyên nhân gốc của QA #8: `adjustRequestedQty` đọc `.length` của kết quả UPDATE,
giá trị đó **luôn** là 2, nên nhánh xử lý "không khớp dòng nào" không bao giờ chạy được.

Repo đã biết bẫy này ở đúng **một** chỗ — `sync-admin-permissions.seed.ts:86-93` có hàm
`returnedRows` cùng một comment mô tả chính xác hành vi — nhưng kiến thức đó nằm chết
trong một file seed, nên chỗ thứ hai vẫn đâm vào.

## Implementation notes

- Tạo `apps/api/src/common/db/returning.util.ts` với hai hàm thuần, không phụ thuộc Nest:
  - `returnedRows<T>(result: unknown): T[]` — mảng dòng thật, cho cả bốn hình dạng.
  - `affectedRowCount(result: unknown): number` — số dòng `UPDATE`/`DELETE` chạm tới;
    với hình dạng mảng dòng (SELECT/INSERT) thì trả `result.length`.
- Nhận diện hình dạng bằng `Array.isArray(result) && Array.isArray(result[0])`, đúng như
  bản đã có trong seed — **không** đoán bằng `result.length === 2`, vì một `SELECT` trả
  đúng 2 dòng cũng có length 2.
- Đổi `sync-admin-permissions.seed.ts` sang import helper mới, xoá bản cục bộ. Giữ nguyên
  hành vi — chỉ dời chỗ ở.
- Không đụng `stock-ledger.service.ts:937` (`INSERT … ON CONFLICT … RETURNING`): lệnh
  INSERT rơi vào nhánh `default:` của TypeORM nên vốn đã đúng (A-11).
