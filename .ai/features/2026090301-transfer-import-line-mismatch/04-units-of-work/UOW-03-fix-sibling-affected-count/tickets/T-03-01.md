# T-03-01 — Chỗ thứ hai dính cùng bẫy

## Context

Cùng lớp lỗi với QA #8, tìm ra trong lúc rà. `StockLedgerService.setBalanceTracking`
(`stock-ledger.service.ts:703-714`):

```ts
const rows = await this.balanceRepo.manager.query<Array<{ id: string }>>(
  `UPDATE stock_balances sb SET is_tracked = $4 … RETURNING sb.id`, […]);
return { updated: rows.length };     // luôn 2
```

Nhẹ hơn bug điều chuyển — nó chỉ báo sai số, không làm hỏng dữ liệu — nhưng cùng một
nguyên nhân, và để nguyên thì lần rà sau lại phải điều tra lại từ đầu.

Lưu ý phân biệt: `stock-ledger.service.ts:937` dùng `INSERT … ON CONFLICT DO UPDATE …
RETURNING` và **đang đúng** — pg đặt `raw.command = 'INSERT'`, rơi vào nhánh `default:`
của TypeORM nên trả thẳng mảng dòng, và `for (const row of returned)` chạy đúng. Không
đụng vào (A-11).

## Implementation notes

- Đổi `rows.length` → `affectedRowCount(rows)` (helper T-01-01).
- Giữ `return { updated: n }`, không đổi hình dạng phản hồi.
- Rà toàn `apps/api/src` tìm mọi cặp `manager.query(…RETURNING…)` đi kèm `.length` hoặc
  vòng lặp trên kết quả; phân loại từng chỗ theo lệnh SQL (UPDATE/DELETE → cần helper;
  SELECT/INSERT → vốn đúng). Chép bảng phân loại vào mô tả PR, kể cả khi không tìm thêm
  được chỗ nào — lần rà sau đọc lại được.
- Đã biết trước, không cần rà lại: `migrations/1779100000000`, `migrations/1789000000000`,
  `seeds/sync-admin-permissions.seed.ts` (đã có helper), `seeds/inventory.seed.ts`,
  `scripts/migrate-legacy-items.ts`.
