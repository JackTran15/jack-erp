# T-01-03 — Unit test cho descriptionSql() và getLedgerCard resolved-description

## Context

Không có test nào hiện có cho `getLedgerCard` hay bất kỳ hàm nào trong
`stock-summary-detail.service.ts`. `StockSummaryDetailService` gọi
`dataSource.query(sql, params)` trực tiếp (raw SQL, không qua QueryBuilder) —
khác với `StockSummaryService` (dùng `createQueryBuilder`), nên không thể tái
dùng y nguyên helper `createQueryBuilder()` của
`stock-summary.service.spec.ts`; cần mock `dataSource.query` trả kết quả theo
thứ tự gọi (`pageSql`, `statsSql`, opening/closing balances, pending transfers,
item).

## Implementation notes

- File mới `stock-summary-detail.service.spec.ts` cạnh service, theo đúng quy
  ước đặt tên trong thư mục (`stock-summary.service.spec.ts`,
  `stock-summary-export.service.spec.ts`).
- Mock tối thiểu:
  ```ts
  const query = jest.fn();
  const service = new StockSummaryDetailService({ query } as never);
  ```
  `getLedgerCard` gọi `Promise.all([...5 lời gọi query...])` theo đúng thứ tự
  trong source — dùng `query.mockResolvedValueOnce(...)` 5 lần theo đúng thứ tự
  đó (pageSql rows, statsSql, opening/closing, pending transfers raw rows,
  item unit) để mock khớp.
- Case 1 — hiển thị đúng Diễn giải (AC-01/AC-02): mock hàng trả về từ pageSql đã
  có cột `description` = giá trị mong đợi (test này chỉ xác nhận row mapper đọc
  đúng field mới, KHÔNG cần chạy Postgres thật — SQL CASE tự nó không unit-test
  được ở tầng này, chỉ kiểm tra được bằng test tích hợp hoặc thủ công như đã ghi
  trong T-01-02's Done-when).
- Case 2 — trống khi không có nguồn (AC-03): mock row `description: null` từ
  DB → assert response `data[0].description === null`.
- Case 3 — bộ lọc dùng đúng cột resolve (AC-04): gọi `getLedgerCard` với
  `dto.description` có giá trị → assert lời gọi `query` cho `pageSql`/`statsSql`
  (tham số SQL string) chứa `resolved_description` (không còn chứa
  `COALESCE(m.notes`).
- Test `descriptionSql()` độc lập (từ T-01-01) trong cùng file hoặc file riêng
  `stock-ledger-reference.constants.spec.ts` nếu thấy tách rõ ràng hơn: assert
  chuỗi SQL sinh ra chứa đúng arm cho `GOODS_RECEIPT` (`d.description`) và
  `STOCK_TAKE` (`COALESCE(d.purpose, d.conclusion, d.notes)`), và KHÔNG chứa arm
  cho `INVOICE`.
