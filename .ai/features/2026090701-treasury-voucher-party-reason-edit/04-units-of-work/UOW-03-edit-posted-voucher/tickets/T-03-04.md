# T-03-04 — Regenerate openapi + api-client cho revision

## Context

Bốn update DTO vừa nhận trường `revision` bắt buộc ở T-03-02 và T-03-03. FE cần schema mới trước
khi gửi được.

## Implementation notes

- Chạy API ở :4000 rồi `pnpm openapi:generate`
- Kiểm rằng `revision` sinh ra là **required**, không phải optional — nếu optional thì FE quên gửi
  sẽ hỏng âm thầm ở runtime thay vì hỏng lúc biên dịch
- Cùng hai bẫy đã ghi ở T-01-03: đừng build song song với `nest --watch`, và xác nhận :4000 chạy
  từ đúng checkout này

## Done when

- [x] `revision` xuất hiện và là bắt buộc trong `schema.ts` ở cả 4 update DTO
- [x] `openapi.snapshot.json` và `schema.ts` đều được commit
- [x] `pnpm --filter @erp/api-client build` xanh

## Sửa lúc thi công

- **Tiến trình `nest start --watch` trên :4000 (của người dùng, pid cha 50221) đã hỏng cơ chế
  build tăng dần**: `dist/` chứa `revision` cho `update-bank-receipt.dto.js` nhưng KHÔNG cho ba
  file DTO còn lại, dù cả bốn file nguồn giống hệt nhau. `touch` lại cả ba, chờ 60s, vẫn không
  biên dịch lại. Nghĩa là schema sống ở :4000 đứng ở một bản build dở dang.
- **Không đụng dev server của người dùng và cũng không chạy `pnpm build`** (nó ghi cùng `dist/`
  mà watch đang giữ — đúng bẫy đã ghi). Thay vào đó dựng bản riêng:
  `tsconfig.openapi.json` + `nest-cli.openapi.json` (giữ nguyên plugin `@nestjs/swagger`,
  `deleteOutDir: false`) → `outDir: dist-openapi` → chạy `PORT=4100` → sinh snapshot bằng
  `OPENAPI_URL=http://127.0.0.1:4100/docs-json` (script có sẵn biến môi trường này).
- Bẫy phải phòng: script `generate-openapi.mjs` **im lặng rơi về file stub** khi fetch hỏng, nên
  đã đọc dòng log `Wrote … from http://127.0.0.1:4100/docs-json` để chắc snapshot đúng nguồn,
  rồi kiểm lại `required: ['revision']` cho cả 4 DTO.
- Đã dừng tiến trình :4100 và xoá `dist-openapi/` + hai file config tạm.
- **Việc cho người dùng:** dev server :4000 đang phục vụ bản cũ; cần khởi động lại nó trước khi
  thử tay trên trình duyệt, nếu không FE sẽ gọi API thiếu `revision` và nhận 400.
