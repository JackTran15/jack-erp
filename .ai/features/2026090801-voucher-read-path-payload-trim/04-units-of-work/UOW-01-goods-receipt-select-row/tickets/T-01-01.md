# T-01-01 — Query chọn-dòng Nhập kho gọi `includeLines=false`

## Context
`PurchaseOrdersPage.tsx:394-403` chạy `useQuery(["goods-receipt", selectedId])` mỗi lần đổi
hàng đang chọn và gọi `GET /goods-receipts/{id}` **không** kèm cờ. BE mặc định
`includeLines ?? true` (`goods-receipt.service.ts:1095-1105`), nên phản hồi mang toàn bộ dòng
— trung bình 259,6 dòng, p95 1 994, max 5 000 trên bản restore prod.

Panel "Chi tiết" bên dưới **không** dùng mảng đó: nó phân trang riêng qua
`POST /v2/goods-receipts/{id}/lines/search` (`:979-996`). Nên số dòng tải về bị vứt đi.

Bốn chỗ khác trên chính repo đã gọi đúng cách rồi — dùng làm mẫu: `PurchaseOrdersPage.tsx:334`,
`:632`, `GoodsIssuePage.tsx:293`, `:609`.

## Implementation notes
- Đổi `queryFn` sang `erpApi.GET("/goods-receipts/{id}", { params: { path: {...},
  query: { includeLines: false } } })`. Nếu `openapi` chưa khai `includeLines` trên route này,
  dùng `apiClient.get(`/goods-receipts/${id}?includeLines=false`)` như bốn chỗ kia đang làm —
  **không** sửa file schema sinh tự động bằng tay.
- Giữ nguyên `queryKey: ["goods-receipt", selectedId]` để mọi lượt invalidate hiện có còn tác dụng.
- Kiểu `PurchaseOrder.lines` phải thành optional ở đường này; `goods-receipt-shared.ts:75` đã
  ghi chú sẵn rằng `lines` là optional từ T-02-01 của `2026083002` — kiểm lại kiểu, đừng ép
  `!` để cho qua TypeScript.
- Sửa comment `:389-393` ("the barcode toolbar, the duplicate/view/edit dialog, and DetailPanel
  all read from this") — sau ticket này nó sai.
