# T-03-03 — Route v2 `lines/search` + wiring + regenerate api-client

## Context
`transfer-order-v2.controller.ts` đã tồn tại và đã có hai route dòng cho phiếu **con**
(`:id/export-goods-issue/lines/search:47`, `:id/import-goods-receipt/lines/search:66`). Thêm
route thứ ba cho dòng của **chính lệnh điều chuyển**. Module đã import `CqrsModule` (hai route
kia dùng `QueryBus`), nên chỉ cần đăng ký handler mới.

## Ordering
`depends_on` gồm T-03-04 vì cả hai ticket đổi hợp đồng của cùng module — regenerate một lần,
sau khi cả hai đã xong. Bốn ticket sinh lại `openapi.snapshot.json` +
`packages/api-client/src/generated/schema.ts` (T-06-01 → T-03-03 → T-04-04 → T-05-03) chạy
**nối đuôi**; đây là ràng buộc về tệp, không phải về nghiệp vụ.

## Implementation notes
- `@Post(':id/lines/search')`, `@RequirePermission('inventory.transfer.read')` — khớp
  `GET /inventory/transfer-orders/:id` (`transfer-order.controller.ts:405-412`).
- `@ApiOperation` + `@ApiResponse` khai kiểu response tường minh. Bẫy đã gặp: controller v2 từng
  để schema response rỗng, api-client sinh ra `unknown` và FE phải ép kiểu bằng tay.
- `POST /search` trả **201** theo mặc định NestJS. Nếu muốn 200 thì `@HttpCode(200)` — chọn
  cái nào cũng được, nhưng phải **khớp với các route search khác trong repo**, kiểm trước.
- Đăng ký handler vào mảng providers của module.
- Chạy `pnpm openapi:generate` với API đang chạy ở `:4000`, commit cả
  `openapi.snapshot.json` và `packages/api-client/src/generated/schema.ts`. **Không** sửa tay
  file sinh tự động.
