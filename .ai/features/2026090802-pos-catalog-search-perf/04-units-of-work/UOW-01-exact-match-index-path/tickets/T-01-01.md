# T-01-01 — Builder SQL khớp tuyệt đối

## Context
`PosCatalogService.lookupByCode` (`pos-catalog.service.ts:296`) lọc bằng
`(i.code = $3 OR b.code = $3)` bắc qua một `LEFT JOIN item_barcodes`. Postgres không
đẩy được dạng đó vào index: đo trên `erp_dev_3008` ra **Seq Scan on items** (21 024
dòng) + **Seq Scan on item_barcodes** (21 023 dòng), 25,3 ms — dù cả hai bảng đều
đã có `UNIQUE(organization_id, code)`.

Dạng `UNION` đã đo: **1,1 ms**, hai `Index Scan`. Xem ADR-01.

## Implementation notes
- File mới `pos-catalog-sql.ts` chỉ chứa hàm dựng chuỗi SQL + mảng tham số, không
  inject gì, không chạm `DataSource` — để test được mà không cần DB.
- `buildExactMatchCte(orgParam, codeParam)` trả về CTE:
  ```sql
  SELECT id FROM items
   WHERE organization_id = $1 AND code = $3 AND is_active = true AND is_pos_visible = true
  UNION
  SELECT i.id FROM items i
    JOIN item_barcodes b ON b.item_id = i.id AND b.organization_id = i.organization_id
   WHERE b.organization_id = $1 AND b.code = $3
     AND i.is_active = true AND i.is_pos_visible = true
  ```
- `LIMIT 2` ở tầng gọi, không ở CTE: cần phân biệt "đúng 1 khớp" với ">1 khớp"
  (UOW-03 dùng để quyết `exact`), nhưng không cần đếm hết.
