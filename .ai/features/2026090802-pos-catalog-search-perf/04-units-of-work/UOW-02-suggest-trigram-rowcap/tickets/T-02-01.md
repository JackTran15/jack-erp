# T-02-01 — Migration trigram còn thiếu

## Context
`1781800000000-AddTrigramSearchIndexes` phủ `items.{code,name,brand,variant_label}`,
`customers.*`, `inventory_item_categories.name` và `products.name` — bỏ sót đúng hai
cột mà truy vấn catalog POS dùng: `item_barcodes.code` và `products.code`.

Đo trên `erp_dev_3008` (41 714 mã vạch): `b.code ILIKE '%235%'` → `Seq Scan`, 18,1 ms.
Sau khi thêm index → `Bitmap Index Scan`, nằm trong tổng 4,55 ms của cả truy vấn.

## Implementation notes
- Viết tay, không dùng `migration:generate` — [[feedback_handwrite_migrations]].
- `pg_trgm` đã được bật bởi migration 1781800000000; vẫn giữ
  `CREATE EXTENSION IF NOT EXISTS pg_trgm` cho môi trường dựng mới.
- `CREATE INDEX IF NOT EXISTS` + `DROP INDEX IF EXISTS` ở `down`, cùng khuôn với
  migration cũ.
- **Không** dùng `CONCURRENTLY`: đo được 240 ms / 1 296 kB trên bảng 41 714 dòng,
  không đáng phải phá tính nguyên tử của migration.
  ```sql
  CREATE INDEX IF NOT EXISTS "IDX_item_barcodes_code_trgm"
    ON "item_barcodes" USING gin ("code" gin_trgm_ops);
  CREATE INDEX IF NOT EXISTS "IDX_products_code_trgm"
    ON "products" USING gin ("code" gin_trgm_ops) WHERE "code" IS NOT NULL;
  ```
- `products.code` nullable (đã có `UQ_products_org_code … WHERE code IS NOT NULL`),
  nên index partial cho khớp.
