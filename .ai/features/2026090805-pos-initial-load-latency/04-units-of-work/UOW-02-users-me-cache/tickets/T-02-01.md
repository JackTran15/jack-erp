# T-02-01 — Cache `getMe`

## Context

`getMe` (`users.service.ts:302-321`) chạy `findById` + truy vấn role + permissions. Chỉ
nhánh permissions đã có cache (`rbac:perms`); hai nhánh còn lại truy vấn mỗi lần tải trang.

Cần nói rõ để khỏi đặt sai kỳ vọng: 641 ms trên dev server phần lớn là thời gian **chờ**
event loop bị chặn chứ không phải thời gian làm việc (A-09). Ticket này cắt phần việc
thật; phần chờ thuộc feature khác.

## Implementation notes

Namespace `users-me`, khoá `${userId}:${orgId}` — cùng hình dạng khoá `my-branches` dùng.
TTL 15 phút (ADR-04); khai báo thành hằng số cạnh `MY_BRANCHES_CACHE_NAMESPACE` ở `:50`.

```ts
const USERS_ME_CACHE_NAMESPACE = "users-me";
const USERS_ME_CACHE_TTL_SECONDS = 15 * 60;
```

**Điểm dễ sai:** `CacheService.getOrSet` (`cache.service.ts:28-53`) **không** bọc
try/catch — Redis chết là ném thẳng ra ngoài, và `/admin/users/me` chết theo thì không ai
đăng nhập được. Bọc ở chỗ gọi:

```ts
async getMe(actor) {
  try {
    return await this.cacheService.getOrSet(NS, key, () => this.buildMe(actor), TTL);
  } catch (err) {
    this.logger.error(`users-me cache unavailable for user=… org=… — reading through`, …);
    return this.buildMe(actor);
  }
}
```

Tách phần thân hiện tại của `getMe` thành `private buildMe(actor)` để cả hai nhánh dùng
chung. Cách ghi log theo đúng khuôn `invalidateUserIdentity` ở `:110-115`.
