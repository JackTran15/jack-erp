# T-01-03 — Cột mới trong file xuất khẩu

## Context

`POST /v2/cash-vouchers/export` chạy lại **đúng** DTO + query của `search` (ADR-06 của
feature 2026090804), nên không có nhánh dữ liệu thứ hai để lệch — chỉ danh sách cột là khai
báo riêng. Đây là đường xuất khẩu **duy nhất** bị ảnh hưởng trong cả feature (A-05).

## Implementation notes

- `EXPORT_COLUMNS` (`cash-voucher-v2.controller.ts:44-53`): chèn
  `{ col: 'personName', label: 'Người nộp/nhận', type: ReportColumnDataType.STRING }`
  ngay sau mục `counterparty`. Chú thích phía trên nói danh sách này theo đúng thứ tự lưới —
  giữ lời hứa đó.
- `cash-voucher-export.fetcher.ts`: kiểm nó có chiếu cột theo danh sách trắng không. Nếu có,
  thêm `personName`; nếu nó trả nguyên hàng thì không phải sửa — **đọc trước khi sửa**.
- Cảnh báo đã trả giá ở feature trước: `VoucherXlsxWriter` từng vỡ vì `mergeCells` sau
  `row.commit()` khi có **hai cột STRING dẫn đầu**. Đường này (`XlsxStreamWriter`) khác
  writer đó, nhưng lỗi biểu hiện ra là **file tải về hỏng chứ không phải HTTP lỗi**, nên
  bằng chứng phải là *mở được file*, không phải *nhận được 200*.

## Done when

- [x] Spec khẳng định `EXPORT_COLUMNS` chứa `personName` **ngay sau** `counterparty`
- [x] Spec khẳng định fetcher trả trường mới xuống writer
- [x] `pnpm --filter @erp/api test -- --testPathPattern cash-voucher-export` xanh

Việc *mở được file tải về* (AC-14) là bằng chứng G4 của UOW-01 — không đặt ở đây.
