# T-05-01 — Sinh lại hợp đồng API

## Context

Bốn DTO đã đổi. Các lưới treasury gọi qua `apiClient` axios với kiểu viết tay nên **không**
phụ thuộc client sinh tự động — nhưng quy ước repo là snapshot phải theo kịp endpoint, và
người đọc `schema.ts` sau này phải thấy `personName`.

## Kết quả (2026-09-09)

`:4000` (dev server `nest start --watch`) phục vụ build **cũ một phần**: `personName` có ở 4
schema chứng từ nhưng **thiếu ở cả hai schema sổ** — đúng cái bẫy ghi trong ticket. Sinh từ đó
sẽ cho một hợp đồng thiếu một nửa mà không báo lỗi gì. Build riêng ở `:4100` cho đủ 6/6.

Hai file cấu hình `nest-cli.openapi.json` + `tsconfig.openapi.json` được tạo **tạm** rồi xoá
sau khi sinh xong, cùng với `apps/api/dist-openapi/` — để diff của feature không mang theo
công cụ build. Công thức nằm ngay dưới đây, dựng lại mất 30 giây.

## Implementation notes

**Không** chạy `pnpm build` (đụng `dist/` mà `nest start --watch` đang giữ) và **không** tin
dev server `:4000` — nó phục vụ build cũ một phần. Công thức đã trả giá ở feature 2026090804:

```bash
./node_modules/.bin/nest build -c nest-cli.openapi.json      # outDir: dist-openapi
PORT=4100 node dist-openapi/main.js                          # boot ~2 phút vì Kafka consumer
OPENAPI_URL=http://127.0.0.1:4100/docs-json pnpm openapi:generate
```

`generate-openapi.mjs` **im lặng rơi về file stub** khi fetch hỏng — bằng chứng bắt buộc là
dòng log `Wrote … from <url>`, không phải exit code 0.
