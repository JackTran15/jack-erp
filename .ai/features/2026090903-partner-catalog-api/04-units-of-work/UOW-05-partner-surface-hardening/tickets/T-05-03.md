# T-05-03 — Sinh lại OpenAPI client, commit snapshot và cập nhật docs đối tác

## Context

Quy ước repo: sửa endpoint xong thì chạy `pnpm openapi:generate` và commit cả hai file sinh
ra. Đây cũng chính là tài liệu đối tác đọc. Change request 2026-09-13 (ADR-07..09) đổi hợp đồng đối tác
ở ba chỗ, nên `docs/partner-catalog-api.md` phải đổi cùng lượt với snapshot.

## Implementation notes

- Bật API rồi chạy `pnpm openapi:generate`. **Không** sửa tay `schema.ts`.
- **Bẫy đã dính:** phải sinh từ một build riêng (cổng `:4200`, `OPENAPI_URL=http://127.0.0.1:4200/docs-json`; ngày 2026-09-13
  `:4100` đang bị API của checkout `jack-erp` chiếm — kiểm `lsof` trước khi bật), vì `:4000` có thể đang được phục
  vụ bởi checkout khác trỏ DB khác — khi đó snapshot sinh ra từ mã nguồn không phải mã mình vừa sửa.
- Kiểm trong `schema.ts`: cả 3 endpoint có kiểu response cụ thể, không phải `unknown`. Đây đúng chỗ
  nhiều controller v2 cũ trong repo bị rỗng schema.
- Kiểm `packages/api-client/openapi.snapshot.json` chỉ chứa thay đổi của 3 endpoint mới — diff phình ra chỗ khác nghĩa là
  snapshot đang sinh từ nhánh hoặc DB sai.
- `docs/partner-catalog-api.md`: §1 và §7 — endpoint 3 thành `GET /v2/partner/catalog/products/:productCode`,
  bỏ trạng thái *"Not routable yet"*; §4 — `inStock` trong bảng request với nghĩa `true`/`false` (ADR-08)
  và đoạn "dòng thu hẹp về biến thể khớp" (ADR-07); §5 — product không có mã không mở được chi tiết, mã
  chứa ký tự đặc biệt phải percent-encode (A-17, A-20); §6 — 404 cho UUID, SKU biến thể, mã khác hoa thường.
