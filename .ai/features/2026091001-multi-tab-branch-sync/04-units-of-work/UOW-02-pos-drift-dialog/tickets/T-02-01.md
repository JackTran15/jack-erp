# T-02-01 — Detector lệch chi nhánh (POS)

## Context

POS khác backoffice ở một điểm quyết định: access token nằm ở `localStorage.pos_access_token`
và **dùng chung mọi tab** (`apps/pos-web/src/lib/common/api-axios.ts:21`). Vì `@Actor` ưu
tiên `jwt` (`actor-context.decorator.ts:33`), `branchId` trong token **chính là** chi nhánh
mà server đang trả dữ liệu — đọc thẳng nó, không đọc khoá persist `pos-branch` (ADR-02, A-04).

Vị trí file theo `apps/pos-web/CLAUDE.md` §6: hook không dính React Query, dùng ở tầng vỏ ⇒
`hooks/common/use-<name>.ts`, named export, một file một hook.

## Implementation notes

- Chữ ký:

  ```ts
  export function usePosBranchDrift(): {
    drifted: boolean;
    sessionBranchId: string | null;   // branchId trong pos_access_token
    tabBranchId: string | null;       // baseline
    resetBaseline: () => void;
  }
  ```

- Giải token bằng `parseAccessTokenPayload` đã có (`lib/common/parseJwt.ts`) — đúng cách
  `PosLocationIndicator.tsx:39-41` đang làm. Không tự viết lại `atob`.
- Token đọc không ra / JSON hỏng ⇒ trả `drifted: false` (fail-open, error taxonomy). Dialog
  chặn màn hình là thứ đắt nhất để bật nhầm.
- Baseline nằm ở **tầng module**, không phải `useRef` (ADR-01), và hook đọc qua
  `useSyncExternalStore`. Ở POS đây không phải chuyện sạch sẽ mà là chuyện đúng/sai:
  đổi chi nhánh ở POS **không reload trang**, nên nếu `handleChange` gọi `resetBaseline()`
  của instance nó mà dialog ôm baseline riêng, tab vừa tự đổi sẽ lập tức tự bật dialog hỏi
  chính mình.
- Baseline chốt tại lần đọc đầu, không tự ghi lại. Đây là thứ giữ cho ca đăng nhập mới ở
  AC-13 **không** bị coi là lệch.
- Tín hiệu đọc lại: `storage` (`event.key === POS_ACCESS_TOKEN_KEY` hoặc `null`),
  `visibilitychange` → `visible`, `focus`, và một lần lúc mount.
- Tắt khi không còn `pos_refresh_token` (đăng xuất ở tab khác — A-12).
- Dùng hằng `POS_ACCESS_TOKEN_KEY` / `POS_REFRESH_TOKEN_KEY` từ
  `constants/common.constant.ts`; không hard-code chuỗi khoá (CLAUDE.md §8).
- Gỡ listener trong cleanup.
