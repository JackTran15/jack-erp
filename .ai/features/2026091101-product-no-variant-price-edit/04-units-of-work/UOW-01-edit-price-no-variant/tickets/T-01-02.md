# T-01-02 — Unit test: update() hàng lẻ giữ purchasePrice/sellingPrice

## Context

Bản sửa UI (T-01-01) dựa vào việc backend ghi giá khi cập nhật. Nhánh product
(`updateProductWithVariants` → `pickProductVariantSharedItemFields`) đã có test
(`item-crud-variants.service.spec.ts:330`). Nhánh hàng lẻ — `:id` là `items.id`, đi
`update` → `super.update` → `beforeUpdate` → `stripDerivedFields` — thì chưa có test nào khẳng
định giá đi qua, trong khi đây là nhánh của 366 hàng lẻ trên `erp_dev_3008`.

Test này **xanh ngay trên `main`**: nó khoá hành vi hiện có để bản sửa không âm thầm hỏng nếu
sau này ai đó thêm giá vào `stripDerivedFields`. Nó không tái hiện lỗi — lỗi nằm ở UI.

## Implementation notes

- Thêm test vào `describe('InventoryItemCrudService.update (nested reconcile)')` sẵn có; spec đã
  mock `dataSource.getRepository().exist → false` (nhánh hàng lẻ) và `repo.merge`.
- Case 1 — giá dương, kèm field suy ra mà form sửa gửi lên:
  `service.update('item-1', { name: 'Item', categoryName: 'Nhóm A', purchasePrice: 110000, sellingPrice: 200000 }, actor)`
  → `expect(repo.merge).toHaveBeenCalledWith(expect.anything(), expect.objectContaining({ purchasePrice: 110000, sellingPrice: 200000 }))`
  và `expect.not.objectContaining({ categoryName: expect.anything() })`.
- Case 2 — giá 0 (ô trống đã map về 0, ADR-03): `{ purchasePrice: 0, sellingPrice: 0 }` → merge nhận
  đúng `0`, không phải `undefined` (`normalizePayload` chỉ đổi `""`).
- Theo style của file: nháy đơn, `as any` cho payload như các test bên cạnh.
- Không đổi code production.
