# T-04-01 — Chặn `is_tracked` trong `resolveAssignedLocation`

## Context

Dialog "Xếp vị trí hàng hóa" chặn lưu khi `GET /products/storage-location` trả một kệ khác kệ đích
(`ArrangeLocationDialog.tsx:438-450`). Resolver (`item-storage-location.service.ts:291-305`) đọc liên kết
`(item, storage)` và chỉ lọc `locations.isActive` — cờ của kệ — nên liên kết trỏ vào cặp (mặt hàng, kệ) đã
"Ngừng theo dõi" (`stock_balances.is_tracked = false`) vẫn bị coi là vị trí hiện tại.

A-05 của `2026090301-inventory-qa-defects` (chốt 03/09/2026) yêu cầu mọi chỗ đọc liên kết tự chặn; quy tắc
đã có ở `InventoryLocationStockService.isBalanceTracked` (`inventory-location-stock.service.ts:1115-1125`),
nhưng hàm đó private và module location đã phụ thuộc ngược vào service này (ADR-04).

## Implementation notes

- `product.module.ts:21-30`: thêm `StockBalanceEntity` (`../ledger/stock-balance.entity`) vào `TypeOrmModule.forFeature`.
- Constructor: `@InjectRepository(StockBalanceEntity) private readonly stockBalanceRepo: Repository<StockBalanceEntity>`.
- Sau khi tìm được `location`:
  ```ts
  const balance = await this.stockBalanceRepo.findOne({
    where: { organizationId, itemId, locationId: location.id },
    select: { id: true, isTracked: true },
  });
  if (balance && !balance.isTracked) return null;
  ```
  Chưa có dòng tồn ⇒ vẫn trả kệ (A-09), đúng quy tắc `isBalanceTracked`.
- Sửa chú thích `:300` cho đúng: lọc `isActive` là cờ của kệ; chặn "Ngừng theo dõi" là bước tra `stock_balances`.
- Spec: đổi tên case `:348` thành "lọc isActive của kệ"; thêm provider mock `getRepositoryToken(StockBalanceEntity)`.
- Grep `ItemStorageLocationService` trong `*.spec.ts` và `test/e2e`: nơi nào dựng service bằng provider thật phải có
  token repository mới.
