# T-01-09 — Thư viện tải file phía backoffice — uploadMedia và hook useMediaUpload

## Context

Code FE dùng chung cho cả 3 chủ sở hữu (`03-logical-design.md` → State ownership). Điểm dễ sai
nhất: byte file **không được** đi qua `erpApi`/axios, vì interceptor gắn `Authorization`,
`X-Branch-Id`, `X-Idempotency-Key` vào mọi request (`apps/backoffice-web/src/lib/api-axios.ts:37-55`).

## Implementation notes

- `media-upload.api.ts`: `createUpload(body)` và `completeUpload(id)` qua `erpApi` +
  `requireErpData` (kiểu lấy từ `schema.ts` đã sinh lại ở T-01-04). `uploadToStorage(upload, file)`
  dùng `fetch(upload.url, { method: 'POST', body: formData, credentials: 'omit' })`; `FormData` nối
  **mọi** trường trong `upload.fields` theo thứ tự trước, trường `file` **sau cùng** (POST policy
  yêu cầu file là trường cuối). Non-2xx → lỗi `UploadFailed`.
- `media-limits.ts`: bản sao giới hạn phía client của A-09 theo `ownerType`. Server vẫn là nơi quyết
  định; bản này chỉ để báo lỗi sớm.
- `useMediaUpload(ownerType, initial?)`: state từng file `{ localId, file?, previewUrl?, status: 'uploading' | 'done' | 'error', mediaId?, error? }`;
  `add(files)` kiểm giới hạn → xin vé → tải → xác nhận; `remove(localId)`; `retry(localId)` xin vé mới;
  trả `mediaIds` theo thứ tự và `isUploading`. Thông báo lỗi tiếng Việt; `STORAGE_UNAVAILABLE` →
  "Không thể tải tệp lên lúc này".
- Không đưa server data vào Zustand; không thêm vào `@erp/ui` (hook gọi API của app).
