# T-05-01 — MediaCleanupJob hằng ngày và lệnh chạy tay media:cleanup

> **Sửa sau khi đóng** (2026-09-13): theo bất biến mới ở ADR-05 (re-review T-01-04), bước 2 phải bỏ qua dòng còn
> trong hạn vé tải lên, nếu không object tải lại bằng vé cũ sẽ không bao giờ được dọn. Thay đổi làm trong
> `media-cleanup.job.ts` dưới ticket T-01-04, không mở lại ticket này.

## Context

ADR-05: gỡ media chỉ đánh dấu `DELETED` trong transaction; object thật bị xoá sau commit hoặc bởi job
này. Job cũng dọn file đã tải lên nhưng không bao giờ được gắn (A-18). `ScheduleModule` đã đăng ký
(`app.module.ts:95`) và repo có đúng một `@Cron` để làm mẫu
(`apps/api/src/modules/pos/services/overdue-debts.service.ts:10-35`, chạy lúc 1 giờ sáng). Class job đã
được đăng ký trong module ở T-01-02; ticket này không sửa `media.module.ts`.

## Implementation notes

- `@Cron(CronExpression.EVERY_DAY_AT_2AM)`, chạy xuyên tổ chức như job nợ quá hạn, lệch sau nó 1 giờ.
- Bước 1: một câu `UPDATE media_objects SET status = 'DELETED', deleted_at = now() WHERE status IN ('PENDING','UPLOADED') AND created_at < now() - interval '24 hours'`.
- Bước 2: lấy theo lô 500 dòng `DELETED` có `object_removed_at IS NULL` → `deleteObject` từng object →
  đặt `object_removed_at`. Lỗi từng object chỉ đếm, không dừng cả lô; `STORAGE_UNAVAILABLE` → log một
  lần rồi dừng.
- **Không bao giờ** chạm dòng `ATTACHED`.
- Log `media.cleanup` với số dòng hết hạn, số object đã xoá, số lỗi.
- `media-cleanup.seed.ts` gọi đúng phương thức `run()` của job; thêm script `media:cleanup` vào
  `apps/api/package.json` cạnh `media:bootstrap`.
- API chạy một tiến trình PM2 (`apps/api/ecosystem.config.cjs:31-32`) nên không cần khoá phân tán (A-18).

## Done when

- [x] Unit: `PENDING` / `UPLOADED` quá 24 giờ → `DELETED`; chưa tới 24 giờ → không đổi — `media-cleanup.job.spec.ts` compares the whitespace-normalised step-1 `UPDATE` against the exact expected statement (`status IN ($1, $2)`, `created_at < now() - interval '24 hours'`, `updated_at = now()`), so a `NOT IN` or dropped clause would fail the test; the boundary itself is Postgres's own `<`/`interval` evaluation, not app code. Confirmed end-to-end twice against real Postgres/MinIO: a 25h-old `UPLOADED` row became `DELETED` with `deleted_at`, `updated_at` (bumped) and `object_removed_at` set, its object gone from MinIO
- [x] Unit: `ATTACHED` không bị đổi, dù cũ đến đâu — spec asserts step 1's params never include `ATTACHED` and step 2 only ever selects `status: DELETED`; confirmed against real DB twice: the `ATTACHED` probe row was untouched (`status`, `deleted_at`, `updated_at`, `object_removed_at` all unchanged) after the run
- [x] Unit: lỗi xoá một object không chặn các object còn lại; `STORAGE_UNAVAILABLE` dừng sạch — covers a generic delete failure not blocking the rest of a batch, `MediaException('STORAGE_UNAVAILABLE')` stopping after exactly one attempt with a single `logger.error` call (and step 1's `expiredCount` still present in the summary), and distinct error names reaching the summary log without keys/messages. Code review (2026-09-13) found step 2's original `failedIds` design could starve newer rows behind a block of permanently-failing ones (measured: 600 failing + 200 healthy → `removed=0 failed=500`, loop exiting early); fixed by paging with a keyset cursor on `id` (not `createdAt`, since `timestamptz` microseconds vs. JS `Date` milliseconds could re-select the cursor row) that advances past every row regardless of outcome. New test with a real in-memory repo (600 failing + 200 healthy) proves `removed=200 failed=600` in ≤3 `find()` calls
- [x] `pnpm --filter @erp/api media:cleanup` chạy được trên local, đúng demo script của UOW-05 — ran with `DB_NAME=erp_dev` against local Postgres + MinIO, twice (before and after the review fix); both times logged `media.cleanup expired=1 removed=1 failed=0`, verified via SQL/`aws s3api`, and all probe rows/objects were deleted afterward (see implementer report)
- [x] `media.module.ts` không bị sửa — not in this diff (`git status` confirms only `media-cleanup.job.ts`, its new spec, the new seed, and the `package.json` script line changed)
