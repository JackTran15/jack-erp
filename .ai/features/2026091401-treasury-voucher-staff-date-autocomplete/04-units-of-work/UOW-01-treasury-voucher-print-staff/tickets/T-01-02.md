# T-01-02 — Resolver nhân viên dùng được từ module tiền mặt

## Context

Service phiếu tiền mặt cần tên nhân viên thu/chi và tên người tạo để in (A-01). Resolver đã có, nhưng nằm ở
`deposit-vouchers/shared`, và `DepositVouchersModule` import `CashVouchersModule` — module tiền mặt không import ngược
được (ADR-03). `PartnerResolverService` đã đi đúng hướng cần làm: file ở `cash-vouchers/shared`, module tiền gửi tự khai
lại làm provider.

Ticket này không đổi hành vi nào người dùng thấy: bản in giữ nguyên cho tới T-01-03.

## Implementation notes

- `git mv` file resolver sang `cash-vouchers/shared/`. Sửa đường import trong 2 service tiền gửi, 2 spec của chúng,
  `deposit-vouchers.module.ts`, và chỗ nhắc đường dẫn trong `employee-branch-scope.md`. Import tương đối
  `../../../auth/user.entity` và `../../../rbac/employee/employee-profile.entity` giữ nguyên độ sâu vì cùng cấp thư mục.
- `CashVouchersModule`: thêm `UserEntity`, `EmployeeProfileEntity` vào `TypeOrmModule.forFeature`, thêm
  `VoucherStaffResolver` vào `providers`. `DepositVouchersModule` giữ provider của mình (như `PartnerResolverService`).
- Thêm vào file resolver:
  ```ts
  export interface TreasuryVoucherPeople { staffName: string | null; creatorName: string | null }
  async resolvePeople(staffId, createdBy, organizationId): Promise<TreasuryVoucherPeople>
  ```
  gọi `resolveMany([staffId, createdBy], organizationId)` **một lần**; id không resolve ⇒ `null`. Không tự lùi
  `staffName` về người tạo — việc lùi thuộc về mapper (ADR-02, A-07).
- `TreasuryPrintLabels` thêm `staffLabel`: "Nhân viên thu" cho `CASH_RECEIPT`, `BANK_RECEIPT`; "Nhân viên chi" cho
  `CASH_PAYMENT`, `BANK_PAYMENT` (A-06).
