# T-01-01 — Reject removeItemFromLocation when quantity is non-zero

## Context

`removeItemFromLocation` (inventory-location-stock.service.ts:306-353) already throws
`ForbiddenException` for negative balances. For positive balances it currently calls
`stockTransferService.postIntraWarehouseMoves` to move stock to the storage's
"Chưa xếp" location and only then deletes the balance row — an implicit, immutable CK
transfer as a side effect of a "remove from view" action (see ADR-01 in
`03-logical-design.md`). Replace that branch with the same `ForbiddenException` guard used
for negative stock; only `quantity === 0` should reach the delete + `clearLocation` path.

## Implementation notes

- Change the `quantity > 0` branch to throw, instead of resolving `ensureUnassignedLocation`
  and calling `postIntraWarehouseMoves`. Keep the existing negative-balance branch as is.
- Message should mirror the existing negative-balance one in tone/format, e.g.
  `'Không thể bỏ hàng hóa đang còn tồn kho. Hãy chuyển hết tồn sang vị trí khác trước.'`
- `locationService` / `stockTransferService` stay injected (still used by `arrange`) — do
  not remove them or their imports.
- Update the controller's `@ApiOperation` summary on `DELETE :locationId/stock-items/:itemId`
  — it currently says "tồn dương được chuyển về Chưa xếp cùng kho", which becomes false.
- Update the existing spec: the test named "moves positive stock to Chưa xếp before
  removing the shelf row" (inventory-location-stock.service.spec.ts:320-346) asserts the
  old behavior and must become a rejection test (mirror the existing negative-stock test at
  line 348-361); the zero-balance test (line 299-318) stays unchanged.

- [x] `quantity === 0` still deletes the balance row and clears the preferred shelf
