# T-01-02 — Disable remove icon with tooltip when a located item has stock

## Context

The trash-icon button in the `_actions` column (LocationStockItemsDialog.tsx:291-306)
always calls `markForDelete`. It must become non-interactive for rows with quantity > 0,
matching the backend rejection in T-01-01, with a tooltip explaining why — reusing this
file's existing pattern of a plain `title` attribute for tooltips (no new component; this
file does not otherwise import `@erp/ui`'s Tooltip primitives).

## Implementation notes

- Compute `const qty = Number(r.quantity);` inside the `_actions` column's `render`
  (the `quantity` column already does `Number(r.quantity)` — same field).
- `disabled={qty > 0}` on the `<button>`.
- `title` becomes conditional: keep `"Đánh dấu bỏ khỏi vị trí"` when `qty === 0`; when
  `qty > 0` use something like `"Không thể bỏ hàng hóa đang còn tồn kho. Hãy chuyển hết tồn sang vị trí khác trước."`
  — match the backend message from T-01-01 so the two surfaces agree.
- Give the disabled state a visible affordance (e.g. `disabled:opacity-40 disabled:hover:bg-transparent disabled:cursor-not-allowed` alongside the existing classes) so it doesn't just look broken.
- `aria-label` can stay static or follow the same conditional — keep it simple.

## Done when

- [x] Hovering a disabled trash button shows the blocked-reason tooltip
- [x] Row with quantity = 0 is unaffected — button enabled, existing tooltip, click still
      calls `markForDelete` and the existing "Lưu" flow still deletes it
