# T-01-02 — `POST /inventory/items/set-images`

## Context
ADR-02. Khuôn là `setActiveStatus` + route `items/set-active-status`
(`inventory-location.controller.ts:73-82`, `item-crud.service.ts:230-305`): nhận id dòng lưới, suy
ra thứ nó đại diện, trả `updated/skipped`. Quy tắc media (skill `media-upload-fetch`): **owner type
và owner id suy từ bản ghi, không từ body; trong transaction luôn truyền `manager`**.

`ItemCrudService` đã 2.000 dòng — đặt logic vào file mới `item-images.service.ts` (một service,
một method công khai), không nhét thêm vào CRUD service.

## Implementation notes
- DTO: `SetItemImagesDto { assignments: SetItemImagesAssignmentDto[] }` với `@ArrayMinSize(1)
  @ArrayMaxSize(50) @ValidateNested({ each: true }) @Type(...)`; assignment `{ id: @IsUUID,
  imageIds: @IsArray @IsUUID('all', { each: true }) @ArrayMaxSize(10) }`. Response
  `{ updated: { id, code, imageCount }[], failed: { id, code: string | null, reason: string }[] }`.
  Export qua `dto/index.ts` như `SetItemActiveStatusDto`.
- Route: `@Post('items/set-images') @RequirePermission('inventory.write')` đặt **trước** mọi route
  `items/:id` (cùng lý do comment ở `set-active-status`).
- Service `ItemImagesService.setImages(assignments, actor)`:
  1. Một truy vấn gom owner: `SELECT id, 'PRODUCT' AS owner_type, code FROM products WHERE
     organization_id = $1 AND id = ANY($2) UNION ALL SELECT id, 'ITEM', code FROM items WHERE
     organization_id = $1 AND product_id IS NULL AND id = ANY($2)`. Id vắng mặt ⇒
     `failed { reason: 'OWNER_NOT_FOUND', code: null }` — kể cả id biến thể (client phải gửi id mẫu mã).
  2. Với từng assignment còn lại: `dataSource.transaction(manager => mediaLink.syncOwner(ownerType,
     id, imageIds, actor, manager))`; bắt **chỉ** `MediaException` ⇒ `failed { reason: err.code }`;
     lỗi khác ném tiếp. Trùng id trong cùng body: xử lý theo thứ tự, lần sau thắng (syncOwner
     idempotent).
  3. `updated[].imageCount = ids trả về từ syncOwner`.length.
- Log một dòng `info` mỗi lượt: số updated/failed, không log mediaId.
- Spec (stub `MediaLinkService` như `cash-receipts.service.spec.ts:115-117`): owner map đúng
  PRODUCT/ITEM; id lạ ⇒ OWNER_NOT_FOUND không gọi syncOwner; `MediaException` 404 ⇒ failed và các
  assignment sau vẫn chạy; lỗi `Error` thường ⇒ ném; tham số thứ 5 của syncOwner là `manager`.
- E2E: theo `media-product-images.e2e-spec.ts` để có mediaId UPLOADED; A (product) + C (item) +
  id org khác + mediaId org khác trong một body ⇒ `updated` 2, `failed` 2 với đúng reason; GET
  record A trả images theo thứ tự; media org khác vẫn `UPLOADED`; tài khoản `inventory.read` ⇒ 403;
  body có `ownerType` ⇒ 400; gọi lại cùng `X-Idempotency-Key` ⇒ `X-Idempotency-Status: REPLAYED`.
