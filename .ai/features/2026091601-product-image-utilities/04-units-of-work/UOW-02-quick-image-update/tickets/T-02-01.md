# T-02-01 — Tách tên file và khớp mã trên server

## Context
ADR-03: quy tắc `SKU (NN)` nằm ở API vì backoffice không có bộ chạy test. Khuôn CQRS "resolve":
`ResolveItemLocationsQuery` / `Handler` / `Controller`. Quy tắc tách và thứ tự khớp ghi ở
`03-logical-design.md` › Domain model (4 bước). Bốn con số đo được trên `erp_dev` quyết định
thiết kế: 0 mã kết thúc `(NN)`, 0 mã trùng khi lower(), 1 biến thể trùng mã mẫu mã ⇒ mẫu mã thắng.

## Implementation notes
- `parse-image-file-name.ts` — hàm thuần, không import Nest:
  `parseImageFileName(name: string): { code: string; seq: number | null; error: 'SEQ_OUT_OF_RANGE' | null }`.
  Bỏ đuôi `/\.(jpe?g|png|gif|webp)$/i`, `trim()`, regex `^(.*?)\s*\((\d{1,2})\)$`. `seq` 1..10 hợp
  lệ; `(00)`, `(11)`, `(99)` ⇒ `SEQ_OUT_OF_RANGE` nhưng vẫn trả `code` để thẻ hiện được mã. Tên rỗng
  sau khi cắt ⇒ `code = ''`.
- DTO: `ResolveImageNamesDto { names: string[] }` `@ArrayMinSize(1) @ArrayMaxSize(500)
  @IsString({ each: true }) @MaxLength(255, { each: true })`. Response
  `{ data: ResolvedImageNameDto[] }` theo thứ tự `names`.
- Handler: parse tất cả → tập `lower(code)` duy nhất → hai truy vấn:
  `SELECT id, code, name FROM products WHERE organization_id = $1 AND lower(code) = ANY($2)` và
  `SELECT id, code, name, product_id FROM items WHERE organization_id = $1 AND lower(code) = ANY($2)`
  (không lọc `is_active`, A-13). Ưu tiên: product → item orphan → item biến thể (`ownerId =
  product_id`, `ownerCode/ownerName` của **mẫu mã** — cần thêm một truy vấn products theo
  `product_id` của các biến thể khớp, hoặc `JOIN products` ngay trong truy vấn items). Với
  `variant`, giữ `code` là mã biến thể người dùng gõ.
- `DUPLICATE_SEQ`: sau khi khớp, duyệt theo thứ tự `names`; `(ownerId, seq)` đã gặp và `seq !== null`
  ⇒ tên sau nhận `error: 'DUPLICATE_SEQ'` (giữ `match`/`ownerId` để thẻ vẫn ghi mẫu mã nào).
- Controller: `@Post('resolve-image-names') @Version('2') @RequirePermission('inventory.read')`
  trong `InventoryItemV2Controller`; đăng ký handler trong module.
- Spec parse: bảng ca — `"ABC (01).png"`, `"ABC(2)"`, `"abc (10).PNG"`, `"ABC (11)"`, `"ABC (00)"`,
  `"ABC"`, `"ABC.jpeg"`, `"(01)"` (code rỗng), `"A B (03)"` (mã có khoảng trắng), `"ABC (1) (2)"`
  (chỉ đuôi cuối là STT).
- Spec handler: stub `manager.query`; khẳng định thứ tự ưu tiên, biến thể trỏ về mẫu mã cha,
  DUPLICATE_SEQ đúng tên thứ hai, response giữ thứ tự input, 2 truy vấn cho 500 tên.
- E2E: A (product), B (orphan), biến thể của A, mã ngừng kinh doanh, tổ chức khác ⇒ null; 501 tên ⇒ 400.
