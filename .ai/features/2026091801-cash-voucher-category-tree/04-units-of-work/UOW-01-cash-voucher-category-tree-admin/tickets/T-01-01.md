# T-01-01 — Schema + luật cha/con

## Context

`CashVoucherCategoriesService` (`cash-voucher-categories.service.ts`) hiện là `BaseCrudService` không override gì;
`DeletionPolicy.SOFT`. Khuôn để chép:

- Cột + FK + index: `inventory/location/item-category.entity.ts:26-40` và migration
  `1782400000000-ExtendItemCategory.ts:14-57` (FK `ON DELETE SET NULL`, bọc `DO $$ … EXCEPTION WHEN duplicate_object`).
- `normalizePayload` (''→`null`, **không** `undefined` vì `repository.merge` bỏ qua `undefined`) và `assertNoCycle`
  với tập `seen`: `inventory/location/supplier-group-crud.service.ts:49-128`.
- Hook có sẵn: `beforeCreate(payload, actor)`, `beforeUpdate(id, payload, actor)`, `beforeDelete(id, actor)` —
  `crud/base-crud.service.ts:187-242`; `remove()` gọi `beforeDelete` trước khi xoá mềm (`:146-181`).

## Implementation notes

- Migration `1790030000000-AddCashVoucherCategoryParentGroup`: `ALTER TABLE "cash_voucher_categories" ADD COLUMN
  "parent_group_id" uuid`; FK `FK_cash_voucher_categories_parent_group` → `cash_voucher_categories(id) ON DELETE SET
  NULL`; `CREATE INDEX IDX_cash_voucher_categories_parent_group ON … (parent_group_id)`. `down()` bỏ index, FK, cột.
  Không migration dữ liệu (A-05).
- Entity: `@Column({ name: 'parent_group_id', type: 'uuid', nullable: true }) parentGroupId?: string | null;`
  `@ManyToOne(() => CashVoucherCategoryEntity, { nullable: true }) @JoinColumn({ name: 'parent_group_id' }) parent?`.
- Service:
  - `beforeCreate`: normalize; nếu có `parentGroupId` → `loadParent` (`findOne({ id, organizationId })`, soft-delete
    filter mặc định của TypeORM đã loại dòng xoá mềm) → thiếu ⇒ `BadRequestException('Mục cha không tồn tại')`;
    `parent.direction !== payload.direction` ⇒ `'Mục cha phải cùng loại Thu/Chi'`.
  - `beforeUpdate`: normalize; `parentGroupId === id` ⇒ `'Mục không thể là mục cha của chính nó'`; `loadParent`;
    `assertNoCycle(id, parentGroupId, actor)` ⇒ `'Không thể chọn mục con làm mục cha'`; loại hiệu lực =
    `payload.direction ?? existing.direction`, so với cha; nếu `payload.direction` khác `existing.direction` và
    `hasChildren(id)` ⇒ `'Không thể đổi loại của mục đang có mục con'`.
  - `beforeDelete`: `hasChildren(id)` (đếm dòng `parentGroupId = id`, chưa xoá mềm, cùng org) ⇒
    `'Không thể xóa mục đang có mục con'` (A-04).
  - Thông điệp đúng chuỗi ở bảng Error taxonomy của `03-logical-design.md` (T-01-04 và demo dựa vào chúng).
- `CASH_VOUCHER_CATEGORY_ENTITY_CONFIG`: chèn `{ key: 'parentGroupId', label: 'Mục cha', type: 'relation',
  relationEntity: 'cash-voucher-categories', hideInList: true }` sau `direction`; thêm
  `enumLabels: { IN: 'Thu', OUT: 'Chi' }` vào `direction`. Không đổi permissions/scoping/deletion.
- Spec theo khuôn `item-category-crud.service.spec.ts` (repo mock qua `getRepositoryToken`, `DataSource` mock):
  cha khác org, cha đã xoá mềm, tự làm cha, vòng 2 tầng và 3 tầng, cha khác loại (create và update), đổi loại khi có
  con, xoá khi có con, xoá lá thành công, `''`→`null` đưa lên gốc.
