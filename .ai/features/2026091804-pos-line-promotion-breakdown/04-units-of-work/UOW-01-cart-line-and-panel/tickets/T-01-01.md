# T-01-01 — Trục dùng chung: dòng ↔ CTKM

## Context
ADR-01: một hàm thuần trả lời "dòng này được CTKM nào giảm bao nhiêu, thuộc nhóm
item hay invoice" cho cả preview (lineId client) lẫn snapshot (invoice_items.id).
Mọi ticket sau chỉ gọi hàm này.

## Implementation notes
- `linePromotionIndex.ts` (mới):
  - `type LinePromotion = { programId; code; name; type; discountAmount; unitPriceAfter; bucket: "item" | "invoice" }`
  - `ITEM_BUCKET_TYPES = new Set([ITEM_DISCOUNT, TIERED_DISCOUNT, BUY_M_GET_N])` — chỗ **duy nhất** giữ danh sách (A-02); `GIFT_ITEM` bỏ
  - `buildLinePromotionIndex(programs: AppliedProgramLike[], knownLineIds?: Set<string>) → { byLine: Map<string, LinePromotion[]>, totals: { item: number; invoice: number } }`
    - `totals` cộng theo `program.discountAmount` (không cộng lại từ lineDiscounts) để khớp `promotionDiscount` server
    - id không nằm trong `knownLineIds` (nếu truyền) → bỏ khỏi `byLine`, vẫn vào `totals`, `console.warn` một lần theo `programId:lineId`
  - `AppliedProgramLike` = `Pick<AppliedProgram, "programId" | "code" | "name" | "type" | "discountAmount" | "lineDiscounts">`
  - `formatPromotionLabel(p: LinePromotion) = \`${p.name} (${formatVnd(p.discountAmount)})\``
- `promotion.interface.ts`: re-export `LinePromotion` nếu cần cho component; không đổi `PromotionItem`
- `checkout-session.store.ts`: `selectLinePromotionIndex(state)` (preview `ready` → index với `knownLineIds` = purchaseCart lineIds; khác → index rỗng) và `selectPromotionBucketTotals(state)`; giữ `selectPromotionDiscountAmount` nguyên (ADR-03)
