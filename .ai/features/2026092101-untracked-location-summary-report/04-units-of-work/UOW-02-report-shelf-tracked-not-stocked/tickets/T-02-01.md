# T-02-01 — Drop the `quantity > 0` predicate from the resolver's stocked-shelf query

## Context

`resolveWithinStorages` (`item-warehouse-location.util.ts:151`) unions the item's preferred
shelves with the shelves from `stock_balances`, and the balance query keeps only rows with
`sb.quantity > 0` (`:211`). A pair that is "Đang theo dõi" at quantity 0 — the shape both
"arrange" and a sold-out shelf produce — therefore vanishes from all four report location
columns. ADR-02 in `03-logical-design.md`: tracked-ness, not quantity, defines a reported shelf.
Do not implement before A-01 is resolved (`aidlc status` shows it).

## Implementation notes

- Remove the single line `.andWhere('sb.quantity > 0')` (`:211`). Leave `isTracked = true`,
  `loc.isActive = true`, `loc.storageId IN` and the `itemId IN` / `organizationId` predicates as
  they are. Query count stays at four (A-11 case in the spec must still pass).
- Rewrite the two comments that state the old rule so the file does not lie:
  - `:43-46`: "2. any shelf there still holding stock (`stock_balances.quantity > 0`)" → "2. any
    shelf there whose pair is still tracked (`stock_balances.is_tracked = true`), at any
    quantity — a shelf that just sold out is still where the item lives"; drop the "These are a
    union, not a priority order — an item whose preferred shelf is empty but has real stock
    elsewhere reports both" sentence's reliance on "real stock" (keep the union point).
  - `:187-189`: "The stocked-shelf query below already filters `isTracked = true`" — still true;
    just stop calling it "stocked-shelf" (e.g. "tracked-shelf query").
- Spec (`item-warehouse-location.util.spec.ts`):
  - Add `quantity: number` to `BalanceRow` (`:28-31`) and set it on every existing fixture
    (they all model shelves with stock — give them `1`).
  - In the `createQueryBuilder` mock (`:96-125`), record whether an `andWhere` was called with a
    SQL string containing `quantity > 0`; in `getRawMany`, when it was, additionally filter
    `b.quantity > 0`. This makes the mock honour the predicate the code applies, so the new case
    below is red on `main` and green after the one-line removal.
  - New case, `it('reports a tracked shelf at quantity 0 that is not the preferred shelf (AC-06/AC-08)')`:
    item with no `preferred` row, one `balances` row `{ quantity: 0 }` at `loc-a101` → expect
    `code: 'A101'`, `storage: 'Kho A1'`.
  - Extend the existing AC-04 case (`:327`) or add a sibling: both balances at `quantity: 0`, one
    listed in `untracked` → only the other code is returned (AC-07).
  - Existing A-11 case (`:310`, "exactly four repository queries") must pass unchanged.
