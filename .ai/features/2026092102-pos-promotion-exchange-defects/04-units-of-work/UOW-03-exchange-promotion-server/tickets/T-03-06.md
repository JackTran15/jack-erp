# T-03-06 — Dry-run của `checkout-return`

## Context
ADR-03/05: FE lấy chiều tiền và trần thanh toán từ BE trước khi post, và số đó
phải đến từ **đúng** code path của `checkout()` — không phải một bản tính lại.
Sau T-03-02, phần đầu của `checkout()` (load draft, validate items/location,
load HĐ gốc, evaluate dòng OUT, `computeTotals`) là thứ cần tách ra.

## Implementation notes
- `CheckoutReturnService`: tách `private async prepare(id, ids: { selectedProgramIds?;
  excludedProgramIds? }, actor)` trả `{ invoice, items, outItems, originalInvoice,
  originalItems, evaluation, totals }`. `checkout()` gọi `prepare()` rồi tiếp tục
  từ `effectiveRefundMethod`/`validateRefundMatrix` như cũ — **không** đổi thứ tự
  hay thông điệp lỗi nào. `preview(id, dto, actor)` = `prepare()` → trả `totals`
  (7 field của `ComputedTotals`, đã `round`).
- `checkout-return-preview.dto.ts`: `CheckoutReturnPreviewDto { selectedProgramIds?;
  excludedProgramIds? }` (decorator như `checkout-v2.dto.ts:101–117`) và
  `CheckoutReturnPreviewResponseDto` với 7 `@ApiProperty({ type: Number })`.
- Controller: `@Post(':id/checkout-return/preview') @RequirePermission('pos.return.create')
  @HttpCode(200) @ApiOkResponse({ type: CheckoutReturnPreviewResponseDto })` — đặt
  **trước** `@Post(':id/checkout-return')` trong file cho dễ đọc (Nest route theo
  path đầy đủ nên thứ tự không ảnh hưởng). Branch scope đã có ở cấp class.
- `IdempotencyInterceptor` áp cho mọi mutation: preview là POST chỉ đọc, cùng
  key + cùng body → replay cùng số, khác body → 409 như mọi POST — chấp nhận,
  `/v2/promotions/evaluate` đang cùng tư thế. Ghi một dòng comment trên handler.
- Spec: `preview()` với mock `QueryBus` trả 60.000 → 7 số đúng AC-28; **không**
  gọi `dataSource.transaction`, không `numbering`, không publisher nào; gọi hai
  lần cùng input → cùng kết quả.
