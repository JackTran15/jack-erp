# T-04-03 — Số gửi đi là số BE

## Context
`use-checkout-actions.ts:365–398` (nhánh `isReturnFlow`): tính
`returnSubtotal`/`newSubtotal` bằng `payloadLineSubtotal` (gross − giảm tay) rồi
dựng payload — sau T-04-02 là `netAmount: newSubtotal − returnSubtotal`. BE:
`netAmount = newNet − returnedNet` (T-03-02) và có dry-run (T-03-06).
`promotionDraft.selectedProgramIds/excludedProgramIds` đã được đọc cho luồng bán
(`:322–325`). Akenzy chốt thu ngân vẫn thanh toán được khi preview POS hỏng
(A-09 rejected → ADR-05).

## Implementation notes
- Sau khi tạo phiếu (`createExchangeMutation`/`createReturnMutation` → `invoiceId`):
  ```
  const ids = { ...(selected.length ? { selectedProgramIds: selected } : {}),
                ...(excluded.length ? { excludedProgramIds: excluded } : {}) };
  let preview;
  try { preview = await previewMutation.mutateAsync({ id: invoiceId, body: ids }); }
  catch { toast.error(CHECKOUT_TOASTS.RETURN_PREVIEW_FAILED); /* dọn draft như nhánh lỗi hiện có */ return; }
  ```
- Xóa hai `reduce` `returnSubtotal`/`newSubtotal` (`:369–377`) và comment cũ; dựng
  payload bằng `buildCheckoutReturnPayload({ netAmount: preview.netAmount,
  paymentLines: cappedLines, ...ids, putOnDebt, dueDate, creditDays, note })`.
- Kẹp `payments`: khi `preview.netAmount > 0`, tổng `paymentLines[].amount` gửi đi
  ≤ `preview.netAmount` — dùng cùng cách `buildCheckoutInvoiceApiPayload` kẹp theo
  `amountDue` ở luồng bán (`:312–317`): `amountDue = Math.min(settlementAbs,
  preview.netAmount)`. Khi `preview.netAmount ≤ 0` không gửi `payments` (mapper đã
  lo). Không đổi `deriveSettlement`/panel.
- `receiptPayload`: giữ như hôm nay (in từ state POS + `posted.code/points`).
  Nếu `preview.netAmount` khác số panel (preview POS hỏng), **không** chặn — ghi
  `console.warn` một dòng để QA thấy trong console (ADR-05).
- `checkout-messages.constant.ts`: `RETURN_PREVIEW_FAILED: "Không lấy được số
  tiền đổi trả từ máy chủ — vui lòng thử lại."`.
- Sửa comment `:320–325` (ids không còn "chỉ luồng SALE").
