# T-01-03 — Access policy and owner on write

## Context
ADR-03, ADR-04, ADR-06. The access table in `03-logical-design.md` is the spec for the
policy — implement it cell for cell.

## Implementation notes
- `PromotionAccessPolicy` (`@Injectable`, provided in `promotion.module.ts`; `RbacService` is
  `@Global`): `forActor(actor)` resolves `isChainManager` once via
  `rbac.hasPermission(actor.userId, actor.organizationId, 'promotion.chain.manage')`.
  Methods: `canRead(program)`, `assertReadable(program)` (404, same text as a missing row),
  `assertManageable(program)` (404 if unreadable, else 403 `PROGRAM_NOT_MANAGEABLE`),
  `ownerForNew()` (chain → undefined; else `actor.branchId` or 403 `NO_ACTIVE_BRANCH`).
- Create: `ownerBranchId = ownerForNew()`; when set, `branchIds = [owner]` regardless of the DTO.
- Update: `assertManageable(existing)`; keep `existing.ownerBranchId`; when set, force `branchIds`.
- Duplicate: `assertReadable(source)`; the copy follows the create rule (A-12).

## Done when
- [x] Policy spec covers every cell of the access table, including no-active-branch
- [x] Create spec: branch manager submitting `branchIds: [HN]` gets owner HCM, scope [HCM]; chain manager gets owner undefined, scope as submitted
- [x] Update spec: chain program by branch manager → 403; other-branch program → 404; own program keeps owner + forced scope
- [x] Duplicate spec: branch-manager copy of a chain program is HCM-owned
