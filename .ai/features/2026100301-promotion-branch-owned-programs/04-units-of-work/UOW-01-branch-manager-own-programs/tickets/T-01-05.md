# T-01-05 — Read side: get-by-id, list scope, owner fields

## Context
`GetPromotionHandler` calls `assertReadable` right after `findById` (visible chain → 200,
other branch / unapplicable chain → 404).

Today `search-promotions-v2.handler.ts:64` filters every actor with an active branch to
programs *applicable* to it. For a branch manager the rule becomes
`owner = B OR (owner IS NULL AND applicable to B)`; with no active branch → 403
`NO_ACTIVE_BRANCH`. The chain-manager side (whole org + owner filter) is T-02-01 — leave the
existing behaviour for chain managers untouched in this ticket.

## Implementation notes
- Get the scope from `PromotionAccessPolicy` (add `searchScope()` returning
  `{ kind: 'branch', branchId }` or `{ kind: 'chain' }`) so the rule lives in one place.
- Summary: `LEFT JOIN branches b ON b.id = p.owner_branch_id` → `ownerBranchId`, `ownerBranchName`
  (`toSummary` takes the joined name). Detail: same two fields; `GetPromotionHandler` looks up
  the branch name with `organizationId` in the where clause.
- `PromotionProgramSummary` / `PromotionProgramDetail`: `ownerBranchId: string | null`,
  `ownerBranchName: string | null`; rebuild `@erp/shared-interfaces`.
