# T-02-03 — Mở rộng AuthGuard

## Context
ADR-01 (03-logical-design.md): một guard duy nhất xử lý cả hai credential. Thứ tự ưu
tiên: Bearer trước (không đổi code cũ), rồi mới tới `X-Api-Key`.

## Implementation notes
- Sau nhánh `authHeader?.startsWith('Bearer ')` hiện có (giữ nguyên, không sửa), thêm
  nhánh đọc header `X-Api-Key` khi không có Bearer.
- Gọi `ApiKeyAuthService.validate(key, request.ip)`; map `kind` sang exception:
  `not_found` → `UnauthorizedException`, `ip_denied` → `ForbiddenException`, `ok` → set
  `request.user`. (`branch_denied` đã bỏ khỏi service từ T-02-02 — xem dưới.)
- `request.user` cho nhánh API key: `{ userId: 'api-key:' + actor.apiKeyId,
  organizationId, roles, branchIds }` — không set `branchId` (không có "chi nhánh đang
  chọn" cho API key, chỉ có `X-Branch-Id` mỗi request); `Actor()` tự suy ra `branchId` từ
  `branchIds` + header, không cần sửa `actor-context.decorator.ts`.
- Không có `X-Api-Key` lẫn không có `Bearer` → 401 y hệt hôm nay.

**Sửa lại `ApiKeyAuthService` (T-02-02) so với bản đã accept**: chuyển việc resolve
`branchIds` cho key không giới hạn (A-08) từ "để guard tự tra" sang "resolve ngay trong
`lookup()`" — tức quay lại đúng thiết kế gốc ở 03-logical-design.md (`branchIds` luôn là
danh sách đầy đủ, không còn `undefined`). Lý do: nếu để guard tự query danh sách chi nhánh
mỗi request, phần đó nằm NGOÀI biên cache mà T-03-01 sắp bọc quanh `lookup()` — quay lại
thiết kế gốc thì việc "không spam backend" áp dụng luôn cho query chi nhánh, không chỉ
query key. Thêm `TypeOrmModule.forFeature([BranchEntity])` vào `api-key.module.ts` (import
thẳng entity, không import `BranchModule` để tránh kéo theo chuỗi phụ thuộc không liên
quan).

**Bug thật phát hiện khi live-test (không phải chỉ chạy unit test)**: `main.ts` gọi
`configService.get<number>('TRUST_PROXY_HOPS', 1)` — nhưng `ConfigService.get()` trả về
đúng kiểu dữ liệu dotenv nạp, tức STRING, mỗi khi giá trị đến từ một file env (kể cả
default "last-resort" từ `.env.example`). Express xử lý `trust proxy` là STRING hoàn toàn
khác NUMBER (string bị hiểu như danh sách subnet tin cậy, không phải "tin N hop") — kết
quả: `X-Forwarded-For` bị lờ đi hoàn toàn, mọi request qua API key đều nhận 403 sai
("IP not whitelisted") bất kể IP thật có đúng whitelist hay không. Test unit ban đầu
(`main-trust-proxy.spec.ts`) không bắt được vì gọi `app.set('trust proxy', 1)` bằng số
literal, không đi qua `ConfigService` thật. Fix: bọc `Number(...)`. Thêm 2 test mới pin
lại đúng lỗi này (string phá vỡ trust, `Number()` phục hồi).
