# T-02-04 — Test AuthGuard mở rộng

## Context
Bao toàn bộ US-01/US-02/US-03 trừ phần cache (UOW-03). Bắt buộc có test regression cho
nhánh JWT — đây là guard toàn cục, sai một dòng là hỏng mọi endpoint trong hệ thống. Viết
ở giai đoạn sau G2 reopen (ADR-04): key được gán role thật (`SEEDED_ROLE_ID` từ
`seedBaseData()`), nên AC-01 kiểm được đúng nghĩa đen "giống hệt JWT" — so sánh trực tiếp
response body của cùng một request qua API key và qua JWT.

## Implementation notes
- `createTestApp()` (`setup/test-app.ts`, dùng chung mọi spec) cần `app.set('trust proxy',
  1)` để `X-Forwarded-For` có tác dụng trong test — thêm vào đây thay vì mock `request.ip`
  trực tiếp; phải đổi `createNestApplication()` sang generic `<NestExpressApplication>`
  (TS không thấy `.set()` trên `INestApplication` trần).
- AC-01: tạo key với `roles: [SEEDED_ROLE_ID]` (role đầy đủ quyền của `seedBaseData()`),
  gọi cùng một endpoint (`GET /admin/entities/customers/records`) qua API key và qua JWT,
  assert `response.body` giống hệt nhau — chứng minh guard tạo `request.user` đủ để
  downstream (PermissionGuard, CrudPermissionGuard, scoping) hoạt động không sai khác.
- AC-09: tạo tổ chức thứ 2 hoàn chỉnh (org/branch/user/role/permission) bằng raw SQL giống
  hệt `seedBaseData()`, key riêng, rồi assert danh sách api-keys của org A không bao giờ
  chứa key org B và ngược lại.
