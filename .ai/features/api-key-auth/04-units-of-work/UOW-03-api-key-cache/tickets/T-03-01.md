# T-03-01 — Cache hoá lookup key

## Context
ADR-02 (03-logical-design.md): cache **bản ghi key** (bao gồm `ipWhitelist`, `roles`,
`branchIds`), không cache verdict theo từng IP. IP/branch check vẫn chạy in-process mỗi
request, chỉ khác là không còn query DB khi cache hit.

## Implementation notes
- `CacheService.getOrSet(API_KEY_CACHE_NAMESPACE, keyHash, () => fetchRecord(keyHash),
  config.get('API_KEY_CACHE_TTL_SECONDS', 60))` bọc quanh `fetchRecord()` (phần lookup DB
  + resolve `branchIds`, gộp từ T-02-03) — IP check vẫn chạy in-process sau khi có bản ghi
  (từ cache hoặc DB), không nằm trong phần cache.
- **Điều chỉnh so với draft ban đầu**: A-07 nói "không cache not_found", nhưng
  `CacheService.getOrSet` vốn cache mọi giá trị `fetchFn()` trả về kể cả `null` — và việc
  đó hoá ra ĐÚNG với mục tiêu "không spam backend": key sai bị dò liên tục cũng không nên
  tốn query DB mỗi lần. Giữ nguyên hành vi cache-cả-null của `CacheService`, không viết
  thêm code để loại trừ riêng not_found.
- `API_KEY_CACHE_NAMESPACE` chuyển thành 1 nguồn duy nhất (export từ
  `api-key-auth.service.ts`), `api-key-crud.service.ts` import lại thay vì tự khai báo
  hằng số trùng tên — tránh hai chỗ có thể lệch nhau.
