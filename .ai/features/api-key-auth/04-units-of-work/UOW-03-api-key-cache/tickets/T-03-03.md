# T-03-03 — Test cache

## Context
Đóng US-06 và phần "trong TTL" của AC-07 (revoke).

## Implementation notes
- Test ở tầng service (`app.get(ApiKeyAuthService)` + `app.get(getRepositoryToken(ApiKeyEntity))`
  từ e2e app thật), không chỉ qua HTTP status — cách duy nhất đo được "có gọi DB hay
  không" chính xác là spy trực tiếp trên `repository.findOne`.
- AC-11: `jest.spyOn(apiKeyRepo, 'findOne')`, gọi `validate()` 2 lần liên tiếp cùng key,
  assert spy chỉ được gọi đúng 1 lần.
- AC-07/AC-12 (revoke): nạp cache bằng 1 lần `validate()`, revoke qua API admin thật
  (DELETE), gọi lại `validate()` ngay — phải `not_found`, không đợi hết TTL 60s.
- AC-12 (sửa whitelist): nạp cache, PATCH `ipWhitelist` sang IP khác qua API admin thật, gọi
  lại `validate()` với IP CŨ → phải `ip_denied` ngay (chứng minh cache bị bust chứ không
  phải chỉ do IP thật sự đổi); gọi với IP MỚI → phải `ok`.
- Dùng chung `seedBaseData()` + cấp quyền `api-key.*` như 2 file e2e trước (cùng
  `SEEDED_ROLE_ID`/pattern `grantApiKeyPermissions` + `RbacService.invalidateUserPermissions`
  để tránh cache RBAC cũ che quyền mới cấp).

**Bug thật (lỗi của chính ticket này, phát hiện khi chạy thật)**: `grantApiKeyPermissions`
ban đầu quên cấp `api-key.update` (chỉ có read/create/delete) — test PATCH ipWhitelist
nhận 403 thay vì 200. Sửa: thêm `api-key.update` vào danh sách cấp quyền.
