# T-01-01 — Add AuthErrorCode enum to shared-interfaces

## Context
`packages/shared-interfaces/src/auth/index.ts` is the existing shared home for auth-domain
types crossing the `apps/api` / `apps/backoffice-web` / `apps/pos-web` boundary
(`JwtPayload`, `LoginRequest`, `LoginResponse`, `RefreshRequest`, `RefreshResponse`,
`SwitchBranchRequest/Response`, `CreateHandoffRequest/Response`,
`ExchangeHandoffRequest/Response`, `SessionInfo` — confirmed by reading the file, no other
error-code type exists there today). Per `03-logical-design.md` ADR-01, this is where
`AuthErrorCode` belongs. Resolves the numbering question left open in A-02 — these are the
final values for this pass, not illustrative.

## Implementation notes
- Add, without touching any existing export in the file:
  ```ts
  export enum AuthErrorCode {
    TOKEN_MALFORMED = '4014001',
    SESSION_REVOKED = '4014002',
    TOKEN_EXPIRED = '4014003',
    REFRESH_TOKEN_INVALID = '4014004',
  }
  ```
- After adding, run `pnpm --filter @erp/shared-interfaces build` (this package is one of the
  three built by the workspace `postinstall`/`build:shared` step — see root `CLAUDE.md`) so
  `apps/api` and both frontends pick up the new export locally without a full `pnpm install`.

## Done when
- [x] `AuthErrorCode` is exported from `packages/shared-interfaces/src/auth/index.ts` with
      exactly the 4 members and string values above
- [x] No pre-existing export in the file is modified or reordered
- [x] `pnpm --filter @erp/shared-interfaces build` succeeds
