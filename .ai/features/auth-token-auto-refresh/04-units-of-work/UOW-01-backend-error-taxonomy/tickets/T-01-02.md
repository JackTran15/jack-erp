# T-01-02 — AuthGuard branches on JWT failure subtype and session revocation

## Context
`AuthGuard.canActivate` (`apps/api/src/common/guards/auth.guard.ts:28-62`) has one
`try/catch` around `jwt.verify()` (lines 46-51) that throws a single generic
`UnauthorizedException('Invalid or expired token')` for every verify failure, and one Redis
liveness check (lines 53-57) that throws `UnauthorizedException('Session revoked or
expired')`. `jsonwebtoken` throws distinct classes: `TokenExpiredError` for an expired `exp`
claim, `JsonWebTokenError` for malformed/invalid-signature tokens, `NotBeforeError` for
tokens used before their `nbf`. Per `03-logical-design.md` Approach/Contracts, this ticket
adds a code-carrying exception class and branches the guard on failure subtype.

No `HttpException` subclass exists anywhere else in `apps/api/src` today (confirmed by
search) — `AuthException` is a new, minimal pattern, not a reuse of an existing one.

## Implementation notes
- New file `apps/api/src/common/exceptions/auth.exception.ts`:
  ```ts
  import { UnauthorizedException } from '@nestjs/common';
  import { AuthErrorCode } from '@erp/shared-interfaces';

  export class AuthException extends UnauthorizedException {
    public readonly code: AuthErrorCode;

    constructor(code: AuthErrorCode, message: string) {
      super(message);
      this.code = code;
    }
  }
  ```
- In `auth.guard.ts`'s catch block (currently lines 48-51), replace the single throw with a
  branch on `err`'s constructor:
  - `err instanceof jwt.TokenExpiredError` → `throw new AuthException(AuthErrorCode.TOKEN_EXPIRED, 'Invalid or expired token')`
  - anything else from that catch (`JsonWebTokenError`, `NotBeforeError`) →
    `throw new AuthException(AuthErrorCode.TOKEN_MALFORMED, 'Invalid or expired token')`
  - Keep the existing `this.logger.debug(...)` line as-is; only the thrown exception changes.
- In the Redis check (currently lines 53-57), replace the throw with
  `throw new AuthException(AuthErrorCode.SESSION_REVOKED, 'Session revoked or expired')`.
  Keep the existing debug log line.
- The missing-`Authorization`-header throw (lines 39-41) is untouched — no AC in
  `02-requirements.md` covers it, and `03-logical-design.md`'s error taxonomy table has no
  row for it.
- Import `AuthErrorCode` from `@erp/shared-interfaces` (already a dependency of `apps/api`).
