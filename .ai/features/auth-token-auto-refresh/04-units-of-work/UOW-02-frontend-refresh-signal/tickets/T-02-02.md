# T-02-02 — pos-web interceptor names the TOKEN_EXPIRED trigger

## Context
`apps/pos-web/src/lib/common/api-axios.ts:44-114` is pos-web's own, separate 401→refresh→retry
interceptor (different guard variable name, `_retry`, and its own `refreshOnce()` single-flight
helper — not shared code with backoffice-web's). Same change as T-02-01, applied to this
app's implementation independently; the two files must not be assumed identical.

## Implementation notes
- Import `AuthErrorCode` from `@erp/shared-interfaces`.
- Inside the response-error handler, after the existing `error.response?.status === 401 &&
  originalRequest && !originalRequest._retry` guard (lines 92-96, unchanged), read the code
  for the same debuggability purpose as T-02-01:
  ```ts
  const authErrorCode = error.response?.data?.code as AuthErrorCode | undefined;
  if (authErrorCode === AuthErrorCode.TOKEN_EXPIRED) {
    // access token expired — refreshOnce() below runs exactly as today
  }
  // else: no code, or a code not special-cased yet — still falls through to the same
  // refreshOnce() call below (AC-05 regression guard, non-negotiable)
  ```
- Do not change the `_retry` guard, `refreshOnce()`/`refreshPromise` single-flight logic, or
  the terminal `localStorage` clear + redirect to `dang-nhap` — none of those lines move.
