# T-01-01 — Migration bảng saga + bảng step

## Context
Nền của toàn epic. Schema đã chốt ở `03-logical-design.md` mục "Schema mới". Migration viết tay,
`synchronize: false`, `migrationsTransactionMode: 'each'` — nên enum phải tạo ở lệnh riêng trước khi
dùng (xem `1787500000002-AddDepositDebtCollectionSaga.ts` làm mẫu, kể cả khối `DO $$ ... EXCEPTION
WHEN duplicate_object`).

## Implementation notes
- Enum `checkout_saga_status_enum`: `PENDING | COMPLETED | COMPENSATED | FAILED`. Giữ đủ 4 giá trị
  cho khớp house pattern dù epic này chưa dùng `COMPENSATED`.
- `checkout_saga`: cột theo đúng bảng trong logical design. `organization_id`/`branch_id` là
  `character varying` cho khớp các bảng nghiệp vụ hiện có, **không** phải uuid.
- Index bắt buộc:
  - `CREATE UNIQUE INDEX ... ON checkout_saga (organization_id, idempotency_key) WHERE status <> 'FAILED'`
    — partial, đây là điểm mấu chốt của ADR-05 và A-13.
  - `(organization_id, status)` và `(invoice_id)`.
- `checkout_saga_step`: unique `(saga_id, seq)`, index `(saga_id)`, FK `saga_id` → `checkout_saga(id)`
  ON DELETE CASCADE.
- `down()` xoá index → bảng → enum, theo thứ tự ngược.
