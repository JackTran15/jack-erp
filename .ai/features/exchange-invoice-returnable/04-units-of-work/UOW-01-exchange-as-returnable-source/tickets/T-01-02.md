# T-01-02 — getEligibleLines nhận hoá đơn EXCHANGE và chỉ chào dòng OUT

## Context

`return-eligibility.service.ts:116` ném 400 với bất kỳ hoá đơn nào không phải `SALE`, và
`getEligibleLines` map **mọi** dòng của hoá đơn ra danh sách trả được. Với hoá đơn `SALE`
điều đó vô hại — mọi dòng đều `direction = OUT`. Với hoá đơn `EXCHANGE` thì không: nửa số
dòng là hàng khách **đã trả về**, chào chúng ra là mời xuất kho khống và chi tiền khống.

Thứ tự hai thao tác (tính giá hoàn, lọc dòng) là điểm dễ sai nhất của ticket này —
xem ADR-02.

## Implementation notes

- Nới điều kiện `type`: nhận `SALE` và `EXCHANGE`; `RETURN` vẫn 400. Thông báo lỗi
  tiếng Anh, sửa cho khớp: `only SALE/EXCHANGE can be returned`.
- `RETURNABLE_STATUSES` giữ nguyên — hoá đơn `EXCHANGE` post xong nhận `PAID`, hoặc
  `DEBT`/`PARTIAL_DEBT` khi net > 0 ghi nợ (`checkout-return.service.ts:326-331`).
- **Thứ tự bắt buộc** (ADR-02):

  ```ts
  const items = await this.itemRepo.find({ where: { invoiceId: originalInvoiceId }, order: { sortOrder: 'ASC' } });
  // Full item set — the same input CheckoutReturnService.computeReturnedNet reads
  // from the original invoice. Filtering before this call would let the preview
  // and the posted charge drift apart.
  const refundable = refundableUnitValues(invoice, items);
  const returnable = items.filter((it) => it.direction === ItemDirection.OUT);
  return returnable.map(...)
  ```

  Tính `refundableUnitValues` trên **toàn bộ** dòng, lọc **kết quả** — không lọc đầu vào.
- Lọc `direction = OUT` **không điều kiện**, không rẽ theo `invoice.type` (ADR-04). Dòng
  `SALE` toàn bộ là `OUT` (ghi tường minh ở `persist-invoice.step.ts:226`, DB default
  `OUT` ở `invoice-item.entity.ts:74`), nên hoá đơn bán không đổi hành vi.
- Cần import `ItemDirection` từ `../entities/invoice-item.entity`.
- Không đụng `refundable-value.util.ts` (A-15).
