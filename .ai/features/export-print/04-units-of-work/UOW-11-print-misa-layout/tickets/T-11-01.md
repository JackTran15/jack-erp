# T-11-01 — renderVoucherHtml theo đúng bố cục mẫu in

## Context

Bốn mẫu `.pdf` đã giải mã cho thấy bản in MISA trùng khít bố cục Excel, chỉ bỏ các cột đang ẩn —
đúng nguyên tắc ADR-01. Khuôn HTML hiện tại lệch ở 9 điểm (`03-logical-design.md` §"House style" →
"Bản in").

Vẫn là **một khuôn cho mọi loại chứng từ** (ADR-05) — không thêm nhánh theo `kind`.

## Implementation notes

- `font-family: "Times New Roman", Times, serif`
- Khối chi nhánh: `text-align: left` (đang center); tên bold; bỏ tiền tố `SĐT: ` cho khớp Excel
- Thay dòng `Số: X — Ngày: Y` bằng **hai** dòng căn giữa:
  `Ngày ${docDate}` rồi `Số: ${docNo}` — `docDate` đã là dạng dài từ T-10-03, renderer chỉ thêm
  chữ "Ngày", không format lại
- Khối info: bỏ `display:flex` + `flex: 1 1 45%`, chuyển sang các dòng full width căn trái, nhãn bold
- `th { background: transparent }` — bỏ `#f0f0f0`
- Dòng tổng: đặt `payload.totalsLabel ?? 'Tổng'` vào ô đầu tiên (colspan qua các cột chuỗi đầu bảng)
- `Số tiền bằng chữ:` → **`Số tiền viết bằng chữ:`**
- Thêm dòng `Ngày.......tháng.......năm............` italic **căn phải**, ngay trên khối ký
- Khối ký rải đều `signatures` (nay 5 phần tử từ T-10-04) — CSS không hardcode số cột
- Giữ `@page { size: ${paper}; margin: 10mm }`, giữ `thead { display: table-header-group }` và
  `tr { break-inside: avoid }` — chúng là thứ làm bảng nhiều trang in đúng

không có `vitest` trong `devDependencies` (pos-web cũng vậy). Nghĩa là `render-voucher-html.test.ts`
— viết từ T-02-01 — **chưa từng chạy lần nào**; `pnpm --filter @erp/backoffice-web test` xanh chỉ vì
nó echo.

này là phá ràng buộc đã duyệt. Cách đã làm thay thế:

   assertion của file test bằng một driver ở scratchpad → **16 passed, 0 failed**;

File `.test.ts` vẫn được cập nhật và giữ lại: khi nào repo thêm runner, nó chạy được ngay. Việc
"backoffice-web/pos-web thiếu runner" là nợ đã biết, nằm ngoài phạm vi feature này.
