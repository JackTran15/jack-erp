# T-13-01 — Mở Content-Disposition qua CORS

## Context

Mọi file tải về từ backoffice đang mang tên dự phòng: chứng từ là `chung-tu.xlsx`, báo cáo là
`bao-cao.xlsx`. Tên do server đặt (`imp000011.xlsx`, `doanh-thu-theo-mat-hang.xlsx`) **không bao giờ
tới được JavaScript**.

Nguyên nhân: `Content-Disposition` không thuộc nhóm header an toàn của CORS, và
`main.ts:42` chỉ expose `['X-Request-Id', 'X-Total-Count']`. Backoffice chạy ở `:3000`, API ở
`:4000` (`api-base.ts` mặc định `http://localhost:4000`, không có proxy trong `vite.config.ts`) —
khác origin, nên trình duyệt giấu header đó khỏi `response.headers`.

Điều này **không thấy được bằng curl**: curl đọc mọi header. Đó là lý do các lần kiểm trước đây
"200 + đúng filename" vẫn đúng ở tầng server mà vẫn không phản ánh cái người dùng nhìn thấy.

## Implementation notes

- Thêm `'Content-Disposition'` vào `exposedHeaders`
- Chỉ vậy; không đổi `origin`/`credentials`
- Header chỉ chứa tên file đã qua `toFileSlug` — không rò rỉ gì

## Done when

- [x] `exposedHeaders` có `Content-Disposition`
- [x] Kiểm **trong trình duyệt thật**, trang ở `http://localhost:8899` gọi API ở
      `http://localhost:4000` (khác origin): `res.headers.get('content-disposition')` trả
      `attachment; filename="phieu-nhap-kho.xlsx"` — trước khi sửa là `null`
- [x] Báo cáo: cùng cách kiểm, `POST /reports/invoices/export` trả
      `attachment; filename="doanh-thu-theo-mat-hang.xlsx"` thay vì rơi về `bao-cao.xlsx`

## Notes

Lỗi này **không thể thấy bằng curl** — curl đọc mọi header, chỉ trình duyệt mới áp luật CORS. Mọi
lần kiểm trước của feature này đều dùng curl nên đều báo "đúng filename" trong khi thứ người dùng
tải về vẫn là `chung-tu.xlsx`. Bài học đã ghi vào Demo script của UOW-13: bước xác nhận tên file
phải chạy trong trình duyệt.
