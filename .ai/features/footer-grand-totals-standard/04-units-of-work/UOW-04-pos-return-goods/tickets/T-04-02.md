# T-04-02 — Đổi trả hàng: phân trang thật + footer từ API

## Context
`use-return-goods.ts:100-101` ghim `page: 1, limit: RETURN_GOODS_DEFAULT_PAGE_SIZE`; hook không có
state trang; `ReturnGoodsPage.tsx:78-83` render `<PosPaginationBar page={1} totalPages={1} />` không
handler nên nút bị khoá. Hệ quả: chi nhánh có hơn 100 đơn đủ điều kiện thì phần còn lại không bao
giờ xem được.

`PosPaginationBar` đã có sẵn `onPageChange`/`onPageSizeChange` (`:5-17`). Tiền lệ đặt state:
`use-invoice-list.ts` (state trong hook, `totalPages` tính từ `total`, reset trang ở mọi setter).

## Implementation notes
- Thêm `page`/`pageSize` state vào hook; `searchBody` gửi chúng và nhận chúng làm dep.
- **Reset trang về 1 ở mọi setter nuôi truy vấn** — gồm cả `setDateRange`, hiện đang trả thẳng setter
  thô ra ngoài nên dễ bị bỏ sót.
- Expose `pageSize`, `totalPages`, `setPage`, `setPageSize`, `refetch`, và `grandTotal` lấy từ
  `totals.totalAmount`.
- `ReturnInvoiceTable` nhận `grandTotal` qua prop; xoá `sumInvoiceTotals` và import của nó; xoá hàm
  trong `returnGoodsMath.ts` nếu thành mồ côi.
- Dialog chọn hàng trả giữ `activeInvoice` là object đã bắt và selection keyed theo id dòng hàng nên
  lật trang không làm hỏng lựa chọn — không cần đụng.
- `@Max(100)` ở DTO: không thêm option 200 vào `pageSizeOptions`.
