# T-01-02 — Gate "Đặt hàng" checkbox in PrintAndOrderRow

## Context

Depends on T-01-01's constant. `PrintAndOrderRow.tsx:51-60` already hides the "Đặt hàng"
checkbox on the return/exchange tab via `isReturnExchange ? null : (...)` — that existing
gate must keep working unchanged (AC-04 is a regression check on it, not a new rule this
ticket introduces). This ticket adds a second, independent condition: hide the checkbox
whenever `SHOW_DEPOSIT_ORDER_CONTROLS` is `false`, regardless of tab.

## Implementation notes

- Import `SHOW_DEPOSIT_ORDER_CONTROLS` from
  `@erp/pos/constants/feature-flags.constant` (same file T-01-01 created).
- Combine the two conditions rather than nesting/duplicating the ternary, e.g.:
  ```tsx
  {isReturnExchange || !SHOW_DEPOSIT_ORDER_CONTROLS ? null : (
    <label className="inline-flex cursor-pointer items-center gap-2">
      <PosCheckbox
        checked={preorder}
        onChange={setPreorder}
        ariaLabel="Đặt hàng"
      />
      Đặt hàng
    </label>
  )}
  ```
- Do not touch the "In hóa đơn" toggle or "In 2 liên" checkbox in this same component — only
  the "Đặt hàng" block is in scope.
- Do not touch `useCheckoutPayment` or the `preorder`/`setPreorder` state itself — the field
  stays exactly as it is, only this one render site is gated.

## Done when

      `false`, `!SHOW_DEPOSIT_ORDER_CONTROLS` is always `true`, so the OR is always `true`
      regardless of `isReturnExchange` — the block is `null` on every tab, sale included. No
      pos-web dev/backend stack was spun up for a live browser check; that remains for G4.
- [x] With the flag `false`, the return/exchange tab's checkout actions row renders exactly
      as it did before this change (the checkbox was already absent there for an unrelated
      reason — `isReturnExchange`) (AC-04) — on that tab `isReturnExchange` is `true`, so the
      OR was already `true` before this ticket touched anything; behaviour is unchanged by
      construction.
- [x] With the flag flipped to `true` locally, the checkbox renders and toggles on the sale
      tab exactly as it does today, and remains absent on the return/exchange tab (AC-05) —
