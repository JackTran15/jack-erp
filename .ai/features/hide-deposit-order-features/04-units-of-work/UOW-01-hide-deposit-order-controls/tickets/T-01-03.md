# T-01-03 — Regression tests: settlement math and receipt printing unaffected

## Context

A-02 asked whether `checkoutSettlement.ts` or the receipt-printing chain treat
`deposit === 0` differently from `deposit === undefined`. Resolved during G2 design review
(see `03-logical-design.md`'s "A-02 investigation" section) by reading the actual code:

- `deposit` is a required `number` throughout (`CheckoutPaymentDraft.deposit`,
  `checkoutDraft.ts:32` defaults it to `0`) — never `undefined` in practice.
- `checkoutSettlement.ts:106` (`deriveSettlement`) has no branch on `deposit`'s presence;
  `deposit = 0` reduces `settlementBase` to `grandTotal + returnFee` (AC-06).
- `checkoutReceiptFactory.ts:244` already guards with `deposit > 0 ? deposit : undefined` —
  a `> 0` check, not `=== 0` — so `0` and `undefined` were already equivalent inputs to this
  line before this feature existed.
- `renderInvoiceHtml.ts:41` (`amountRow`) uses `amount == null`, so a `depositAmount` of
  `undefined` already omits the "Đặt cọc" receipt line (AC-07).

No code change is needed anywhere in this chain — this ticket is pure test-writing to lock
that conclusion in, not a defensive code change.

## Implementation notes

- `checkoutSettlement.test.ts` already exercises `deposit: 0` (line 50) and non-zero deposits
  through `deriveSettlement`. Add an explicit case (or extend an existing `describe` block)
  asserting that `deriveSettlement({ ..., deposit: 0 })` produces
  `settlementGrandTotal === grandTotal + (returnFee ?? 0)` for a plain sale (non-debt,
  non-refund) — i.e., a zero deposit is a true no-op on settlement math. This directly covers
  AC-06.
- `checkoutReceiptFactory.ts` has no existing test file — add a small new
  `checkoutReceiptFactory.test.ts` (vitest, same `describe`/`it` style as the sibling test
  files in this directory) covering just the `depositAmount` field of the built payload:
  - `deposit: 0` → `totals.depositAmount` is `undefined`
  - `deposit: 50_000` (non-zero) → `totals.depositAmount` is `50_000`
  This directly covers AC-07 by proving the printed-receipt input never regresses for the
  no-deposit case this feature guarantees going forward.
- Do not modify `checkoutSettlement.ts`, `checkoutReceiptFactory.ts`, or
  `renderInvoiceHtml.ts` — this ticket is tests only, per the design conclusion above.
- Run with `npx vitest run` from `apps/pos-web` (per-repo note: `pnpm --filter test` is wired
  to `echo test`, but vitest runs directly).
