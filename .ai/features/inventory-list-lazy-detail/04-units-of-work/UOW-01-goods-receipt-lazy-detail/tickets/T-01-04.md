# T-01-04 — DetailPanel line table switches to infinite-scroll pagination

## Context
`DetailPanel` (defined inline in `PurchaseOrdersPage.tsx`, around `:818,878-936`) currently renders
`order.lines.map(...)` in one shot. It switches to consuming
`GET /goods-receipts/:id/lines?page=&pageSize=` (T-01-02) via `useInfiniteQuery`, fetching more lines
as the user scrolls near the bottom of the line table, appending to what's already rendered without
re-fetching earlier pages.

No `useInfiniteQuery` precedent exists in this repo yet — TanStack Query itself is not new (91 files
already depend on it), just this particular hook. For the scroll-triggered *UX* (not the fetch
mechanism), `LookupField.tsx`'s `loadMore()`/scroll-threshold pattern is the closest prior art: state
at `LookupField.tsx:152-161`, `loadMore()` around `:204-227`, scroll trigger `:250-259`.

## Implementation notes
- Key the infinite query on `selectedId` (e.g. `["goods-receipt-lines", selectedId]`), separate from
  T-01-03's header query cache key — a header refetch must not discard already-scrolled line pages.
- `getNextPageParam` uses the response's `hasMore`/`page` to decide whether there's a next page; stop
  once `hasMore` is `false` — do not show a "loading more" affordance past that point (AC-08).
- Attach a scroll listener to the line table's scroll container (or an `IntersectionObserver` sentinel
  row) that calls `fetchNextPage()` near the bottom, guarded against firing while already fetching —
  mirror the guard pattern at `LookupField.tsx:253` (`if (!open || loading || !hasMore ||
  loadingMoreRef.current) return;`).
- Flatten `data.pages` into one array for the `<table>`'s `.map()`, replacing `order.lines.map(...)`.
- A document with 1-3 lines: the first fetch returns `hasMore: false`, so no further request fires and
  no loading affordance appears (AC-08).

## Done when
- [x] Opening a document with 200+ lines shows only the first page initially — `useInfiniteQuery` fetches
      one page (`pageSize=50`) at a time, `lines` is `data.pages.flatMap(...)` of only the pages fetched
- [x] Scrolling near the bottom fetches and appends the next page, without re-fetching earlier pages —
      `IntersectionObserver` sentinel row calls `fetchNextPage()`, guarded by `hasNextPage`/`isFetchingNextPage`
- [x] Opening a document with ≤ `pageSize` lines shows all of them after one fetch, with no further
      request and no stuck "loading more" state — `hasMore: false` ⇒ `hasNextPage` false ⇒ sentinel not rendered
- [x] Line rows render the same columns/fields as before (mapped from the new endpoint's `item` /
      `location` shape instead of `order.lines`)
- [x] `pnpm --filter @erp/backoffice-web build` passes (type-check) — confirmed green

## Implementation note
Used an `IntersectionObserver` sentinel row rather than an `onScroll` listener: the actual scroll
container is `DocumentListShell`'s resizable detail-panel wrapper (`@erp/ui`, `document-list-shell.tsx`),
owned outside this component and not exposing an `onScroll` prop, so `DetailPanel` can't attach a
listener to it directly. The ticket's own implementation notes allow either mechanism. Full 200+-line
scroll behavior verified by code inspection (query/observer wiring) + build; live browser scroll-and-append
deferred to G4 demo.
