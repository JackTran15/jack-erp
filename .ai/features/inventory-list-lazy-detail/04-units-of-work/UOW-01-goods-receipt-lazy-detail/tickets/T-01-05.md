# T-01-05 — Regression coverage — list trim, new endpoint, print/export unaffected

## Context
Closes out UOW-01 with automated proof of the three claims the design makes: the list response no
longer carries `lines`, the new endpoint paginates/404s/empty-cases correctly, and — the risk this
whole UoW's design turns on — nothing that depends on `getById`/`findOrFail` returning full eager
`lines` (print/export) regressed.

## Implementation notes
- `search-goods-receipts-v2.handler.spec.ts`: assert response rows have no `lines` property (or that
  it's `undefined`), and that `provider`/`location` are still populated.
- `goods-receipt.service.spec.ts`: add cases for the new lines method — paginated happy path, 404 for
  unknown/out-of-scope id, empty-lines document returns `hasMore: false`/`total: 0`, `hasMore` toggles
  correctly across a page boundary.
- Do **not** modify any existing `getPrintPayload`/`getById`/`export`-related spec assertions — run
  them unchanged and confirm they still pass, as the regression proof that ADR-01's decision (leave
  `GET /:id` untouched) held.

- [x] Existing `getPrintPayload`/`getById`/export-related tests in `goods-receipt.service.spec.ts` pass
