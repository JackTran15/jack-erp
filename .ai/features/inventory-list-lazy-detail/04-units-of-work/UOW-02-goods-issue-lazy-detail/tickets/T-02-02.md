# T-02-02 — Add paginated GET /inventory/goods-issues/:id/lines endpoint

## Context
Mirrors T-01-02 for Goods Issue. New sub-resource, additive, alongside the existing
`GET :id/print-payload` / `GET :id/export` on the same controller. Two steps:
1. Existence + org/branch-scope check via `giRepo.findOne({ where: { id, organizationId,
   ...(branchId ? { branchId } : {}) }, loadEagerRelations: false })` — see ADR-02 in
   `03-logical-design.md`. 404 if not found. Does **not** reuse the private `findOrFail` — that method's
   eager `lines` load is relied on by `getPrintPayload` and, cross-service, by
   `TransferOrderService.applyDeltaToLines` (`transfer-order.service.ts:1515`); this ticket must not
   touch it.
2. Paginated query directly against `GoodsIssueLineEntity`: `where: { goodsIssueId: id,
   organizationId }`, `order: { createdAt: "ASC" }`, `skip`/`take` from `page`/`pageSize`, plus
   `count()`. `GoodsIssueLineEntity.item`/`.location` stay `eager: true`
   (`goods-issue-line.entity.ts:37-41`) — each returned line already carries item/location detail.

## Implementation notes
- Route: `GET inventory/goods-issues/:id/lines`, same guards/permission as the existing `GET :id`
  (`@RequirePermission('inventory.goods-issue.read')`, `@RequireBranchScope()`).
- Query params: reuse `PaginationQueryDto` — `page`/`pageSize` with existing defaults/validation.
- Response shape: `{ items, page, pageSize, hasMore, total }` — see `03-logical-design.md` Contracts.
- A document with zero lines returns `{ items: [], page, pageSize, hasMore: false, total: 0 }`.

## Done when
- [x] `GET /inventory/goods-issues/:id/lines?page=&pageSize=` returns paginated lines with
      `item`/`location` populated per line
- [x] The existence/scope check uses `loadEagerRelations: false` (or equivalent lean query), not
      `findOrFail`
- [x] 404 for a nonexistent id or one outside the actor's org/branch scope
- [x] A zero-line document returns 200 with `items: []`, `hasMore: false`, `total: 0`
- [x] `hasMore` is correctly `false` on the last page and `true` otherwise

Automated coverage written in T-02-05 (this UoW's regression ticket), mirroring T-01-02/T-01-05.

## Deviation from plan
`GoodsIssueLineEntity` has no `createdAt` column (unlike `GoodsReceiptLineEntity`/`TransferOrderLineEntity`)
— ordered by `id ASC` instead, which is equally stable/deterministic for infinite-scroll accumulation
(the actual requirement per `03-logical-design.md`'s Contracts section), just not insertion order.
Also: no `GoodsIssueLineEntity` repository was already injected into `GoodsIssueService`, and the entity
has no `organizationId` column — used `this.giRepo.manager.findAndCount(GoodsIssueLineEntity, { where:
{ goodsIssueId: id }, ... })` via the existing injected `giRepo`'s manager (same pattern already used
elsewhere in this file, e.g. `manager.delete(GoodsIssueLineEntity, ...)`), scoped by the existence check
on the parent `GoodsIssueEntity` instead.
