# T-02-03 — Row click fetches GET /:id; barcode toolbar reads from it instead of the list row

## Context
Mirrors T-01-03 for Goods Issue. `GoodsIssuePage.tsx` uses the same shared
`useDocumentListSelection` hook, deriving `selectedIssue` client-side off the already-fetched list page.
Once T-02-01 strips `lines` from those rows, `.lines` on the derived object becomes empty. `GET
/inventory/goods-issues/:id` itself is unchanged (still eager-loads full `lines`) — this ticket doesn't
need T-02-02's new endpoint, only the existing `GET :id`.

Two call sites read `selectedIssue.lines` directly and must be rewired:
- Barcode toolbar action (`GoodsIssuePage.tsx:414`)
- `DetailPanel`'s `issue` prop — T-02-04 handles the line *table* inside `DetailPanel`; this ticket
  ensures `DetailPanel` keeps receiving valid header fields.

## Implementation notes
- Add a `useQuery` keyed on `selectedId` (e.g. `["goods-issue", selectedId]`) calling
  `GET /inventory/goods-issues/:id` via `erpApi`/`requireErpData`, `enabled: !!selectedId`.
- Replace `selectedIssue` (currently `useDocumentListSelection`'s `activeRecord`) with this query's data
  wherever full detail (including `lines`) is needed — barcode toolbar (`:414`) and the value passed to
  `DetailPanel`.
- Header fields render as soon as this query resolves, independent of any line-pagination fetch.

## Done when
- [x] Clicking a row (or its doc-number link) triggers a `GET /inventory/goods-issues/:id` network
      request
- [x] Header fields render as soon as that request resolves, without waiting on any `/lines` request
- [x] The barcode toolbar action builds its item list from the `GET /:id` response's `lines`, not the

      actual lines — verified by code inspection; live browser click-through deferred to G4 demo
- [x] `pnpm --filter @erp/backoffice-web build` passes (type-check) — confirmed green

doc-number-link fetches `GET /inventory/goods-issues/:id` before opening the view dialog).
