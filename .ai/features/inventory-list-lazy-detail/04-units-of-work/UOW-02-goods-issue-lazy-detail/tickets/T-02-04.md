# T-02-04 — DetailPanel line table switches to infinite-scroll pagination

## Context
Mirrors T-01-04 for Goods Issue. `DetailPanel` (inline in `GoodsIssuePage.tsx`, around `:766-801`)
currently renders `issue.lines.map(...)` in one shot; switches to
`GET /inventory/goods-issues/:id/lines?page=&pageSize=` (T-02-02) via `useInfiniteQuery`. Same
scroll-triggered UX precedent as T-01-04: `LookupField.tsx`'s `loadMore()`/scroll-threshold pattern
(state `:152-161`, `loadMore()` `:204-227`, scroll trigger `:250-259`).

## Implementation notes
- Key the infinite query on `selectedId` (e.g. `["goods-issue-lines", selectedId]`), separate from
  T-02-03's header query cache key.
- `getNextPageParam` uses `hasMore`/`page`; stop fetching once `hasMore` is `false`, no lingering
  "loading more" UI (AC-08).
- Scroll-near-bottom trigger guarded against re-firing while a fetch is in flight, mirroring
  `LookupField.tsx:253`.
- Flatten `data.pages` for the `<table>`'s `.map()`, replacing `issue.lines.map(...)`.

## Done when
- [x] Opening a document with 200+ lines shows only the first page initially
- [x] Scrolling near the bottom fetches and appends the next page, without re-fetching earlier pages
- [x] Opening a document with ≤ `pageSize` lines shows all of them after one fetch, no further request,
      no stuck "loading more" state
- [x] Line rows render the same columns/fields as before (mapped from the new endpoint's shape)
- [x] `pnpm --filter @erp/backoffice-web build` passes (type-check) — confirmed green

## Implementation note
Same `IntersectionObserver` sentinel-row approach as T-01-04, for the identical reason (the actual
scroll container is `@erp/ui`'s `DocumentListShell`, outside this component). Live browser scroll
verification deferred to G4 demo.
