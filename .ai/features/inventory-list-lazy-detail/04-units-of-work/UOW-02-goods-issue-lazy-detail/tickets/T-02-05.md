# T-02-05 — Regression coverage — list trim, new endpoint, print/export/TO-edit unaffected

## Context
Mirrors T-01-05 for Goods Issue, with one extra risk to prove: `TransferOrderService.applyDeltaToLines`
calls `goodsIssueService.getById` cross-service (`transfer-order.service.ts:1515`) and depends on the
full eager `lines` array to compute per-line quantity deltas — this is the concrete regression ADR-01 in
`03-logical-design.md` exists to prevent.

## Implementation notes
- `search-goods-issues-v2.handler.spec.ts`: assert response rows have no `lines` property, and that
  `provider`/`reasonRef`/`location`/`targetBranch` are still populated as applicable.
- `goods-issue.service.spec.ts`: add cases for the new lines method — paginated happy path, 404,
  empty-lines document, `hasMore` correctness across a page boundary.
- Run `transfer-order.service.spec.ts`'s existing quantity-delta / `applyDeltaToLines`-related test
  cases unmodified and confirm they still pass — proof that `goodsIssueService.getById` still returns
  full eager `lines`.
- Do not modify existing `getPrintPayload`/`getById`/export-related spec assertions.
