# T-03-03 — Row click fetches GET /:id to supply header/DetailPanel state

## Context
Mirrors T-01-03/T-02-03 for Transfer Order — minus the barcode toolbar rewire, since
`TransferOrdersPage.tsx` has no barcode-scan toolbar action (AC-09 doesn't apply here). Same shared
`useDocumentListSelection` hook derives `selectedOrder` client-side off the already-fetched list page.
Once T-03-01 strips `lines` from those rows, `.lines` on the derived object becomes empty. `GET
/inventory/transfer-orders/:id` itself is unchanged — this ticket doesn't need T-03-02's new endpoint,
only the existing `GET :id`.

`DetailPanel`'s `order` prop (`TransferOrdersPage.tsx:612-660`) is the only consumer that reads
`.lines` today; T-03-04 handles the line *table* rendering inside `DetailPanel`. This ticket ensures
`DetailPanel` keeps receiving valid header fields (e.g. `order.sourceStorageId`, used as a fallback for
lines that don't specify their own).

## Implementation notes
- Add a `useQuery` keyed on `selectedId` (e.g. `["transfer-order", selectedId]`) calling
  `GET /inventory/transfer-orders/:id` via `erpApi`/`requireErpData`, `enabled: !!selectedId`.
- Replace `selectedOrder` (currently `useDocumentListSelection`'s `activeRecord`) with this query's
  data wherever full detail (including `lines`) is needed — the value passed to `DetailPanel`.
- Header fields render as soon as this query resolves, independent of any line-pagination fetch.

## Done when
- [x] Clicking a row (or its doc-number link) triggers a `GET /inventory/transfer-orders/:id` network
      request
- [x] Header fields render as soon as that request resolves, without waiting on any `/lines` request
- [x] `pnpm --filter @erp/backoffice-web build` passes (type-check) — confirmed green

(`selectedOrder` now sources from the new `useQuery`; doc-number-link fetches
`GET /inventory/transfer-orders/:id` before opening the view dialog).
