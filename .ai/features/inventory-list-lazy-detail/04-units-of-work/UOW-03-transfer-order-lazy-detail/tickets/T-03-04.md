# T-03-04 — DetailPanel line table switches to infinite-scroll pagination

## Context
Mirrors T-01-04/T-02-04 for Transfer Order. `DetailPanel` (inline in `TransferOrdersPage.tsx`, around
`:605-660`) currently renders `order.lines.map(...)` in one shot; switches to
`GET /inventory/transfer-orders/:id/lines?page=&pageSize=` (T-03-02) via `useInfiniteQuery`. Same
scroll-triggered UX precedent as T-01-04/T-02-04: `LookupField.tsx`'s `loadMore()`/scroll-threshold
pattern (state `:152-161`, `loadMore()` `:204-227`, scroll trigger `:250-259`).

## Implementation notes
- Key the infinite query on `selectedId` (e.g. `["transfer-order-lines", selectedId]`), separate from
  T-03-03's header query cache key.
- `getNextPageParam` uses `hasMore`/`page`; stop fetching once `hasMore` is `false`, no lingering
  "loading more" UI (AC-08).
- Scroll-near-bottom trigger guarded against re-firing while a fetch is in flight, mirroring
  `LookupField.tsx:253`.
- Flatten `data.pages` for the `<table>`'s `.map()`, replacing `order.lines.map(...)`; each line's
  `sourceStorageId` fallback to `order.sourceStorageId` (`:641`) still needs `order` (from T-03-03's
  header query) alongside the paginated line data.

## Done when
- [x] Opening a document with 200+ lines shows only the first page initially
- [x] Scrolling near the bottom fetches and appends the next page, without re-fetching earlier pages
- [x] Opening a document with ≤ `pageSize` lines shows all of them after one fetch, no further request,
      no stuck "loading more" state
- [x] Line rows render the same columns/fields as before (mapped from the new endpoint's shape); each
      line's `sourceStorageId` fallback to `order.sourceStorageId` still uses `order` from T-03-03's
      header query alongside the paginated `lines`
- [x] `pnpm --filter @erp/backoffice-web build` passes (type-check) — confirmed green
