# T-01-01 — Cột `separator` trên `document_number_rules`

## Context

`formatDocumentNumber` đang `parts.join('-')` cứng. Để dựng được `2608210001` (dính liền)
mà `INV-202608-00013` (có gạch) không đổi một ký tự, dấu phân cách phải trở thành dữ liệu
của rule chứ không phải hằng số trong code (ADR-01).

Ticket này **chỉ thêm cột**. Không đụng logic dựng số (T-01-02), không đổi rule nào
(T-01-04). Tách ra vì hai lý do: migration `ALTER` và migration `UPDATE` revert được độc
lập, và `migrationsTransactionMode: 'each'` nghĩa là chúng vốn đã không nguyên tử với nhau.

## Implementation notes

- Thêm vào `DocumentNumberRuleEntity`, đặt ngay dưới `suffix` để cụm prefix/suffix/separator
  đứng cạnh nhau:
  ```ts
  @Column({ length: 5, default: '-', comment: 'String joining prefix / date / sequence / suffix; empty means no separator' })
  separator: string;
  ```
- Migration `1789300000000-AddDocumentNumberSeparator`:
  - `up`: `ALTER TABLE document_number_rules ADD COLUMN separator varchar(5) NOT NULL DEFAULT '-'`
  - `down`: `ALTER TABLE document_number_rules DROP COLUMN separator`
- `DEFAULT '-'` là điểm mấu chốt của cả feature: mọi hàng đang có nhận `-`, nên T-01-02 sửa
  `join` xong thì đầu ra không đổi. Đừng để `NULL`-able rồi xử lý `?? '-'` trong code — đẩy
  giá trị mặc định vào code là chỗ nó dễ bị quên.
- Viết tay migration, **không** `migration:generate` — nó sinh drift khổng lồ trên repo này.
