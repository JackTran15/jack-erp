# T-02-02 — Bỏ `generateInvoiceNumber`, vá số thật từ response checkout

## Context

Đây là ticket sửa đúng cái bug trong ảnh. `checkoutReceiptFactory.ts:23`:

```ts
/** Receipt number generator: YYMMDD + 4 random digits — e.g. "2605050007". */
function generateInvoiceNumber(d: Date): string { … Math.floor(Math.random() * 10_000) … }
```

Con số đó chưa từng được gửi lên server, chưa từng được lưu, và không tra ra được gì. Trong
khi đường in lại (`invoiceRowPrintPayload.ts:101`) dùng đúng `invoice.code` — nên hai tờ in
của **cùng một hoá đơn** không bao giờ khớp nhau.

Nếp vá-sau-mutation đã có sẵn ngay trong file này: `receiptPayload.totals.pointsEarned` được
gán sau khi API trả về, vì điểm tích cũng chỉ biết sau khi checkout xong. Số hoá đơn đi cùng
đường đó.

## Implementation notes

- `checkoutReceiptFactory.ts`: xoá hẳn `generateInvoiceNumber` (cả hàm lẫn comment) và bỏ
  `invoiceNumber: generateInvoiceNumber(new Date())` khỏi object trả về ở dòng ~219. Không
  thay bằng `invoiceNumber: ""` — trường tuỳ chọn thì để vắng mặt, đừng để chuỗi rỗng.
- `use-checkout-actions.ts`, nhánh **SALE** (~dòng 331), ngay cạnh chỗ đã vá `pointsEarned`:
  ```ts
  if (receiptPayload) {
    receiptPayload.invoiceNumber = soldInvoice.code;
    receiptPayload.totals.pointsEarned = soldInvoice.pointsEarned;
    …
  }
  ```
- `use-checkout-actions.ts`, nhánh **RETURN / EXCHANGE** (~dòng 435), khối `if (receiptPayload)`
  thứ hai: `receiptPayload.invoiceNumber = posted.code;`
- Hai nhánh cách nhau ~110 dòng trong cùng một hàm. Sót một nhánh nghĩa là một nửa số phiếu
  in không có số — và nửa đó vẫn "trông bình thường". Sửa xong thì
  `grep -n "receiptPayload.invoiceNumber" use-checkout-actions.ts` phải ra đúng **hai** dòng.
- `soldInvoice` và `posted` đều kiểu `InvoiceRow`, đã có `code: string`
  (`invoice.interface.ts:47`) — không cần đổi kiểu, không cần regen api-client.
- **Không** đụng `use-checkout-estimate.ts`: đường tạm tính dựng biên lai qua cùng factory và
  giờ tự nhiên không có số — đó là AC-13, không phải thiếu sót.
- AC-12 (tra cứu bằng số trên giấy) không cần code mới: ô tìm hoá đơn ở màn Đổi trả đã lọc
  theo `code` (`use-return-goods.ts:117`). Nó đúng ngay khi số in ra là `code` thật.
