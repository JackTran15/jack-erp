# T-02-02 — FE: POS gửi active branch cho filter-options

## Context

`useReportFilterOptionsQuery` (`use-query-daily-report.ts:54-63`) **đã** đọc `branchId` từ
`usePosBranchStore` nhưng chỉ dùng nó làm cache key — không gửi lên server. Đó là lý do đổi chi
nhánh thì cache đổi mà kết quả vẫn org-wide.

Cần T-02-01 xong trước, không thì `forbidNonWhitelisted` trả 400 cho param lạ.

## Implementation notes

- `daily-report.service.ts:49-59`: `getFilterOptions(type, search = "", branchId?)`, thêm
  `if (branchId) qs.set("branchId", branchId)`.
- `use-query-daily-report.ts:54-63`: truyền `branchId` xuống service, và thêm
  `enabled: Boolean(branchId)` — chưa chọn chi nhánh thì không bắn request org-wide (đúng với
  bảng error taxonomy ở `03-logical-design.md`).
- Một thay đổi này phủ cả ba ô, không cần sửa component nào:
  - "Thu ngân" và "NVBH" trên toolbar (`DailyReportToolbar.tsx:82-83`)
  - ô "Nhân viên" nhận/bàn giao ca (`HandoverPanel.tsx:126`, dùng lại `type="cashier"`)

### Vòng review 1 — PASS

Không blocker. Reviewer bổ sung một dữ kiện đáng ghi: `DailyReportPage` chỉ render dưới
`PosRequireBranch`, component này redirect sang `/chon-chi-nhanh` khi `branchId` falsy, và
`usePosBranchStore` persist bằng adapter localStorage đồng bộ (không `skipHydration`) nên store
đã rehydrate trước lần render đầu. Nghĩa là `enabled: Boolean(branchId)` trên thực tế là lớp
phòng thứ hai, không phải lớp duy nhất — vẫn giữ, vì nó chặn đúng trạng thái cần chặn nếu route
guard đổi về sau.

Cũng xác nhận `dailyReportService.getFilterOptions` chỉ có duy nhất caller này, và bộ lọc báo cáo
chuỗi ở backoffice đi qua file API riêng (`chain-store/reports/_api/report-filter-options.api.ts`)
nên AC-11 không bị chạm về mặt cấu trúc.

### Ghi chú

`enabled: Boolean(branchId)` là thay đổi hành vi thật, không phải dọn dẹp: trước đây khi chưa
chọn chi nhánh, hook vẫn gọi và server trả về danh sách nhân sự **toàn tổ chức** cho tài khoản có
`iam.user.read.all`. Đó chính là trạng thái cần chặn.
