# T-01-05 — Snapshot OpenAPI

## Context

CLAUDE.md: "After changing API endpoints: run the API, then `pnpm openapi:generate`. Commit
the updated `openapi.snapshot.json` and generated `packages/api-client/src/generated/schema.ts`."

Thay đổi này đổi hình dạng response của `POST /v2/invoices/search`. Nhưng
`InvoiceV2Controller.search` không khai `@ApiResponse` kiểu nào — nó `return this.queryBus.execute(...)`
không có kiểu trả về tường minh — nên có khả năng schema sinh ra vốn đã rỗng và không có
gì để cập nhật. Và pos-web gọi qua `http` riêng, không qua `@erp/api-client` (A-05).

Ticket này **quyết định** bằng cách kiểm tra, không bằng phỏng đoán.

## Implementation notes

1. `grep -n "v2/invoices/search" packages/api-client/openapi.snapshot.json` — endpoint có trong snapshot không?
2. Nếu **không** có: không có gì để regenerate. Ghi kết luận vào ticket này, đóng A-05, hết việc.
3. Nếu **có** và schema response mô tả hình dạng `data[]`: chạy API rồi `pnpm openapi:generate`,
   commit cả `openapi.snapshot.json` lẫn `packages/api-client/src/generated/schema.ts`.
   **Không** sửa tay file generated.
4. Dù rẽ nhánh nào, ghi lại kết quả grep vào phần Done when — để lần sau không ai phải hỏi lại.

Cảnh báo: `pnpm openapi:generate` cần API chạy trên :4000 **từ đúng checkout này**. Xem
`.ai/verify-stack.sh` và bẫy đã dính một lần: API :4000 chạy từ worktree khác cho kết quả
trông y hệt như chưa sửa gì.

## Done when

- [x] Kết quả grep: endpoint **có** trong snapshot, tại `packages/api-client/openapi.snapshot.json:15858`
- [x] **Không cần regenerate.** Schema response của nó là `{"type": "object"}` — rỗng hoàn toàn:

      ```jsonc
      "responses": { "201": { "content": { "application/json": {
        "schema": { "type": "object" }   // ← không mô tả data[] chút nào
      }}}}
      ```

      `InvoiceV2Controller.search` không khai `@ApiResponse` và không có kiểu trả về tường
      minh, nên Swagger không suy ra được hình dạng nào. Thêm một field vào response
      **không thể** làm schema này đổi ⇒ `pnpm openapi:generate` sẽ sinh ra file y hệt.
- [x] A-05 chuyển sang `verified`, và mạnh hơn giả định ban đầu: không phải "endpoint vắng
      mặt trong snapshot", mà là "có mặt nhưng response không được mô tả"
- [x] Không file generated nào bị sửa tay

## Ghi chú cho lần sau

Việc `search` (và mọi endpoint v2 khác trong `InvoiceV2Controller`) trả schema rỗng nghĩa
là `@erp/api-client` **không** kiểu hoá được response của chúng — đó là lý do pos-web tự
khai `InvoiceSearchV2Response` trong `dtos/invoice.dto.ts` thay vì dùng type sinh ra. Sửa
điều đó là việc riêng, ngoài phạm vi feature này.
