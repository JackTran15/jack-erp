# T-01-01 — AuthService reads access/refresh TTL from ConfigService

## Context
`ACCESS_TOKEN_TTL = 15 * 60` and `REFRESH_TOKEN_TTL = 7 * 24 * 60 * 60`
(`auth.service.ts:31-32`) are module-level constants referenced 16 times across `login`
(~97-120), `refresh` (~165-189), `switchBranch` (~220-246), `exchangeHandoffCode`
(~332-353), and `signAccessToken`/`signRefreshToken` (~428-437). `jwtSecret`/
`jwtRefreshSecret` already follow the pattern this ticket copies:
```ts
this.jwtSecret = this.config.get<string>('JWT_SECRET', 'change-me-secret');
```
(`auth.service.ts:58-62`).

## Implementation notes
- Add `private readonly accessTokenTtl: number;` / `private readonly refreshTokenTtl: number;`
  fields, set in the constructor next to `jwtSecret`:
  ```ts
  this.accessTokenTtl = this.config.get<number>('JWT_ACCESS_TTL', 86400);
  this.refreshTokenTtl = this.config.get<number>('JWT_REFRESH_TTL', 2592000);
  ```
- Delete the two module-level constants; replace every reference
  (`ACCESS_TOKEN_TTL` → `this.accessTokenTtl`, `REFRESH_TOKEN_TTL` → `this.refreshTokenTtl`)
  at all 16 call sites. Pure rename — no control-flow change.
- `ConfigService.get<number>` returns a `string` if the underlying env value isn't coerced —
  confirm (or add) numeric coercion consistent with however `ConfigModule` is configured
  elsewhere in this app; if in doubt wrap with `Number(...)`.
- Update `apps/api/.env.example:36-37` to `JWT_ACCESS_TTL=86400` / `JWT_REFRESH_TTL=2592000`.
- Update this checkout's `apps/api/.env` (gitignored, already has the old values explicitly
  set) to the same new values — otherwise local verification of AC-01 will appear to fail
  for a reason invisible from the diff (see A-02).
