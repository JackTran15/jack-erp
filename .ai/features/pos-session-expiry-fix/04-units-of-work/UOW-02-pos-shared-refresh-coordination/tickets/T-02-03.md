# T-02-03 — api-axios.ts uses the shared refreshOnce

## Context
`api-axios.ts:47-81` has its own `refreshPromise`/`refreshOnce`/`tryRefreshToken`. The
response interceptor (~88-121) calls `refreshOnce()` on a 401, with an
`AuthErrorCode.TOKEN_EXPIRED` branch and an explicit "AC-05 regression guard" comment
(from `auth-token-auto-refresh`) that must not regress.

## Implementation notes
- Delete `api-axios.ts`'s local `refreshPromise`, `refreshOnce`, `tryRefreshToken`.
- Import `refreshOnce` from `./token-refresh` instead; the interceptor's control flow
  (the `AuthErrorCode.TOKEN_EXPIRED` check, the fallthrough comment, `_retry` guard,
  clear-and-redirect on failure) is otherwise untouched.
- Run the existing `api-axios.test.ts` suite before and after — it must still pass
  unmodified, since it's the regression guard for `auth-token-auto-refresh`'s AC-05/06/07/08.

## Post-implementation correction (by the orchestrating session, not this ticket's
implementer)
The implementer correctly stopped short of ticking "suite passes unmodified" and flagged two
issues instead of forcing it. Investigated both:
1. **Pre-existing, out-of-scope harness bug, confirmed independently**: `git stash`-ing this
   ticket's *and* T-02-02's changes back to the last commit (T-02-01 only) and running
   `npx vitest run api-axios.test.ts` still fails 3/4 tests with the identical
   `AssertionError: expected "wrap" to be called 1 times, but got 0 times` — against
   `api-axios.ts`'s **original, unmodified, axios.post-based** `tryRefreshToken`. So this is a
   `vi.spyOn(axios, "post")` / axios-ESM-interop issue in this repo's vitest setup, unrelated
   to transport choice or to this feature. Out of scope to fix here; flagged to the user
   separately.
2. **Real design flaw, now fixed**: `token-refresh.ts` (T-02-01) used `fetch`, which this
   suite's spy can never observe regardless of the harness bug above. Corrected
   `token-refresh.ts` to use `axios.post` instead (axios is already a pos-web dependency via
   this same file) — restores the same spy target the suite expects, fully transparent to
   `http.ts`/`api-axios.ts`'s callers of `refreshOnce()`. Re-ran the suite after the fix:
   identical 3-failed/1-passed output, byte-for-byte, as the pre-existing baseline in (1) — no
   *new* failure introduced.
