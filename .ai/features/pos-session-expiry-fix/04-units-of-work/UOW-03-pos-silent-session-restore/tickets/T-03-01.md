# T-03-01 — PosSessionHandoff proactively refreshes an expired-but-refreshable session

## Context
`PosSessionHandoff` already blocks rendering `<Routes>` (and therefore `PosRequireAuth`)
via a `pending` state while its `?handoff=` code exchange effect runs — see its doc
comment explaining this exists specifically because `PosRequireAuth` is synchronous. This
ticket adds a second, mutually-exclusive bootstrap path to the same gate: when there's no
handoff code, proactively attempt a silent refresh before letting `PosRequireAuth`'s
existing synchronous `exp` check run.

`authService.isAuthenticated()` (`auth.service.ts:82-92`) is the existing synchronous check
this ticket does not modify — it's what decides the outcome after this ticket's proactive
refresh (if any) has already resolved.

## Implementation notes
- Extract the async bootstrap decision as a plain exported function, e.g.:
  ```ts
  export async function restoreSessionIfNeeded(): Promise<void> {
    if (authService.isAuthenticated()) return;
    if (!localStorage.getItem(POS_REFRESH_TOKEN_KEY)) return;
    await refreshOnce();
  }
  ```
  so it's testable without rendering (per A-04) — `PosSessionHandoff`'s `useEffect` just
  calls it and ignores the resolved value; `PosRequireAuth`'s own check afterwards decides
  the final outcome either way (satisfies AC-05: no valid refresh token → this function is
  a no-op → existing behavior unchanged).
- Wire it into `PosSessionHandoff`'s existing `pending` gate: when `code` (the handoff
  param) is absent, set `pending` from this function's promise instead of from the handoff
  effect. When `code` is present, behavior is completely unchanged — the handoff branch
  must not also trigger this check (AC-06).
- Import `refreshOnce` from `../../../lib/common/token-refresh` (UOW-02's output).
- Update the component's doc comment: it now bootstraps a session two ways (handoff
  exchange, proactive refresh), not one.

## Done when
- [ ] `restoreSessionIfNeeded` is exported and callable independent of rendering
- [ ] With no `?handoff=` param: an expired-access/valid-refresh session resolves via one

      no-op
- [ ] With a `?handoff=` param: behavior is identical to before this ticket (byte-diff the
      handoff branch if unsure)
- [ ] `PosRequireAuth.tsx` has zero diff
