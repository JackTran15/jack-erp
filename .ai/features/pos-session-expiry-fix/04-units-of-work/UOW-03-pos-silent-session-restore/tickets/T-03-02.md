# T-03-02 — Tests prove the proactive-refresh bootstrap decision

## Context
Per A-04, this tests `restoreSessionIfNeeded` (T-03-01's plain exported function) directly
— no component mount, no DOM. AC-06 (handoff still takes priority end-to-end) is not
covered here; it's verified via UOW-03's G4 demo script instead, since proving it would
require rendering the component tree, which this repo's test infra doesn't support (A-04).
State this explicitly in the PR rather than silently under-covering it.

## Implementation notes
- Mock `authService.isAuthenticated` and `token-refresh`'s `refreshOnce` (module mocks,
  `vi.mock`), plus a fake `localStorage`, following `api-axios.test.ts`'s style.
- AC-04: `isAuthenticated()` → `false`, refresh token present → assert `refreshOnce` was
  called exactly once.
- AC-05: `isAuthenticated()` → `false`, no refresh token → assert `refreshOnce` was **not**
  called (nothing to attempt; `PosRequireAuth`'s own check handles the redirect, untouched
  by this feature).
- A third case worth asserting for free: `isAuthenticated()` → `true` → `refreshOnce` not
  called (no unnecessary refresh on an already-valid session).

- [x] AC-05 case passes: no valid refresh → zero `refreshOnce()` calls
- [x] Already-valid-session case passes: zero `refreshOnce()` calls
