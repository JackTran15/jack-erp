# T-02-03 — Regen openapi snapshot + api-client

## Context

`PosProductDetailDto` là DTO duy nhất trong feature có khai báo Swagger, nên đây là thay đổi
hợp đồng API duy nhất phải phản ánh ra snapshot. Hai endpoint kia (`/catalog`,
`/catalog/lookup`) trả type thuần, không có `@ApiOkResponse` — snapshot không đụng tới.

`pos-web` gọi bằng `http.get` với interface tự khai, nên regen **không** phải để FE compile
được; nó là để hợp đồng trong repo khớp thực tế.

## Implementation notes

- Chạy API (`make dev-api`), rồi `pnpm openapi:generate`.
- Commit cả `openapi.snapshot.json` và `packages/api-client/src/generated/schema.ts`. Không
  sửa tay file generated.
- Nếu diff lòi ra thay đổi ngoài `showroomQuantity`, **dừng lại và báo** — nghĩa là snapshot
  đang lệch sẵn từ trước, không phải việc của ticket này gộp vào.

## Done when

- [x] `pnpm openapi:generate` chạy xong (API thật trên :4000, DB `erp_dev`)
- [x] Phần dôi ra ngoài `showroomQuantity` đã được báo cáo — xem bên dưới

## Kết quả

`showroomQuantity` xuất hiện đúng **một** schema: `PosProductVariantDto` (cả `properties` lẫn
`required`). Không schema nào khác bị đụng — đúng như thiết kế: `/catalog` và `/catalog/lookup`
trả type thuần, không có `@ApiOkResponse`.

## Phần dôi ra — snapshot đã lệch sẵn từ trước

Diff của `openapi.snapshot.json` là **+307 dòng, 0 dòng xoá**, trong đó phần của feature này
chỉ khoảng 10 dòng. 297 dòng còn lại là **ba endpoint đã có trong code nhưng chưa bao giờ
được regen vào snapshot**:

- `GET /inventory/goods-issues/{id}/lines`
- `GET /inventory/transfer-orders/{id}/lines`
- `GET /goods-receipts/{id}/lines`

Cả ba thuộc feature `inventory-list-lazy-detail`, không liên quan gì tới cảnh báo tồn kho.

**Đã giữ nguyên toàn bộ kết quả regen, không cắt bớt.** File này là file sinh tự động; sửa tay
để diff cho gọn là đúng thứ quy ước repo cấm. Nhưng hệ quả phải nói rõ khi review: diff của
feature này mang theo 297 dòng nợ của người khác, và người review đừng mất công soi chúng.

Nếu muốn tách bạch, cách sạch là commit riêng phần regen drift trước, rồi commit feature —
quyết định đó thuộc về chủ sở hữu, ticket này không tự ý tách.
