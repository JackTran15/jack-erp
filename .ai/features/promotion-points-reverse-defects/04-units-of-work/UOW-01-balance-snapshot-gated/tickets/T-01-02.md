# T-01-02 — Spec for the blocked-accrual balance projection

## Context

`persist-invoice.step.spec.ts` has three `pointsBalanceAfter` cases today — the ordinary
projection (`100 - 20 + 73 = 153`, line 104), the walk-in null case (line 116), and the
clamp-at-zero case (line 197). None of them sets `pointsBlocked: true`, which is why #15
shipped green. `pointsBlocked` lives on the step context's `totals`
(`checkout-step.ts:133`), so the existing test doubles already have a place to set it.

## Implementation notes

- Add a case mirroring QA's exact numbers, so a future reader can match the test against the
  defect report: card 7575, `amountDue` 800.000, `totals.pointsEarned` 80,
  `pointsBlocked: true`, `pointsRedeemed` 0 → expect `pointsEarned` 0 and
  `pointsBalanceAfter` 7575. Name it after the behaviour, not the ticket.
- Add a second blocked case that also redeems points — card 7575, redeemed 100, blocked →
  expect 7475 — so the two independent terms are proved separately rather than by one case
  where a sign error could cancel out.
- Assert `pointsEarned` and `pointsBalanceAfter` in the same case. The whole defect is the two
  disagreeing; a test that checks only one cannot see it.
- Leave the three existing cases exactly as they are (AC-02, AC-03 are no-change
  regressions). If one of them needs editing, the implementation is wrong, not the test.

- [x] A blocked-and-redeemed case asserts `pointsBalanceAfter = 7475`
