# T-02-01 — `points` on the reverse payload, honoured by the consumer

## Context

`LoyaltyPointsReverseConsumer` re-derives the point count from money at line 60-62:

```ts
const requestedDelta = Math.floor(
  Math.abs(Number(subtotalDelta)) / POINT_EARN_VND_PER_POINT,
);
```

That was correct while `points_earned = floor(amount_due / rate)` held for every invoice.
`promotion-scope-points-toggle` broke the identity, and the consumer has no way to know. This
ticket gives it one. It is the contract half of the fix — no producer changes here, so nothing
observable moves until T-02-02 lands.

ADR-01 governs the shape: optional field, authoritative when present, money kept as the
fallback so events already sitting in the topic at deploy time still process correctly (A-05).

## Implementation notes

`loyalty-points-reverse.publisher.ts`:
- Add `points?: number` to both `LoyaltyPointsReversePayload` and
  `LoyaltyPointsReverseInput`, documented as "authoritative point count; when absent the
  consumer falls back to `floor(subtotalDelta / POINT_EARN_VND_PER_POINT)`".
- Pass it through in the `satisfies LoyaltyPointsReversePayload` block. Use
  `input.points == null ? undefined : Number(input.points)` — `Number(undefined)` is `NaN`,
  and a `NaN` on the wire would be read as "present" by `??`.
- Update the existing doc comment on `subtotalDelta`, which currently states the consumer
  decrements `floor(subtotalDelta / rate)` — no longer unconditionally true.
- **Leave the `if (input.subtotalDelta <= 0) return false` guard alone.** A blocked cancel
  still moves money, so it still publishes, carrying `points: 0`. That is deliberate: the
  consumer's delta-0 branch writes the `ADJUST` row the replay guard keys on (A-04).

`loyalty-points-reverse.consumer.ts`:
- Destructure `points` alongside the rest of the payload at line 28-29.
- Replace the `requestedDelta` computation with
  `points ?? Math.floor(Math.abs(Number(subtotalDelta)) / POINT_EARN_VND_PER_POINT)`.
  Use `??`, not `||` — `points: 0` is the exact case this feature exists to honour, and `||`
  would fall straight through to the money derivation.
- Extend the log lines to name the resolved count and its source, e.g.
  `... requested=${requestedDelta} source=${points == null ? 'money-fallback' : 'payload'}`.
  Per the error taxonomy, the zero case logs that accrual was blocked rather than no-opping
  silently.
- Do not touch the dedup lookup, the `Math.min(requestedDelta, card.points)` clamp, the
  no-card branch or the delta-0 insert. All keep their current behaviour.
