# T-03-01 — Cap the return reverse at what the original actually earned

## Context

The return path has #16's shape in two places. Line ~345 snapshots

```ts
invoice.pointsReversed = Math.floor(
  this.computeReverseBase(originalInvoice, totals) / POINT_EARN_VND_PER_POINT,
);
```

and line ~1122 publishes `subtotalDelta: this.computeReverseBase(originalInvoice, totals)`.
Both are pure money. `computeReverseBase` returns `totals.returnedNet` when an original exists
and `abs(refundedAmount || returnSubtotal)` for a QUICK return with none — nothing anywhere
consults `originalInvoice.pointsEarned`. Return a blocked invoice and the customer loses points
that were never accrued, exactly as cancelling did.

ADR-02 fixes it with a cap rather than a re-derivation, so every partial-return number stays
where it is: `min(money-derived, originalInvoice.pointsEarned)`. A blocked original caps to 0;
a full return caps to exactly what was earned; a partial return sits below the cap untouched.

## Implementation notes

- Add a private `computeReversePoints(originalInvoice, totals): number` next to
  `computeReverseBase`, so the pair reads together:
  - `const derived = Math.floor(this.computeReverseBase(originalInvoice, totals) / POINT_EARN_VND_PER_POINT)`
  - `return originalInvoice ? Math.min(derived, Number(originalInvoice.pointsEarned ?? 0)) : derived`
- Document it the way `computeReverseBase` is documented — a doc comment stating the rule, why
  the cap and not a proration (point to ADR-02 and A-02), and that QUICK returns are uncapped
  because there is no recorded earn to cap against.
- Use it at **both** sites:
  - line ~345: `invoice.pointsReversed = this.computeReversePoints(originalInvoice, totals);`
  - line ~1122: add `points: this.computeReversePoints(originalInvoice, totals)` to the
    `loyaltyPointsReversePublisher.publish` call, keeping `subtotalDelta: delta` unchanged.
  Having one function feed both is the point — #16 was the snapshot and the card disagreeing.
- Leave the `if (delta > 0)` publish guard as it is. A blocked full return still has
  `returnedNet > 0`, so it still publishes and still writes the replay marker with `points: 0`.
- Do not touch `computeReverseBase`, `computeRedeemedCreditBack`, `returnedNet`, or the
  exchange earn call on `totals.newSubtotal`.
- Per the error taxonomy, log when there is no original invoice to cap against, so an
  unexpectedly uncapped reverse is visible.
