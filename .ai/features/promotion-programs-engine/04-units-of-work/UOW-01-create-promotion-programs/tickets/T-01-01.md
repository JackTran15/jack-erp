# T-01-01 — Schema chuẩn hóa cho chương trình khuyến mại

## Context

Nền của toàn epic. Bảng `promotions` cũ (jsonb) **không đụng tới** — xem ADR-04. Migration
viết tay, không dùng `migration:generate` (sinh drift khổng lồ trên repo này).

`data-source.ts` đặt `migrationsTransactionMode: 'each'`, nên `ALTER TYPE … ADD VALUE` phải
nằm ở **file riêng**: dùng giá trị enum mới trong cùng transaction vừa thêm nó sẽ nổ `55P04`.

## Implementation notes

- File 1 chỉ một câu: `ALTER TYPE "document_number_rules_document_type_enum" ADD VALUE IF NOT
  EXISTS 'PROMOTION'`. `down()` để trống kèm comment — Postgres không gỡ được giá trị enum.
- File 2: 15 `CREATE TYPE` + 7 `CREATE TABLE` + index. `down()` gỡ theo thứ tự ngược.
- Mọi bảng mang cột chuẩn của `BaseEntity`; riêng 2 bảng nối chỉ có PK ghép + `organization_id`.
- `promotion_programs` có `deleted_at` (soft delete, AC-18); index `UNIQUE (organization_id,
  code)`, `(organization_id, status, start_date, end_date)`, `(organization_id, priority)`.
- `promotion_lines`: **không** FK trên `target_id` (ADR-05); index `(organization_id,
  target_type, target_id)`.
- Mọi FK con → `promotion_programs` đặt `ON DELETE CASCADE`.
- `birthday_match` gồm cả `RANGE` + 2 cột `birthday_before_days`/`birthday_after_days` (A-14).
- Permission: `PermissionSyncService` đồng bộ `PERMISSION_DEFINITIONS` lúc boot → chỉ sửa
  `permissions.seed.ts`, **không** cần migration seed. Thiếu label VI thì description fallback
  về chính key.
- Comment cột bằng tiếng Anh.
