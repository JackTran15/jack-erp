# T-01-05 — Đường ghi qua CommandBus

## Context

Dùng `CommandBus` dù skill `cqrs-search-endpoint` ghi ngược lại — lý do và hệ quả ở ADR-02.
Idempotency **không** đổi: `IdempotencyInterceptor` toàn cục chặn ở tầng HTTP, độc lập CQRS.

| Method | Route | Command | Permission |
| --- | --- | --- | --- |
| POST | `/v2/promotions` | `CreatePromotionCommand` | `promotion.write` |
| PUT | `/v2/promotions/:id` | `UpdatePromotionCommand` | `promotion.write` |
| POST | `/v2/promotions/:id/duplicate` | `DuplicatePromotionCommand` | `promotion.write` |
| PATCH | `/v2/promotions/:id/status` | `ChangePromotionStatusCommand` | `promotion.write` |
| DELETE | `/v2/promotions/:id` | `DeletePromotionCommand` | `promotion.delete` |

## Implementation notes

- **Một** DTO phẳng với `@ValidateIf` theo `type`, không discriminated union — union làm
  OpenAPI generator sinh type khó dùng ở FE, và form FE vốn là một `ProgramFormState` phẳng.
- DTO phải khai **mọi** trường của cả 5 hình thức: global `ValidationPipe` chạy
  `whitelist: true, forbidNonWhitelisted: true`, thiếu một trường là FE bị 400 khó hiểu.
- Validate theo `type` chạy ở **domain** (`PromotionProgram.create`), không nhân bản vào DTO.
  DTO chỉ validate kiểu/format.
- `rethrowDomainError(e)` map `DomainValidationError → BadRequestException` với body
  `{ message, issues: [{ field, code, message }] }`. Helper dùng chung, **không** exception
  filter toàn cục (sẽ ảnh hưởng module khác).
- `create` sinh `code` qua `DocumentNumberingService`; client **không** gửi `code`. Luôn đặt
  `status = TRACKING` (bản ghi mới không có radio trạng thái).
- `update` từ chối đổi `type` → 400 `PROMOTION_TYPE_IMMUTABLE` (A-11).
- `duplicate` sao chép trọn aggregate, cấp `code` mới, `status = TRACKING`, tên
  `<tên gốc> (sao chép)`; **không** sao `id`/`createdAt`/`createdBy`.
- `delete` là soft delete + hook `assertNotReferenced()` kiểm `invoice_promotions.ref_id` —
  hiện luôn rỗng vì POS chưa nối, đặt sẵn để epic POS không quên (A-17).
- CTKM của tổ chức khác → **404**, không phải 403.
- `@UseGuards(PermissionGuard)` cấp class + `@RequirePermission` từng method; `AuthGuard` đã
  đăng ký toàn cục qua `APP_GUARD`. **Không** để `@RequirePermission` bị comment.
