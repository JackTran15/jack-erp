# T-01-02 — Force the save path and new-program default to ALL_ITEMS

## Context

Two places still let a stale `NON_PROMO_ONLY` value survive even after the radio is
removed from the UI (T-01-01): the new-form default, and the save-path mapper that reads
whatever is sitting in `form.applyScope`. Both must be pinned to `ALL_ITEMS` so AC-01 (new
program) and AC-02 (re-saving an old `NON_PROMO_ONLY` program forces `ALL_ITEMS`) hold even
though nothing in the UI can change `form.applyScope` anymore.

## Implementation notes

- `program-form.constants.ts:209` — `buildInitialFormState()`'s `applyScope:
  ApplyScope.NON_PROMO_ONLY` becomes `applyScope: ApplyScope.ALL_ITEMS`.
- `promotion.mapper.ts` — `invoiceDiscountToDto()` (~line 520-530) currently sends
  `invoiceScope: applyScopeToApi(form.applyScope)`. Change it to send
  `invoiceScope: PromotionInvoiceScope.ALL_ITEMS` unconditionally, ignoring
  `form.applyScope`. This is what makes AC-02 hold even for a program whose
  `invoiceDiscountFromDetail()` hydration loaded a stale `NON_PROMO_ONLY` into
  `form.applyScope` from the DB on open — the save path must not trust that value anymore.
- Leave `invoiceDiscountFromDetail()` (~line 532-544) as-is: it still hydrates
  `form.applyScope` from `detail.invoiceScope` for round-trip fidelity of whatever the form
  briefly holds in memory. There is no UI left that reads it for display (T-01-01 replaced
  that with a static label), so this is inert, not incorrect — do not delete it, deleting it
  is out of scope for this ticket and not needed to satisfy any AC.
- Leave `applyScopeToApi` / `applyScopeFromApi` helper functions in place; only the call
  site in `invoiceDiscountToDto` changes.
- No backend change. `PromotionInvoiceScope.ALL_ITEMS` already exists and the engine already
  honors it (`invoice-discount.strategy.ts:37-38`, unmodified).

## Done when

- [x] Creating a brand-new invoice-discount program via the form persists
      `invoiceScope: ALL_ITEMS` with zero manual interaction (AC-01)
- [x] Opening an existing program stored with `invoiceScope: NON_PROMO_ONLY` and saving it
      again (no field changed) persists `invoiceScope: ALL_ITEMS` (AC-02)
- [x] A program that is never opened/re-saved through the form is untouched — verified by
      not adding any backfill/migration logic in this ticket (AC-03, A-03)
