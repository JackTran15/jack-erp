# T-01-03 — Tests for the scope-lock behaviour + AC-03 regression proof

## Context

AC-01/AC-02 are FE mapper-level assertions (no radio to click, so the meaningful test is on
`invoiceDiscountToDto`, not on rendered markup). AC-03 is a pure regression claim about
backend code this UoW never touches — proving it means confirming the existing suite still
passes unmodified, not writing a new test for unchanged behavior.

## Implementation notes

- In `promotion.mapper.spec.ts`, add/extend a case for `invoiceDiscountToDto()`: given a
  `ProgramFormState` with `applyScope: ApplyScope.NON_PROMO_ONLY` (simulating a loaded old
  program, T-01-02 deliberately does not stop this from being possible in memory), assert
  the emitted DTO's `invoiceScope` is `PromotionInvoiceScope.ALL_ITEMS` regardless — this is
  the concrete proof for AC-01/AC-02, since it exercises exactly the "ignore form state, send
  ALL_ITEMS" behavior T-01-02 implements.
- Run via `npx vitest run apps/backoffice-web/src/pages/promotions/api/promotion.mapper.spec.ts`
  (this directory's existing spec files already follow this convention;
  `apps/backoffice-web/package.json`'s `test` script is a no-op `echo test`, unrelated to
  whether the spec file itself runs).
- For AC-03: do **not** write a new backend test. Run the existing
  `invoice-discount.strategy.spec.ts` suite (`pnpm --filter @erp/api test -- invoice-discount.strategy.spec.ts`)
  and confirm it is green and unmodified by this feature — that file already covers the
  `NON_PROMO_ONLY` branch of `invoice-discount.strategy.ts:37-38`, and this UoW does not
  touch that file, so a passing run is the regression proof.
