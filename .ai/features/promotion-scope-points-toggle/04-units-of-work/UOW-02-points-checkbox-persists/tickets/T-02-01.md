# T-02-01 — Migration: add `accrue_points` to `promotion_programs`

## Context

New boolean column, `not null default false` — but that default governs NEW rows only.
Confirmed by Akenzy via AI-DLC discovery Q&A, 2026-08-17: existing, already-live
invoice-discount programs must be backfilled to `true` (points keep accruing exactly as
today) so the migration does not silently zero out points on every live promotion the
moment it runs. Only programs created *after* this ships default to `false`. See
`03-logical-design.md`'s "Migration impact" note for the reasoning this decision resolves.
Per `CLAUDE.md`, this repo hand-writes migrations rather than using `migration:generate`
(diff-generation produces large drift here). Mirror the shape of
`apps/api/src/database/migrations/1788700000000-AddWarehouseVoucherRevision.ts`.

Timestamp `1788900000000` is chosen because it is greater than the latest existing migration
at plan time, `1788800000000-AddSupplierDebtOverpaidStatus.ts` — re-check
`apps/api/src/database/migrations/` immediately before implementing, in case another
migration has landed on `main`/`feat/promotions` since this plan was written, and bump the
timestamp (and the filename/class name) accordingly if so.

## Implementation notes

```ts
import { MigrationInterface, QueryRunner } from 'typeorm';

export class AddPromotionProgramAccruePoints1788900000000
  implements MigrationInterface
{
  name = 'AddPromotionProgramAccruePoints1788900000000';

  public async up(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(`
      ALTER TABLE "promotion_programs"
      ADD COLUMN IF NOT EXISTS "accrue_points" boolean NOT NULL DEFAULT false
    `);
    // Backfill: rows that existed before this migration keep today's behavior (points
    // accrue) until an admin explicitly opts one out via the new checkbox. The column
    // DEFAULT stays false so programs created AFTER this migration default to off, per
    // the "Default là không tích điểm" business rule for new programs. Confirmed by
    // Akenzy, 2026-08-17 — see 03-logical-design.md "Migration impact".
    await queryRunner.query(`
      UPDATE "promotion_programs" SET "accrue_points" = true
    `);
    await queryRunner.query(`
      COMMENT ON COLUMN "promotion_programs"."accrue_points" IS
        'Whether this promotion program allows the invoice it applies to earn loyalty points. Default false for programs created after 2026-08-17; existing programs were backfilled to true to preserve their pre-existing points behavior. Only meaningful for INVOICE_DISCOUNT-type programs today.'
    `);
  }

  public async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(`
      ALTER TABLE "promotion_programs" DROP COLUMN IF EXISTS "accrue_points"
    `);
  }
}
```

- Resolved: existing rows are backfilled to `true` in the same migration so live promotion
  programs keep accruing points exactly as they do today; only new programs (created after
  this ships) default to `accrue_points = false`. See `03-logical-design.md`'s "Migration
  impact" note — decision confirmed by Akenzy, 2026-08-17.
