# T-02-03 — Domain aggregate field + entity↔domain mapper

## Context

`PromotionProgram` is an immutable aggregate root built via a private constructor + static
`create()` factory (`promotion-program.ts:237` on). `promotion.mapper.ts`'s `toDomain()`
(line 119-177) builds a `PromotionProgramProps` from a persisted row and calls
`PromotionProgram.create(props)`; `toPersistence()` (line 193 on) does the reverse. Both
already carry `invoiceScope` at the exact sites this ticket mirrors.

## Implementation notes

`promotion-program.ts`:
- Add `accruePoints: boolean;` to `PromotionProgramProps` (next to `invoiceScope?`, line
  ~45), to the class's `readonly` field declarations (next to `readonly invoiceScope?`,
  line ~259-260), to the constructor assignment (next to `this.invoiceScope = ...`, line
  ~298-299), and to the `toProps()`-style reconstruction near line ~352-353 (next to
  `invoiceScope: this.invoiceScope`).
- No new validation rule in `create()` — it is an unconstrained boolean, unlike
  `discountValue`'s conditional `validateDiscountAmount` call.

`promotion.mapper.ts`:
- `toDomain()` (line 119-177): add `accruePoints: row.program.accruePoints,` to the `props`
  object (next to `invoiceScope: fromDb(row.program.invoiceScope)`, line 158) — no
  `fromDb()`/`toDomainNumber()` wrapper needed, it's a plain boolean passthrough, unlike the
  nullable-enum fields around it.
- `toPersistence()` (line 193 on): add `program.accruePoints = aggregate.accruePoints;`
  (next to `program.invoiceScope = nullify(aggregate.invoiceScope)`, line 226) — again a
  direct assignment, no `nullify()` wrapper (the domain field is never `undefined`/`null`).

## Done when

- [x] `PromotionProgram.create(props)` accepts and exposes `accruePoints: boolean`
- [x] `toDomain()` / `toPersistence()` round-trip `accruePoints` without loss
- [x] `pnpm --filter @erp/api build` compiles clean

Deviation: making `accruePoints` non-optional on `PromotionProgramProps` broke compilation of
every existing call site that hand-builds those props (7 spec files + the shared
`promotion-fixture.ts` test builder), plus `promotion-dto.mapper.ts`'s `dtoToProgramProps()`
(T-02-04's file) which also builds the same props type. Fixed all of them here as orphan
cleanup (each a 1-line `accruePoints: false` addition) so `pnpm --filter @erp/api build`
actually compiles clean, per this ticket's own done-when — T-02-04 was implemented in the
same pass for that reason; see T-02-04 for its own done-when tally.
