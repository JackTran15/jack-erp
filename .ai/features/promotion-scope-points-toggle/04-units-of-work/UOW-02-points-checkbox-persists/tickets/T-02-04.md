# T-02-04 — Application DTOs: create/update request, DTO→props mapper, response DTO

## Context

Three sites carry `invoiceScope` through the application layer's request/response contract;
`accruePoints` needs the same three additions, at the same spots, following the same
"INVOICE_DISCOUNT only" annotation convention already used for `invoiceScope`/`discountMode`.

## Implementation notes

`create-promotion.dto.ts` (same DTO class serves create and update — verified against how
`invoiceScope` is declared once), next to `invoiceScope` (line 250-253):

```ts
@ApiPropertyOptional({ default: false, description: 'INVOICE_DISCOUNT only' })
@IsOptional()
@IsBoolean()
accruePoints?: boolean;
```

`promotion-dto.mapper.ts` (line ~104, DTO → domain props): add
`accruePoints: dto.accruePoints ?? false,` next to `invoiceScope: dto.invoiceScope,` — the
`?? false` matters here (unlike `invoiceScope`, which stays `undefined` when absent) because
the domain field is a non-nullable `boolean`, and an update DTO that omits the field entirely
must not leave the aggregate holding `undefined`.

`promotion-program.response.dto.ts`'s `toDetail()` (line 100-140): add
`accruePoints: program.accruePoints,` next to `invoiceScope: program.invoiceScope,`
(line 124) — the FE form needs this to render the checkbox's current state.
