# T-02-05 — FE checkbox: state field, component, form wiring, mapper

## Context

Mirrors `AutoApplyCheckbox` (`_PromotionSections/AutoApplyCheckbox/AutoApplyCheckbox.tsx`) —
the closest existing pattern: a standalone checkbox component taking `{ checked, onChange }`,
rendered directly inside `PromotionInvoiceDiscount.tsx`. Per ADR-03, this checkbox is
invoice-discount-only; do not add it to `PromotionProductDiscount.tsx`,
`PromotionTieredDiscount.tsx`, `PromotionBuyGet.tsx`, or `PromotionGift.tsx`.

## Implementation notes

`program-form.types.ts`: add `accruePoints: boolean;` to `ProgramFormState` next to
`applyScope: ApplyScope;` (line 216).

`program-form.constants.ts`: `buildInitialFormState()` gets `accruePoints: false,` (default
OFF per AC-04).

New file `AccruePointsCheckbox.tsx`, copying `AutoApplyCheckbox.tsx`'s shape exactly:

```tsx
interface Props {
  checked: boolean;
  onChange: (checked: boolean) => void;
}

/** Checkbox "Tích điểm cho khách hàng" — chỉ dùng ở form Giảm giá hóa đơn (invoice-discount). */
export function AccruePointsCheckbox({ checked, onChange }: Props) {
  return (
    <label className="mt-4 flex cursor-pointer items-center gap-2 text-sm">
      <input
        type="checkbox"
        className="h-4 w-4 cursor-pointer rounded border border-input accent-primary"
        checked={checked}
        onChange={(e) => onChange(e.target.checked)}
      />
      Tích điểm cho khách hàng
    </label>
  );
}
```

`PromotionInvoiceDiscount.tsx`: import and render `<AccruePointsCheckbox checked={form.accruePoints}
onChange={(v) => onChange({ accruePoints: v })} />` — place it near
`<ApplyScopePromotionSection .../>` (line 41) inside the `"km"` tab, matching the intent
doc's framing that this checkbox sits in the same section context as the scope lock.

`promotion.mapper.ts`:
- `invoiceDiscountToDto()` (line 520-530): add `accruePoints: form.accruePoints,` to the
  returned partial.
- `invoiceDiscountFromDetail()` (line 532-544): add
  `base.accruePoints = detail.accruePoints ?? false;`.

**Write-conflict note:** this ticket and T-01-02 both edit `promotion.mapper.ts`'s
`invoiceDiscountToDto`/`invoiceDiscountFromDetail`. They are logically independent (see
UOW-01/UOW-02's own risk rows) but must not be implemented on parallel agents without
sequencing — `uow_graph.py --parallel` flags this pair explicitly.

## Done when

- [x] New invoice-discount program form shows the checkbox unchecked by default (AC-04)
- [x] Checking it, saving, and reopening the program in edit mode shows it still checked
      (AC-05)
- [x] `PromotionProductDiscount`, `PromotionTieredDiscount`, `PromotionBuyGet`,
      `PromotionGift` do not render the checkbox
- [x] `pnpm --filter @erp/backoffice-web build` compiles clean

AC-04/AC-05 mechanism: `buildInitialFormState()` sets `accruePoints: false`;
`invoiceDiscountToDto()` emits `form.accruePoints` on save; `invoiceDiscountFromDetail()`
hydrates `base.accruePoints = detail.accruePoints ?? false` on reopen — same round-trip
already live-verified against a real API in T-02-04's evidence (POST with
`accruePoints: true` → 201 echoed `true` → GET returned `true`). Isolation confirmed via
`grep -rl AccruePointsCheckbox apps/backoffice-web/src/pages/promotions/` — only
`PromotionInvoiceDiscount.tsx` renders it. Dedicated FE assertions are T-02-06's ticket.
