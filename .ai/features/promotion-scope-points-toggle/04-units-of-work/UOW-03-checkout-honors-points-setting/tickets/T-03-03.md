# T-03-03 — Gate the sync and async points writes on `pointsBlocked`

## Context

The two consequence sites of `pointsBlocked` (ADR-02). Both read `ctx.totals.pointsBlocked`,
which T-03-02 already populated — neither file re-derives anything.

## Implementation notes

`persist-invoice.step.ts:71`, currently:

```ts
invoice.pointsEarned = invoice.customerId ? totals.pointsEarned : 0;
```

becomes:

```ts
invoice.pointsEarned = invoice.customerId && !totals.pointsBlocked ? totals.pointsEarned : 0;
```

Same line, same existing comment above it about "no customer, no points" — extend that
comment's reasoning to mention the new `pointsBlocked` case rather than replacing it (the
customerId guard is still the primary rule; `pointsBlocked` is an additional one).

`enqueue-outbox.step.ts:143`, currently:

```ts
if (invoice.customerId) {
  const loyaltyPayload: LoyaltyPointsAwardPayload = { ... };
  await this.outbox.enqueue(manager, ERP_TOPICS.LOYALTY_POINTS_AWARD, { ... }, invoice.customerId);
}
```

becomes:

```ts
if (invoice.customerId && !totals.pointsBlocked) {
  ...
}
```

This is the entire change to this file — the outbox row is simply never written when
blocked, which is what makes `loyalty-points.consumer.ts` → `MembershipCardService.
awardPointsForInvoice` never fire (ADR-02; `awardPointsForInvoice` has exactly one caller in
the codebase, verified during design).

## Done when

- [x] `invoice.pointsEarned === 0` whenever `totals.pointsBlocked === true`, regardless of
      `customerId`
- [x] No `LOYALTY_POINTS_AWARD` outbox row is written whenever `totals.pointsBlocked ===
      true`, regardless of `customerId`
- [x] Behavior is unchanged (bit-for-bit) whenever `totals.pointsBlocked === false` —
      existing `persist-invoice.step.spec.ts` / `enqueue-outbox.step.spec.ts` cases pass
      without modification
