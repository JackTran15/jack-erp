# T-03-04 — Sync-path tests: `pointsBlocked` → `invoice.pointsEarned`

## Context

Covers the synchronous half of AC-06 through AC-11 — everything observable on `ctx.totals`
and `invoice.pointsEarned` without needing a live Kafka consumer.

## Implementation notes

In `preflight-steps.spec.ts` (covers `compute-totals.step.ts`), add cases for:
- One applied program, `accruePoints: false` → `ctx.totals.pointsBlocked === true` (AC-06
  groundwork).
- One applied program, `accruePoints: true` → `pointsBlocked === false` (AC-08 groundwork).
- Two applied programs, one `true` one `false` → `pointsBlocked === true` (AC-09
  groundwork — "any unchecked wins").
- Two applied programs, both `true` → `pointsBlocked === false` (AC-10 groundwork).
- No applied programs (`ctx.promotion` undefined or `appliedPrograms: []`) → `pointsBlocked
  === false` (AC-11 groundwork — regression, unaffected by this feature).

In `persist-invoice.step.spec.ts`, add cases for:
- `totals.pointsBlocked = true`, `invoice.customerId` set → `invoice.pointsEarned === 0`
  (AC-06, AC-09).
- `totals.pointsBlocked = false`, `invoice.customerId` set → `invoice.pointsEarned ===
  totals.pointsEarned` unchanged (AC-08, AC-10, AC-11 — this is the existing behavior,
  confirm it is unaffected).
- Existing "no customerId → 0" case (already covered) still passes unmodified.
