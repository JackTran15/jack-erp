# T-01-05 — Test đầu-cuối cho đơn đổi trả nhanh có KM dòng

## Context

AC-05 là regression guard quan trọng nhất của UoW này: sửa cách tính `returnSubtotal` mà
làm lệch số hoàn của đơn đổi trả **theo hoá đơn gốc** thì hỏng nặng hơn bug đang sửa.

## Implementation notes

- E2E: tạo đơn đổi trả nhanh đúng số liệu ca thật (460.000 trả / 685.000 KM 30% mua thêm,
  không customerId, thu 19.500) → 200, `net_amount = 19.500`
- E2E: đơn đổi trả **theo hoá đơn gốc** — bán một hoá đơn có KM, trả một dòng, khẳng định
  số hoàn bằng đúng giá trị trước khi sửa (prorate qua `refundableUnitValues`)
- Chạy nối tiếp (`maxWorkers: 1`) như phần còn lại của e2e; đọc output thật, đừng tin exit code

## Kết quả

`apps/api/test/e2e/quick-exchange-line-discount.e2e-spec.ts` — **5/5 test pass**, dựng trên
`buildCheckoutSagaFixture` sẵn có (COA + quỹ tiền mặt + payment_accounts + hàng có tồn).

- AC-01: đơn đổi nhanh khách lẻ, OUT 685.000 −30% / IN 460.000 → draft `netAmount 19.500`,
  `checkout-return` với 19.500 tiền mặt trả 201, DB `net_amount = 19.500`, `status = paid`,
  dòng OUT lưu `percent/30/sale30`, `line_discount 205.500`, `line_total 479.500`
- AC-02: KM 10% trên dòng trả → `line_total 450.000`, `netAmount 150.000`
- AC-03: net âm (−120.500) hoàn tiền mặt, **không** đòi customerId
- AC-04: đơn trả thuần KM 30.000 → hoàn 270.000
- AC-05 (regression): bán 685.000 −30% qua luồng bán v1 rồi trả dòng đó theo hoá đơn gốc →
  hoàn **479.500** (số khách thực trả) chứ không phải 685.000 — prorate qua
  `refundableUnitValues` không đổi

**Suite exit code 1 nhưng không có test nào đỏ**: `QueryFailedError: relation "outbox_messages"
does not exist` ném từ `OutboxRelayService.pollOnce` — poller nền đua với `resetDatabase()`
lúc teardown. Đúng cái bẫy e2e đã biết của repo; đọc kết quả test, đừng đọc exit code.
