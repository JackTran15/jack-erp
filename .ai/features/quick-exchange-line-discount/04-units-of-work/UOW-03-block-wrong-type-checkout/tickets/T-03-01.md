# T-03-01 — Guard type SALE ở cả hai luồng checkout

## Context

Cả hai luồng tất toán đơn bán chỉ kiểm `isDraft`/`status`, không kiểm `type`:
`checkout-invoice.service.ts:238` (v1) và `load-draft.step.ts:88` (saga v2). Đó là mắt xích
cuối để một phiếu nháp EXCHANGE trở thành hoá đơn phát hành có `net_amount` mồ côi
(ADR-02).

## Implementation notes

- Thêm điều kiện `invoice.type !== InvoiceType.SALE` vào đúng chỗ đang kiểm `isDraft`
- Saga v2: đặt **sau** nhánh `isCompletedReplay` để không chặn nhầm một replay idempotent
- Dùng lại code lỗi `INVOICE_NOT_CHECKOUTABLE` sẵn có, thông điệp tiếng Anh, nêu rõ
  `type` và gợi ý dùng `/checkout-return`
- Log warn kèm `invoiceId` + `type` bị từ chối — dấu hiệu còn client cũ chạy đường vòng
- Không đụng `CheckoutReturnService`

## Done when

- [x] Draft EXCHANGE gọi `/checkout` → 400 `INVOICE_NOT_CHECKOUTABLE`, phiếu vẫn `is_draft = true`, chưa tiêu số chứng từ
- [x] Draft RETURN cũng bị từ chối
- [x] Draft SALE tất toán bình thường ở cả v1 và saga v2
- [x] Replay idempotent của một checkout SALE đã hoàn tất vẫn trả lại kết quả cũ, không bị guard chặn

## Kết quả

- Guard `invoice.type !== InvoiceType.SALE` thêm vào `checkout-invoice.service.ts:126`
  (kèm `logger.warn` nêu id + type) và `load-draft.step.ts:74` (đặt SAU nhánh
  `isCompletedReplay` để replay idempotent không bị chặn nhầm)
- Trả `BadRequestException` với code `INVOICE_NOT_CHECKOUTABLE` sẵn có, thông điệp tiếng Anh
- Phát hiện kèm: stub trong `checkout-invoice.service.spec.ts` và `preflight-steps.spec.ts`
  không có cột `type` — trong khi schema là NOT NULL default SALE. Đã bổ sung
  `type: InvoiceType.SALE` vào các stub đó (5 chỗ), không đổi ý nghĩa test nào
