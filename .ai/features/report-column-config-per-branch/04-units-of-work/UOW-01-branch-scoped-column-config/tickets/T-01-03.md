# T-01-03 — Đường đọc của miền kho

## Context

`ListInventoryReportTemplatesHandler` và `GetInventoryReportTemplateHandler` hiện lọc đúng
`{ organizationId }` (và `reportType` nếu có). Sau ticket này chúng đọc theo phạm vi: hàng của
chi nhánh đang đứng **hợp** với hàng cấp chuỗi, rồi chọn ưu tiên trên RAM (ADR-01).

NFR: vẫn **một** câu SELECT. Không được thêm truy vấn thứ hai để tra bản chuỗi.

## Implementation notes

- Cả hai Query object nhận thêm `scope?: TemplateScope` (tham số cuối, tuỳ chọn — giữ nguyên
  thứ tự tham số hiện có để không phải sửa nơi gọi khác).
- Controller: `@Query('scope') scope?: TemplateScope` trên `GET templates` và `GET templates/:id`.
  Route và permission (`RequirePermission`) giữ nguyên.
- List handler:
  ```
  const resolved = resolveTemplateScope(scope, actor);
  const rows = await this.repo.find({
    where: readScopeWhere(actor, resolved).map(w => ({ ...w, ...(reportType ? { reportType } : {}) })),
    order: { sortOrder: 'ASC', createdAt: 'DESC' },
  });
  return pickEffective(rows, resolved).map(toTemplateView);
  ```
  `readScopeWhere` trả **mảng** điều kiện — TypeORM hiểu mảng là OR; phải rải `reportType`
  vào từng phần tử, đặt ngoài mảng là mất bộ lọc ở nhánh thứ hai.
- Get handler: `findOne` với `readScopeWhere(...)` + `id` rải vào từng nhánh; không thấy → giữ
  nguyên `NotFoundException('Inventory report template not found')`. Hàng của chi nhánh khác
  rơi ra ngoài vị từ nên tự động 404 (AC-11).
- Không đụng bốn miền còn lại trong ticket này (UOW-03).

**Đo trên API thật ở :4000, dữ liệu `erp_dev`** (tổ chức `f1000000…01`, hai chi nhánh
Hồ Chí Minh `c3bf1922…` và Hà Nội `09743ddb…`, token Hà Nội):

| Gọi | Kết quả |
| --- | ------- |
| `?reportType=inventory-stock-summary&scope=branch` | `f1b8859f` / `branch` / `09743ddb` — đúng bản của Hà Nội, **một** dòng dù bản chuỗi cùng `(reportType, name)` vẫn tồn tại |
| `…&scope=chain` | `b0c36b2f` / `chain` — chỉ bản chuỗi |
| `GET /templates/{bản của HCM}` bằng token Hà Nội | **404** — AC-11 |
| `GET /templates/{bản chuỗi}` bằng token Hà Nội | **200**, `scope: chain` — AC-11 |
| Xoá mềm bản của Hà Nội rồi list lại | `b0c36b2f` / `chain` — kế thừa đúng, AC-03 (đã khôi phục sau khi đo) |

- Handler kho có bộ lọc riêng `reportType ?? In(registry.list())` vì bảng này dùng chung với
  miền hoá đơn. Bộ lọc đó phải **rải vào từng phần tử** của mảng `readScopeWhere`; treo ngoài
  mảng thì nhánh chuỗi hết bị lọc và template hoá đơn lọt sang route kho. Có một ca test riêng
  khẳng định đúng chuyện này.
- `/auth/switch-branch` **thu hồi phiên cũ** — token trước khi đổi chi nhánh trả
  `4014002 Session revoked or expired`. Đo hai chi nhánh thì phải làm tuần tự, không giữ hai
  token song song.
- Không bật được `pg_stat_statements` (cần `shared_preload_libraries`, phải dựng lại container),
  nên "đúng 1 SELECT" khẳng định bằng `expect(repo.find).toHaveBeenCalledTimes(1)` trong spec —
  bền hơn đọc log, và chạy lại được ở CI.
