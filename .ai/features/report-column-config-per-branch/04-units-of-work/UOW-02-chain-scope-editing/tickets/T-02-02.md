# T-02-02 — Nối chế độ chuỗi vào scope

## Context

T-01-05 đã kéo `scope` xuyên suốt ba lời gọi và khoá cache, nhưng đóng cứng `"branch"`.
Ticket này đổi nguồn giá trị. Toàn bộ thay đổi nằm trong một file.

## Implementation notes

- `const scope: TemplateScope = useIsChainSelected() ? "chain" : "branch";`
  Import từ `../../../../store/common/branch/branch.store`.
- Dùng đúng `useIsChainSelected()`, **không** đọc `useBranchStore(s => s.isChain)`: selector
  đã gộp sẵn `canViewChain()`, còn `isChain` thô thì persist trong localStorage và có thể
  đúng ở một tài khoản đã mất quyền — khi đó UI hiện chế độ chi nhánh nhưng request lại gửi
  `scope=chain`.
- `enabled` của query giữ nguyên (`TEMPLATE_SOURCES` + `backendKey`).
- Ở chế độ chuỗi, `branchId` trong `queryKey` vẫn giữ nguyên giá trị chi nhánh cuối — vô hại
  vì `scope` đã tách khoá; đừng bỏ nó đi, cần cho lúc quay về chế độ chi nhánh.

## Done when

- [x] Ở chế độ "Toàn chuỗi": list request mang `scope=chain`; POST/PATCH body mang `scope: "chain"` — AC-05
- [x] Đổi qua lại chuỗi ↔ chi nhánh **không reload trang** vẫn nạp đúng bố cục của từng phạm vi (`queryKey` mang `scope`)
- [x] Tài khoản không có quyền xem chuỗi luôn gửi `scope=branch`
- [x] `pnpm --filter @erp/backoffice-web build` sạch

## Ghi chú khi làm

- **Đổi nguồn so với kế hoạch:** dùng `useReportStore(s => s.branch) === STORE_TYPE.CHAIN`
  thay vì gọi `useIsChainSelected()` lần nữa. `ReportPage` đã suy `branch` **từ chính**
  `useIsChainSelected()` (đã gộp sẵn `canViewChain()`) rồi bơm vào report store, nên hai giá
  trị không thể lệch nhau — mà lấy từ report store thì hook không phải thêm phụ thuộc vào
  branch store cho việc này. Cảnh báo trong kế hoạch (đừng đọc `s.isChain` thô) vẫn đúng và
  vẫn được tôn trọng: `s.branch` kế thừa đúng cái guard đó.
- `branchId` vẫn lấy từ `useBranchStore` cho khoá cache — hai thứ khác nhau, đừng gộp.
