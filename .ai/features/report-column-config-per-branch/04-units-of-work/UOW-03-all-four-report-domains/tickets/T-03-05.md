# T-03-05 — Spec đối chiếu bốn miền

## Context

Rủi ro thật của UOW-03 không phải "làm sai" mà là "làm sót": bốn miền, hai mươi handler, sót
một cái thì miền đó âm thầm ghi theo chuỗi và lỗi chỉ lộ ở tổ chức có nhiều chi nhánh. Spec
này chạy **cùng một bộ ca** qua cả bốn bộ handler bằng một bảng tham số.

## Implementation notes

- Bảng tham số: `[{ domain: 'inventory', List, Get, Create, Update, Delete }, { domain: 'invoice', … }, …]`
  rồi `describe.each`. Mock `Repository<ReportTemplateEntity>` như các spec sẵn có.
- Bộ ca tối thiểu cho mỗi miền:
  1. list, chi nhánh chưa có bản riêng → trả bản chuỗi
  2. list, chi nhánh có bản riêng → trả bản riêng, không trả kèm bản chuỗi trùng
  3. get, id của chi nhánh khác → `NotFoundException`
  4. update, bản chuỗi + `scope='branch'` → `repo.save` nhận entity không có `id`
  5. delete, bản chuỗi + `scope='branch'` → `NotFoundException`, `softRemove` không được gọi
- Thêm một ca "canh gác" quét mã nguồn: đọc 20 file handler và khẳng định không file nào còn
  chuỗi `where: { id, organizationId: actor.organizationId }` trần. Rẻ, và bắt được đúng kiểu
  lỗi sót mà bảng tham số không thấy nếu ai đó thêm miền thứ năm.
