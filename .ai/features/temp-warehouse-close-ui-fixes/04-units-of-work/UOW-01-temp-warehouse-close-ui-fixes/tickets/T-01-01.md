# T-01-01 — Fix FastStockTransferPage scroll clipping

## Context

`FastStockTransferPage.tsx` renders inside `PosLayout`'s
`flex h-[100dvh] flex-col overflow-hidden` shell, below a sticky header. Its
root div currently claims a fixed `h-screen` (100vh) instead of filling the
space `PosLayout` actually leaves it, so it overflows by roughly the header's
height — and `PosLayout`'s `overflow-hidden` clips that excess instead of
letting it scroll. `FastStockTransferTable`'s own `overflow-auto` wrapper
never sees the real remaining height, so the last row(s) sit in the clipped
region and can't be scrolled into view. See ADR-01 in `03-logical-design.md`.

## Implementation notes

- In `apps/pos-web/src/pages/FastStockTransferPage.tsx`, change the root div's
  className from `flex h-screen flex-col bg-white` to
  `flex min-h-0 flex-1 flex-col overflow-hidden bg-white` — the same
  fill-remaining-space pattern `DailyReportPage.tsx` already uses.
- Do not touch `PosLayout.tsx`, `PosDataTable.tsx`, or
  `FastStockTransferTable.tsx` — the existing `min-h-0 flex-1 overflow-auto`
  wrapper around the table is already correct once its parent stops
  overflowing.
- `ReturnGoodsPage.tsx` and `InvoiceListPage.tsx` carry the same `h-screen`
  pattern (A-02) — leave them alone, out of scope for this ticket.
