# T-01-02 — Default "Đóng kho tạm" dialog to "Không xử lý"

## Context

`FastStockTransferDiscrepancyDialog` initializes its `closeMode` state to
`TempWarehouseCloseMode.NET_OFFSET` ("Xuất đi/Trả lại kho tạm"). It should
default to `TempWarehouseCloseMode.NONE` ("Không xử lý") instead, so closing a
temp warehouse doesn't default into an offset/transfer action.

The dialog is always mounted (`open` is a boolean prop passed from
`FastStockTransferDialogs.tsx`, not conditional JSX), so this `useState`
initializer only runs once per page session, on first mount — this ticket
changes only that initial value. Per A-03 (confirmed), the last-picked option
is still remembered across cancel/reopen within the same session, unchanged
from today's behavior.

## Implementation notes

- In `FastStockTransferDiscrepancyDialog.tsx`, change:
  `useState<TempWarehouseCloseMode>(TempWarehouseCloseMode.NET_OFFSET)` →
  `useState<TempWarehouseCloseMode>(TempWarehouseCloseMode.NONE)`.
- `TempWarehouseCloseMode.NONE` is unconditionally included in
  `CLOSE_MODE_OPTIONS` (not filtered by `netOffsetEligible`), so no other
  change is needed to keep the selection valid.
- Do not touch the `netOffsetEligible` reset `useEffect` (lines 65–72) — it
  must keep resetting away from `NET_OFFSET` to `CREATE_TRANSFERS` exactly as
  it does today (AC-04).
