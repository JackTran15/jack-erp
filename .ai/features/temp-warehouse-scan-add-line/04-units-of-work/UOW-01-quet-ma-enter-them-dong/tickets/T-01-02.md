# T-01-02 — Hàm thuần `decideScanOutcome`

## Context

Phím Enter hiện quyết định dựa trên `toolbarDraft.product` đọc từ closure React đã cũ,
nên khi máy quét gửi Enter ngay sau chuỗi ký tự thì nó thấy `null` và không làm gì.
Bảng quyết định thật ra không cần biết gì về React — tách nó ra hàm thuần vừa sửa được
lỗi gốc, vừa là **chỗ duy nhất có test tự động** trong feature này (ADR-06).

Đây là ticket "chỉ thêm file mới, không sửa file nào" — nó không tự thay đổi hành vi;
T-01-05 mới là chỗ nối dây.

## Implementation notes

- File mới `fast-stock-transfer-scan-resolve.ts`, đặt cạnh `fast-stock-transfer-draft.ts`.
- Không import React, không import store, không gọi mạng. Chỉ nhận dữ liệu và trả quyết định.

```ts
export type ScanOutcome =
  | { kind: "add"; product: PosCatalogLine }      // chọn hàng này rồi thêm dòng ngay
  | { kind: "suggest"; candidates: PosCatalogLine[] }  // mở dropdown, để người dùng chọn
  | { kind: "empty" }                             // có chữ nhưng không tra ra gì
  | { kind: "none" };                             // không có gì để làm

export function decideScanOutcome(input: {
  highlighted: PosCatalogLine | null;   // dòng đang nổi trong dropdown, nếu có
  query: string;
  candidates: PosCatalogLine[];         // kết quả đã tra (khớp tuyệt đối, hoặc gần đúng)
}): ScanOutcome;
```

Thứ tự quyết định, đúng theo bảng "Error taxonomy" trong `03-logical-design.md`:

| Điều kiện | Kết quả |
|---|---|
| `highlighted` khác null | `add(highlighted)` |
| `query.trim()` rỗng | `none` |
| `candidates.length === 1` | `add(candidates[0])` |
| `candidates.length > 1` | `suggest(candidates)` |
| còn lại | `empty` |

- Thứ tự này có ý nghĩa: `highlighted` thắng tất cả, vì người dùng đã chủ động chọn dòng
  đó bằng mũi tên (AC-07).
