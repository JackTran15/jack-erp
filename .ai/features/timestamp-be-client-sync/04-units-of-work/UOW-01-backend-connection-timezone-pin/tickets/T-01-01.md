# T-01-01 — Pin timezone option in data-source.ts and app.module.ts

## Context

Neither Postgres connection config in the API sets a `timezone` option today:

- `apps/api/src/database/data-source.ts:21-36` — the CLI `DataSource` used by
  `migration:generate` / `migration:run` / `migration:show`. The `new DataSource({ ... })`
  object currently has 6 connection fields (`type`, `host`, `port`, `database`,
  `username`, `password`) plus `entities`, `migrations`, `migrationsTransactionMode`,
  `synchronize` — no `timezone`.
- `apps/api/src/app.module.ts:64-76` — the runtime `TypeOrmModule.forRootAsync` factory.
  The object returned by `useFactory` currently has `type`, `host`, `port`, `database`,
  `username`, `password`, `autoLoadEntities`, `synchronize` — no `timezone`.

Both silently inherit the deploy host's own Postgres session timezone default. Add the
identical option to both, per ADR-01 in `03-logical-design.md`.

## Implementation notes

- `data-source.ts`: add `timezone: 'Asia/Ho_Chi_Minh',` inside the `new DataSource({ ... })`
  object — placement alongside the other connection fields (`host`, `port`, `database`,
  `username`, `password`), before `entities`.
- `app.module.ts`: add `timezone: 'Asia/Ho_Chi_Minh',` inside the object returned by
  `useFactory`, alongside `host`, `port`, `database`, `username`, `password`.
- Use the literal string `'Asia/Ho_Chi_Minh'` in both — do not introduce an env var or a
  shared constant for it; `00-intent.md` / ADR-01 explicitly reject configurability here
  (this is a fixed business fact, not something a deploy should be able to override).
- No other line in either file changes. Do not touch `migrationsTransactionMode`,
  `synchronize`, `autoLoadEntities`, or the dotenv-loading block above `data-source.ts`'s
  `DataSource` constructor.

## Done when

- [x] `apps/api/src/database/data-source.ts`'s `DataSource` config includes
      `timezone: 'Asia/Ho_Chi_Minh'`
      — DEVIATION: `PostgresConnectionOptions` in TypeORM 0.3.28 has no `timezone` field
      (that's a mysql2-only TypeORM option; confirmed by reading
      `typeorm/driver/postgres/PostgresConnectionOptions.d.ts`, which lists no such
      property, and `tsc` rejecting it with `TS2353`). Used the documented `pg`/TypeORM
      mechanism instead: `extra: { options: '-c timezone=Asia/Ho_Chi_Minh' }`, which
      `PostgresDriver.createPool` merges verbatim into the `pg.Pool` config
      (`PostgresDriver.js:1196`). Verified empirically against the live local Postgres
      (`docker compose` instance on :5433) that this sets
      `current_setting('TIMEZONE') = 'Asia/Ho_Chi_Minh'` on connect — same effect ADR-01
      specifies (`SET TIME ZONE` equivalent at connection time).
- [x] `apps/api/src/app.module.ts`'s `TypeOrmModule.forRootAsync` factory return value
      includes `timezone: 'Asia/Ho_Chi_Minh'`
      — same deviation and same `extra: { options: '-c timezone=Asia/Ho_Chi_Minh' }` fix.
- [x] `pnpm --filter @erp/api build` succeeds (no type errors)
- [x] No other line in either file is modified
      — one 3-line explanatory comment was added above the `extra` line in each file
      (matches existing file style, e.g. the `migrationsTransactionMode` comment already
      in `data-source.ts`), since the literal string the ticket assumed doesn't compile
      and the substitute needs the same kind of "why" comment already present nearby.
