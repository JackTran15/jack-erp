# T-01-02 — Regression tests proving the timezone pin survives a foreign host TZ

## Context

AC-08 requires a test that forces `process.env.TZ` to a non-Vietnam value and proves the
result is still correct — otherwise a future edit could silently drop the `timezone`
option (or a new connection could be opened elsewhere without it) and nothing would catch
it, repeating the exact bug class documented in `00-intent.md`. AC-10 requires this
feature's new tests provide the same class of protection the existing regression tests
(`apps/api/src/modules/promotion/application/date-format.util.spec.ts`,
`.../date-window.spec.ts`) already provide for date-string formatting.

Two layers of test are needed because the two config surfaces are proven differently:

1. `data-source.ts`'s `DataSource` is a plain exported object — its config is checkable
   with a static unit test, no DB connection required.
2. `app.module.ts`'s factory is inline inside `TypeOrmModule.forRootAsync` and is not
   separately exported — the only way to prove it actually sets the Postgres session
   timezone (not just that the source code contains the right string) is to boot the real
   app against a live connection, which the existing e2e harness
   (`apps/api/test/e2e/setup/test-app.ts`'s `createTestApp()`, used by every other
   `*.e2e-spec.ts` file, e.g. `cash-vouchers-phase1.e2e-spec.ts`) already does.

## Implementation notes

**Unit test — `apps/api/src/database/data-source.spec.ts`:**
- Import `AppDataSource` from `./data-source`.
- Before importing, set `process.env.TZ = 'UTC'` (or `'America/New_York'`) so the
  assertion is meaningfully independent of the host's real TZ, not just coincidentally
  correct on this machine.
- Assert `AppDataSource.options.timezone === 'Asia/Ho_Chi_Minh'`.
- Restore `process.env.TZ` to its original value after the test (`afterAll`), since Jest
  unit test files can run in the same worker as others.

**E2E test — `apps/api/test/e2e/db-connection-timezone.e2e-spec.ts`:**
- Follow the existing pattern (see `cash-vouchers-phase1.e2e-spec.ts`): import
  `createTestApp` from `./setup/test-app`, which boots the real `AppModule` (the same
  `TypeOrmModule.forRootAsync` factory this ticket's sibling, T-01-01, edits) and exposes
  the live `DataSource`.
- In a `beforeAll`, set `process.env.TZ = 'UTC'` **before** calling `createTestApp()` (the
  connection's `SET TIME ZONE` happens at connect time, so the override must be in place
  before the app boots, not just before the query runs).
- Run `await ds.query("SELECT current_setting('TIMEZONE') AS tz")` (or `SHOW TIME ZONE`)
  and assert the returned value is `Asia/Ho_Chi_Minh`.
- In `afterAll`, restore the original `process.env.TZ` and close the app — this suite runs
  with `maxWorkers: 1` (`jest-e2e.config.ts`), so a leaked `TZ` override would bleed into
  every e2e spec file that runs afterward in the same process.
- Do not call `resetDatabase()` / `seedBaseData()` — this test only needs a live
  connection, not seeded data, so skip the schema reset other specs perform to keep this
  suite fast.
