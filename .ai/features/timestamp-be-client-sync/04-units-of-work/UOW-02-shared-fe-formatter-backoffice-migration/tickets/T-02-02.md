# T-02-02 — Migrate SelectTransferReceiptDialog and SelectTransferOrderDialog date formatters

## Context

Two files declare a near-identical, un-zoned date-only formatter:

- `SelectTransferReceiptDialog.tsx:51-58` — module-scope `const dateFmt = new
  Intl.DateTimeFormat("vi-VN")` and `function formatDate(iso)` wrapping it, returning
  `"—"` for null/invalid input.
- `SelectTransferOrderDialog.tsx:63-69` — the same `dateFmt` / `formatDate` pair,
  identical behaviour.

Both files also declare an unrelated `ymd(d: Date)` helper right below `formatDate` — that
helper does local-component date math (`getMonth()`, `getDate()`, `getFullYear()`) with no
`Intl.DateTimeFormat` call and is out of scope; leave it untouched.

## Implementation notes

- Replace the module-scope `dateFmt` constant and `formatDate` function body in both files
  with a call into `@erp/ui`'s `formatViDate`. Two options, pick whichever keeps the diff
  smaller per file:
  - Delete `const dateFmt = ...` and `function formatDate(iso) { ... }`, and update call
    sites to call `formatViDate(iso)` directly (note: `formatViDate` returns `""` for
    invalid input, not `"—"` — check every call site's rendering and add a `|| "—"`
    fallback at the call site if the em-dash is relied on visually, to avoid changing
    on-screen behaviour beyond the timezone fix).
  - Or keep `formatDate(iso)` as a thin local wrapper that calls `formatViDate(iso)` and
    maps `""` back to `"—"` — smaller diff, preserves the existing local function name
    every call site already uses.
- Do not change `ymd()`, the dialog's data-fetching, or any unrelated formatting
  (`moneyFmt` in `SelectTransferReceiptDialog.tsx:51`).

## Done when

- [x] Neither file constructs its own `Intl.DateTimeFormat` instance anymore
- [x] Both route date formatting through `@erp/ui`'s `formatViDate`
- [x] The `"—"` empty/invalid-date fallback still renders exactly as before (visual
      no-op on valid input, only the timezone becomes explicit)
      — kept `formatDate(iso)` as the thin local wrapper (option 2 in the ticket),
      mapping `formatViDate`'s `""` back to `"—"`.
- [x] `pnpm --filter @erp/backoffice-web build` succeeds — verified (tsc + vite build,
      2735 modules, no errors).
