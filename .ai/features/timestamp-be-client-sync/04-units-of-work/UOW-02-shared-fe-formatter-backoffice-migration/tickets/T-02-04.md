# T-02-04 — Migrate InvoiceDetailDialog, IAM display, and stock document report formatters

## Context

Three self-contained call sites, each declaring and using its own formatter in the same
file (no separate consumer file to also touch, unlike T-02-03):

- `InvoiceDetailDialog/_lib/format.ts:14-25` — `formatDateTime(iso)`, constructs a fresh
  `Intl.DateTimeFormat("vi-VN", { day, month, year, hour, minute })` per call, returns
  `""` for null/invalid.
- `lib/iam/display.ts:26-31` — `formatIamDate(value)`, `new
  Intl.DateTimeFormat("vi-VN").format(d)` (date-only, no explicit options), returns the
  raw `value` string (not `""`) for invalid input — note this differs from the other
  call sites' fallback.
- `lib/iam/display.ts:34-42` — `formatIamDateTime(value)`, `new Intl.DateTimeFormat("vi-VN",
  { dateStyle: "short", timeStyle: "short" })`, same raw-value-on-invalid fallback as
  `formatIamDate`.
- `StockDocumentDetailsReportPage.tsx:29-33` — module-scope `const DATE_FMT = new
  Intl.DateTimeFormat("vi-VN", { day, month, year })`, used once at line 76:
  `DATE_FMT.format(posted)` inside a `Number.isNaN(posted.valueOf())` guard (no fallback
  string needed — the ternary already handles it).

## Implementation notes

- `InvoiceDetailDialog/_lib/format.ts`: replace `formatDateTime`'s body with a call to
  `@erp/ui`'s `formatViDateTime`; keep the exported function name `formatDateTime`
  (external callers of this file are untouched) as a thin wrapper, since its signature
  (`iso: string | null | undefined`) differs slightly from the shared util's
  (`Date | string`).
- `lib/iam/display.ts`: both `formatIamDate` and `formatIamDateTime` fall back to
  returning the raw input `value` (not `""`) when parsing fails — preserve that exact
  fallback behaviour when wrapping `formatViDate` / `formatViDateTime` (do not silently
  change it to `""`, since that's a user-visible behaviour change outside this feature's
  scope). Keep both exported names as thin wrappers.
- `StockDocumentDetailsReportPage.tsx`: replace the `DATE_FMT` constant with a direct call
  to `formatViDate(posted)` at its one call site (line 76); the existing
  `Number.isNaN(posted.valueOf())` guard can be dropped in favour of `formatViDate`'s own
  `""` fallback, or kept — either is fine since the visible result is the same empty
  string either way.
- Do not touch `formatMoney` / `formatQuantity` in `InvoiceDetailDialog/_lib/format.ts`,
  `joinFullName` / `splitFullName` / `userDisplayCode` / `formatAccountStatus` in
  `iam/display.ts`, or `DOC_TYPE_OPTIONS` / `DOC_KIND_LABEL` in
  `StockDocumentDetailsReportPage.tsx`.

      already exhibited the same time-first CLDR quirk `formatViDateTime` fixes (see
      T-02-01's deviation note), so delegating here is a pure win (zone-correct +
      contract-compliant `dd/MM/yyyy HH:mm` order), not a format regression.
