# T-02-02 — Áp vị ngữ chi nhánh vào `EMPLOYEE_SELECT`

## Context

`GET /cash-vouchers/partners` phục vụ **hai** ô khác nhau trên cùng một phiếu, cả hai đi
chung một endpoint:
- ô **Đối tượng** (`VoucherEntitySearchModal`, chọn được cả 3 loại)
- ô **Nhân viên thu/chi** (`VoucherStaffFields`, khoá cứng `lockedKind = EMPLOYEE`)

Sửa endpoint là cả hai ô đúng theo — đó là lý do AC-05 và AC-06 nằm chung một ticket.

Bốn màn dùng lại nó: Phiếu thu, Phiếu chi, Phiếu thu tiền gửi, Phiếu chi tiền gửi.

## Implementation notes

- Inject `EmployeeBranchScopeService` vào `PartnerLookupService`. Chỉ inject **service**;
  không import entity class nào của `rbac` — raw SQL ở file này tồn tại chính là để module
  cash-vouchers không phụ thuộc entity của module khác.
- `lookup()` gọi `resolve(actor)` trước khi dựng câu truy vấn.
- `mode: 'none'` **và** `type` là `employee` → trả `{ data: [], total: 0, page, pageSize }`
  ngay. Với `type=all` thì vẫn chạy truy vấn nhưng bỏ fragment nhân viên ra khỏi UNION.
- `mode: 'branch'` → `buildLookupQuery` (từ T-02-01) đẩy thêm `scope.branchId` vào `params`
  **chỉ khi** fragment nhân viên có mặt, và dựng vị ngữ bằng
  `employeeBranchScopeSqlPositional('u.id', `$${params.length}::uuid`)`.
- `::uuid` là bắt buộc: tham số tới Postgres dạng text, còn `uba.branch_id` là `uuid`
  (đã kiểm `information_schema`, xem A-12). Thiếu cast → `operator does not exist: uuid = text`.
- `EMPLOYEE_SELECT` hiện là `readonly` property dùng `$1`/`$2` cứng. Chuyển thành method
  nhận placeholder để đánh số không còn nằm rải rác.

## Verification run

Unit: 28/28 (`pnpm --filter @erp/api test -- partner-lookup`). Bất biến mạnh nhất chạy
trên **12 tổ hợp** `type` × `scope`: `highestPlaceholder(sql) === params.length`, tức
đúng thứ Postgres sẽ từ chối nếu lệch.

Ba trạng thái, ba hình dạng câu truy vấn khác nhau, đều được khẳng định:

| scope | `type=all` sinh ra |
|---|---|
| `branch` | 3 fragment, params `[org, pattern, branchId]`, `LIMIT $4 OFFSET $5` |
| `all` | 3 fragment, params `[org, pattern]`, `LIMIT $3 OFFSET $4` |
| `none` | 2 fragment (bỏ nhân viên), params `[org, pattern]` |

`type=employee` + `scope=none` trả rỗng mà **không gọi DB** — không dựng câu SQL què.
