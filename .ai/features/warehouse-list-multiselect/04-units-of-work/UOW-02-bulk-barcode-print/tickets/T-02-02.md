# T-02-02 — Nhập kho — In tem mã gom lines mọi phiếu đã tick

## Context

Toolbar item `barcode` (`PurchaseOrdersPage.tsx:484-511`) map `selectedOrder?.lines`
sang `BarcodePrefillItem[]` rồi gọi `navigateToBarcodePrint`. Sau T-01-04 người dùng
tick được nhiều phiếu, nhưng nút vẫn chỉ in một phiếu.

## Implementation notes

- Tách phần map dòng hàng đang có thành hàm cục bộ
  `toPrefillItems(lines): BarcodePrefillItem[]` — **giữ nguyên từng dòng mapping**
  (`line.item?.code`, `storageNameById`, `line.location?.code`…), chỉ đổi chỗ ở, để
  cả đường một phiếu lẫn đường nhiều phiếu dùng chung
- `const [gatheringLabels, setGatheringLabels] = useState(false)` — nút `disabled: gatheringLabels` (AC-15)
- `onClick`:
  ```
  checkedCount === 0
    → navigateToBarcodePrint(navigate, "/inventory/purchase-orders",
        toPrefillItems(selectedOrder?.lines ?? []) hoặc undefined nếu rỗng)   // AC-13, y hệt hôm nay
    → ngược lại: setGatheringLabels(true)
        Promise.all([...checkedIds].map(id =>
          requireErpData(await erpApi.GET<PurchaseOrder>("/goods-receipts/{id}", { params: { path: { id } } }))))
        // Promise.all reject ngay ở lỗi đầu tiên → đúng AC-16, không cần viết thêm gì
        catch → toast.error(getUserFacingApiErrorMessage(err)), KHÔNG điều hướng
        finally → setGatheringLabels(false)
        ok → mergeBarcodePrefillItems(orders.flatMap(o => toPrefillItems(o.lines ?? [])))
             → navigateToBarcodePrint(...)
  ```
- Dùng `GET /:id` chứ **không** `GET /:id/lines`: `/:id/lines` phân trang, dựng cho panel
  cuộn vô hạn; `/:id` trả `lines` đầy đủ và chính là nguồn nút này đang dùng (A-05)
- `[...checkedIds]` giữ thứ tự chèn của `Set` → thứ tự tem theo thứ tự người dùng tick
